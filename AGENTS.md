# OntoShip (DSH) — точка входа

OntoShip — метод и project-local пакет: **база знаний на markdown + git** с
детерминированным поиском, интервью, которое разрешает план до появления кода,
tracer-bullet тикетами и гейтированным ship-потоком — всё на нативных примитивах
хоста.

> Канон — [docs/decisions/ontoship-core.md](docs/decisions/ontoship-core.md).
> Он арбитр: правило, которое ему противоречит, по умолчанию не действует —
> оно принадлежит строгому профилю, истории или разбирается как ошибка
> канона решением оператора.

## Принцип

Markdown + git — источник истины. Всё производное — поисковый индекс, HTML-граф —
перегенерируется и никогда не коммитится как истина. `README.md` каждой папки — её
индекс; не давай документу стать сиротой. Ищи в KB до ответа или записи нового
документа.

## Форма

- **KB** durable; **spec** durable; **тикеты** эфемерны.
- **Факты** — работа агента; **решения** — работа оператора, через ask-инструмент
  хоста: выбор с вариантами и рекомендацией, не полотно вопросов. Оценка —
  работа агента, принятие варианта — оператора.
- Тест доказывает **пункт спеки** вместе с прочитанным артефактом, охраняет
  **инвариант проекта** или воспроизводит **реальный сбой** — ничего больше.
- Правила живут в механизмах (гейты хоста, промпты, тесты, движок) или остаются
  заявкой: у нормы есть названный носитель и, где проверяемо, проверка.

## Язык документации

Вся документация проекта — планы, спеки, тикеты, справочники, runbook'и и проза
скиллов — на русском. Английский остаётся только для машинно-значимых литералов:
команд, путей, идентификаторов, ключей frontmatter, значений `node_type`, маркеров и
проверяемых строк. Вывод команд и сообщения об ошибках передаются как есть. Код и
комментарии в коде — по конвенции проекта; если её нет, комментарии на английском.

## Канон текстов

Полный регламент — [docs/reference/text-style.md](docs/reference/text-style.md).
Кратко:
- скиллы и правила — знание, не история: даты правок и хроника живут в git
  и continue.md, не в нормах; адрес внешнего явления — версия, не дата прогона;
- проектных фактов (абсолютные пути, имена сессий) в скиллах нет;
- правило уборки живёт рядом с правилом создания (`.scratch/`, worktree);
- одно правило — один полный текст; пересказ в скилле сторожится якорным
  тестом (`tests/test_canon_sync.py`): правь все носители одним изменением;
- язык: императив без «вы»-форм, активный залог, «т. д.» с пробелом, без
  NBSP; машинные слои (код, таблицы, YAML-обвязка) проходами не правятся;
- проза ≤ 80, подравнивается при следующей содержательной правке носителя.

## Сопровождение

Движок KB — `skills/kb-search/gitmark.py`, урезанная копия вендорной базы
`vendor/ontoship-zcode/gitmark.py`:

```bash
python3 skills/kb-search/gitmark.py index    # пересобрать индекс после правки документов
python3 skills/kb-search/gitmark.py lint     # проверки онтологии
python3 skills/kb-search/gitmark.py map -o docs-map.html
```

## База знаний (OntoShip)

- Точка входа: [`docs/README.md`](docs/README.md) — главный индекс KB; у каждой папки
  есть индекс `README.md`.
- Ищи до ответа или записи: загрузи скилл `kb-search`. Движок лежит в
  `.agents/skills/kb-search/gitmark.py`; корень — `.agents/skills` или
  `.zcode/skills`, по каналу установки.
- Новые или обновлённые документы: загрузи скилл `kb-curate` — сначала поиск, никогда
  не дублируй.
- Сопровождение после правки документов:

  ```sh
  python3 .agents/skills/kb-search/gitmark.py index
  python3 .agents/skills/kb-search/gitmark.py lint --strict
  python3 .agents/skills/kb-search/gitmark.py map -o docs-map.html
  ```

- KB — это markdown + git: `.gitmark/`, `*-map.html` и `.scratch/` производные или
  эфемерные — никогда не коммитятся.

## Вход в работу (OntoShip)

- Изменения этого проекта идут через ship-флоу: скилл `ship` по команде
  оператора, один тикет за запуск; свободные правки в обход тикета не
  делаются — прямые решения оператора выше этого правила.
- Запрос плана открывает draft-спеку через скилл `grilling`; режим плана
  харнесса (в ZCode — план-мод) не используется.
- Состояние и порядок работы — [docs/ops/continue.md](docs/ops/continue.md):
  сессия продолжается оттуда и берёт следующий тикет оттуда же.
- Команды: «стартуй юнит» — открыть draft-спеку; «исполняй тикет N» — ship
  тикета N.
