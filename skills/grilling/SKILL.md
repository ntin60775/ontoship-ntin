# Skill: grilling
# Интервью, которое разрешает план до появления кода

Этот скилл — фаза 1 метода OntoShip; методные фазы —
`../ship/references/method-phases.md`; файл бандла — первоисточник,
проект переопределяет его документом `docs/reference/method-phases.md` —
написал свой, бери его. Он превращает названный юнит в спеку, которую
оператор утверждает на план-гейте, — до того, как написан код или нарезаны
тикеты.

## Когда использовать

- Оператор назвал новый юнит, а спеки в `docs/plans/` для него ещё нет.
- План спорный: у изменения больше одного разумного решения.
- Не используй скилл для мелочей, которые решаются одним фактом из репозитория:
  их решают сразу, без интервью.

## Дерево дизайна и фронтир

1. Расклади предмет как дерево дизайна: узлы — решения, дети — варианты, у
   каждого варианта — цена и следствие.
2. **Фронтир** — решения, чьи предпосылки уже улажены фактами и которые можно
   задавать оператору сейчас.
3. **Цена доказательства входит во фронтир.** Задай вопрос «как каждый пункт
   будет доказываться и что будет дорого» до написания спеки — тем же
   проходом через ask-инструмент хоста, вопросом с вариантами и
   рекомендованным ответом. Дорогие пункты переформулируются или разрезаются
   на фронтире — раньше, чем их поймает критик после нарезки.
4. Вопрос, который зависит от другого открытого вопроса, ждёт следующего раунда:
   не задавай его раньше срока.

## Раунды

1. **Собери факты до раунда.** Читай репозиторий, канон и источники; каждое
   утверждение неси с путём или называй пробелом. Факты — работа агента.
2. **Задай весь фронтир одним проходом через ask-инструмент хоста.** Каждый
   вопрос — вопрос инструмента с вариантами; рекомендованный ответ — первый
   вариант с пометкой и обоснованием в описании. Больше четырёх вопросов —
   несколько вызовов. Полотно вопросов в чате — дефект: удобство оператора в
   приоритете. Поле вопроса несёт само решение, одно предложение: отчёт и
   доказательства идут в чат текстом перед вызовом, в описании варианта пишут
   следствие выбора, не свидетельства. Рекомендация — не решение.
3. **Прими ответы оператора.** Решения — работа оператора; агент, ответивший за
   оператора, сломал скилл. Молчание оператора — не согласие: интервью стоит,
   пока оператор не ответит. Правило проекта или памяти об автономии —
   «продолжай без ответа», «иди по рекомендации» — не отменяет этой остановки
   и не действует на раунды и план-гейт.
4. **Пересчитай фронтир.** Ответы закрывают часть вопросов и открывают новые;
   повторяй раунды, пока фронтир не опустеет.

## Готовность и выход

- Готово: фронтир пуст и оператор подтвердил общее понимание вслух.
- Выход — спека `docs/plans/<slug>.md` с frontmatter `node_type: plan` и
  разделами Цель / Готово / Рамки / Ограничения / Контекст. Факты в спеке — с
  путями; решения — с именем принявшего их оператора.
- **Контрольная вычитка спеки перед план-гейтом.** Спека, расширявшаяся по
  частям, прячет противоречия. Перечитай её целиком: носители шагов — чем
  каждый пункт «Готово» будет доказываться (прогон, вывод команды, файл,
  живая проба) — названы; условные решения названы явно вместе с условием;
  числа согласованы между разделами; противоречия между разделами
  устранены. Найденное правится до гейта; спека после гейта меняется только
  решением оператора.
- **План-гейт:** спеку утверждает оператор ask-инструментом хоста —
  один вопрос с вариантами «утвердить» и «править»; условные
  решения спеки идут вариантами того же вопроса. До утверждения код
  не пишется и тикеты не нарезаются.
- Дальше нарезка — по правилу канона: агент сам оценивает сложность плана и
  выносит нарезку ask-инструментом хоста, ровно один вопрос на тикет.

## Честность

- Не выдумывай факты, пути и цифры; пробел называется пробелом.
- Не прячь спорные варианты: у фронтира нет очевидных ответов, есть
  рекомендованные.
- Решение, принятое без оператора, — дефект прогона, даже если оно казалось
  единственным разумным.

## Вне рамок v1

Автономный режим — явный флаг для обратимых решений; канон его допускает, но в
этой версии скилла его нет: каждое решение из фронтира идёт оператору.
