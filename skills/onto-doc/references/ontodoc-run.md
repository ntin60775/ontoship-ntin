# Прогон онто-дока по харнессам

Контракт прогона общий: кураторы идут на моделях из `[agents.curator]` в
`.agents/config.toml`, каждый кусок декомпозиции ведёт один куратор и
возвращает строку отчёта `path`, `curator`, `files`, `refusal`; способ
назначить модель субагенту у каждого харнесса свой.

## zcode — прогон онто-дока

Прогон — сохранённый workflow `.zcode/workflows/onto-doc.dwf.ts` (его
доставляет раннер) с тремя аргументами: `root` (корень KB — worktree
прогона), `plan` (куски декомпозиции `[{path, what}]`, по куратору на кусок)
и `model` (назначенная модель — файл прогона печатает её в log).
Модель и уровень едут в `subagent_model` вида `<model>$<level>` — тот же
транспорт, что у ревью-панели
([../ship/references/review-panel.md](../../ship/references/review-panel.md));
сверку модели и уровня с каталогом моделей хоста (`ListModels`) скилл делает
до запуска: расхождение — стоп, каталога нет — названный пробел и стоп.
Прогон пишет только внутри `root`.

## dsh — прогон онто-дока

Маршрут куратора берётся из `[agents.curator]`: строка `model` —
`<provider>/<model>`, ключ `level` — `reasoning_effort`; адаптер делит
строку по первому `/`. Прогон — fan-out `subagent` (spawn, не `subagent_fork`):
по куратору на кусок, все кураторы стартуют в одном сообщении с явными
`provider`, `model` и `reasoning_effort`. `workflow` не используется: его
`agent()` не несёт `effort`, а уровень — часть контракта. Сверку маршрута и
уровня скилл делает до запуска по живому `list_subagent_models`:
расхождение — стоп, каталога нет — названный пробел и стоп.

План кусков родитель проверяет до fan-out: `path` — относительный путь от
корня KB, без `..` и без начального `/`, области не повторяются, пустой
план — стоп. Промпт куратора несёт корень KB, кусок и запрет: пиши только
внутри `root`, за его пределы не выходи. `cwd` субагента — чекаут сессии,
команды — от корня KB; запись мимо `root` сверяй по `git status` чекаута
сессии — diff в корне её не покажет. Куратор ведёт срез по скиллу
`kb-curate` каталога сессии: md+git — источник истины, не дублируй;
frontmatter, типизированные ссылки и README-индекс папки — как велит
скилл. Невыполнимое задание — отказ с причиной, а не обход.

Ответ куратора — только JSON-строка с полями `path` (путь области),
`curator` (имя куратора), `files` (созданные или обновлённые файлы от корня
KB) и `refusal` (причина отказа или пустая строка). Ответ не по схеме —
именованный отказ строки, а не пустой список: `files` не подменяется на
`[]` при прозе вокруг JSON. Родитель собирает строки, объединяет `files` и
сверяет с `git diff --cached --name-only` в корне прогона после `git add -A`:
без индексации новые файлы в diff не видны; пустой `files` при непустом
diff и лишний `files` — расхождение.

## Qoder — вне плана

Способ запуска кураторов онто-дока в Qoder живой сессией не подтверждён —
как у ревью-панели
([../ship/references/review-panel.md](../../ship/references/review-panel.md));
пробел окружения, возврат — словом оператора в живой сессии.
