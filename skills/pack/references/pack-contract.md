# Контракт пака стандартов — API v1

Пак — каталог с манифестом `manifest.json` и файлами стандартов,
чек-листов ролей и конфигов гейтов. Пак — проектный бандл: живёт в
`.agents/packs/<имя>/` проекта, ставится каналом `--pack` установщика
ядра; пока канал не поставлен, пак кладётся в каталог вручную и
проверяется валидатором. Пак несёт только данные: стандарты, чек-листы
и конфиги гейтов; код, хуки и права на гейты остаются у ядра, конфиги
гейтов исполняет ядро в окружении проекта.

## Раскладка

```text
<имя пака>/
  manifest.json
  standards/<файлы>.md
  roles/<файлы>.md
```

Имя каталога совпадает с `name` манифеста. Файлы стандартов и
чек-листов — markdown; конфиги гейтов живут в манифесте как данные.

## Манифест

JSON-объект, ключи только из таблицы:

| ключ | тип | обязательность | правило |
|---|---|---|---|
| `name` | строка | обязательный | `[a-z0-9]+(-[a-z0-9]+)*`, совпадает с именем каталога |
| `type` | строка | обязательный | `team` (команда) или `stack` (стек) |
| `version` | строка | обязательный | `MAJOR.MINOR.PATCH`, цифры |
| `standards` | список строк | необязательный | относительные пути `.md` внутри пака, файлы существуют |
| `roles` | список объектов | необязательный | роли ревью, см. ниже |
| `gates` | список объектов | необязательный | механические гейты, см. ниже |

Неизвестный ключ — отказ. Пути — только относительные, без `..` и
абсолютных путей, цель внутри пака существует.

### Роль

Объект с ключами `name` и `checklist`, других ключей нет:

- `name` — `reviewer-<kontur>-<aspect>`: минимум два сегмента после
  `reviewer`, сегменты `[a-z0-9]+`, разделитель `-`;
- `checklist` — относительный путь `.md` внутри пака, файл существует.

Чек-лист роли — markdown: область (что читать) и пункты проверки.
Роль регистрируется в реестре ролей проекта бутстрап-вопросом init;
модель роли назначает реестр, не пак.

### Гейт

Объект с ключами `name`, `command` и необязательным `expect_exit`,
других ключей нет:

- `name` — непустая строка, имя гейта в отчётах;
- `command` — непустой список строк: команда и аргументы, исполняется
  ядром в окружении проекта без shell-интерпретации;
- `expect_exit` — целое число, ожидаемый код выхода (по умолчанию 0).

Гейт — данные, не код: валидатор проверяет схему, не семантику
команды. Пак — доверенный источник команды; команда гейта исполняется
с правами проекта.

## Стандарты

Файл стандартов — markdown: правила с носителями. Правило без
носителя и проверки — заявка, не норма; где правило проверяемо,
чек-лист роли или гейт называет проверку. Приоритет норм: канон >
стандарты проекта > пак команды > пак стека > базовый документ;
неразрешимый конфликт — вопрос оператору.

## Валидация

Валидатор бандла — [`../validate_pack.py`](../validate_pack.py), только
stdlib:

```sh
python3 <бандл pack>/validate_pack.py <каталог пака>
```

- валиден — exit 0, строка `✓ пак <имя> (<тип>, <версия>) валиден`;
- нарушение — именованный отказ: причина в stderr, exit 2, stdout
  пустой;
- usage-ошибки (нет аргумента, каталог не существует, файл вместо
  каталога) — тот же контур отказа.

Эталонный минимальный пак —
[`manifest.json`](../reference-pack/manifest.json) в `../reference-pack/`:
манифест, один стандарт, одна роль, один гейт; валидатор на нём
проходит. Мутации эталона (убранное поле, чужой тип, неизвестный ключ,
висящая ссылка) обязаны краснеть.
