# chain-live-activity — живая активность прогонов на доске цепочки

Спека юнита. Повод — оператор 2026-11-12: доска цепочки — единственный
оперативный источник правды об исполнителях, а статус «в работе» на ней
не обновляется. Разбор (сессия плагина `session-cdc352e6`, 2026-11-12):
доска выводит active из прозы continue.md, которая о факте работы не
знает; исполнитель сидит в worktree, невидимом доске до merge; перехода
«остановился» нет — «в работе» живёт вечно. В будущем — параллельное
исполнение, схема должна нести множественность с первого дня.

## Цель

Доска показывает живую активность прогонов — кто держит тикет, в какой
фазе, насколько свеж сигнал — поверх plan-статусов из markdown+git.
Активность — эфемерный реестр lease с правилами истины; durable-канал
очереди и приёмки не меняется.

## Решения

Приняты оператором ask-проходом grilling 2026-11-12 (раунды 1–2).
Спека утверждена на план-гейте ask-проходом 2026-11-12 (вариант
«утвердить»); контрольная вычитка до гейта правила блокер 07+09.
Правки после план-гейта внесены решением оператора ask 2026-11-12
(триаж проекций, отчёт `tickets/chain-live-activity/00-projection-report.md`):
пакет подтверждённых находок; упрощения — поле `seq` снято (один
писатель на файл, порядок по `updatedAt`), бейдж-гигиена прозы — задел,
не v1.

## Готово

1. **Реестр и схема.** Каталоги `.scratch/board/runs/` относительно
   `boardRoot`; два файла на прогон: `<runId>.dispatch.json` (писатель —
   оркестратор) и `<runId>.run.json` (писатель — исполнитель). Таблица
   поле → файл → писатель: dispatch несёт `v`, `runId`, `unit`, `ticket`,
   `phase` (= `dispatched`), `orchestrator.session` (автоматически),
   `executor.session` (из спавна, известен на dispatch), `startedAt`,
   `updatedAt`, `ttlSec` (= 1800); run несёт `v`, `runId`, `phase`,
   `executor` (label = `ship`, model, session — автоматически), `branch`,
   `worktree` (аргументы update из cwd исполнителя), `boardRoot`,
   `scope`, `startedAt`, `updatedAt`, `ttlSec`, `note`. Терминальные
   фазы: `accepted` (автоприёмка записана), `aborted` (точка остановки,
   вопрос оператору, пенсия), `failed` (отказ инструмента,
   неразрешимая ошибка); `idle` — исполнитель жив, тикет не держит
   (после финиша и между тикетами), не живая активность. `runId`
   рождается на dispatch и едет в каждом сообщении выдачи. — носители:
   контракт формата (таблица) в ARCHITECTURE.md плагина, тесты модели
   (парсинг, версия, неизвестные поля, битый JSON).
2. **Host-инструменты.** `ontoship_run_dispatch` (unit, ticket,
   executorSession → runId, dispatch-файл; уборка: того же юнита,
   терминальные и протухшие нетерминальные с `updatedAt` старше 24 ч,
   живые не трогает; уборка — названное GC-исключение к «один писатель»,
   только в dispatch, chain её не дублирует) и `ontoship_run_update`
   (runId, phase, boardRoot?, branch?, worktree?, note → run-файл;
   caller сверяется с `executor.session` dispatch — несовпадение →
   отказ с причиной; `ttlSec` 1800, для review 3600). Запись — raw fs
   tmp+rename с уникальным именем tmp (прецедент `ontoship_board_open`);
   `boardRoot` валидируется (абсолютный существующий каталог, запись
   только под `.scratch/board/runs/`); ошибка ФС при записи в boardRoot
   → `scope: local` в cwd вызывающего. Плагина нет — названный пробел,
   проход идёт. — носители: `index.js` плагина, host-тесты (атомарность,
   отказ caller, триггер фолбэка, уборка, TTL-значения).
3. **Модель доски.** `parseRunLease` + `mergeActivity(board, leases,
   now)`: accepted/done из markdown перебивает activity; run перебивает
   dispatch того же runId; порядок по `updatedAt` (поле `seq` снято);
   протухший по TTL lease — stale («нет сигнала N мин»), не жив в
   шапке, не исчезает молча; два живых прогона на тикет — конфликт;
   run без dispatch (orphan) и lease на заблокированный/отсутствующий
   тикет — бейдж-несогласованность, не жив; dispatch без run — «выдан,
   сигнала нет» сразу, без ожидания TTL; `idle` не жив и не считается
   в шапке; чужой юнит отскоуплен (существующее поведение доски,
   v1-код); проза active колонку не задаёт — существующие зелёные
   тесты prose-active переписываются этим срезом. — носители:
   `src/model.js` плагина, тест-кейсы с управляемым `now` и точными
   TTL (stale/граница 1800/3600, конфликт, orphan, dispatch-only,
   битый JSON, accepted перебивает, idle не жив, чужой юнит,
   перепись prose-active).
4. **UI доски.** Шапка «N тикетов · frontier M · в работе K» (K — только
   живые); поповер прогонов (роль, модель, сессия, тикет, фаза,
   давность сигнала, branch, note); карточки «В работе» с фазой;
   stale-бейдж «нет сигнала N мин», конфликт-бейдж, бейдж-несогласованность,
   состояние «выдан, сигнала нет»; idle — «между тикетами». **Таймер
   UI (~30 с) пересчитывает свежесть без событий реестра** — протухание
   наступает по часам, а не только по кадрам watch; watch каталога
   реестра тем же паттерном, что `tickets/<unit>`. Сборка `build.mjs` →
   `client.js` обязательна (node — абсолютный путь). — носители:
   `src/ui.js`, локали, client-тесты по дереву vnode с управляемыми
   часами (stale-бейдж, конфликт, поповер, шапка K, dispatch-only),
   дизайн-тест (охрана литералов — названное ограничение).
5. **Скилл ship.** Lease на границах и внутренних рубежах шагов:
   1 — starting (runId из входа; runId нет — self-dispatch, boardRoot =
   cwd), 2–3 — working (heartbeat после чтения лога тестов), 4 — review
   (heartbeat до запуска панели, на старте/финише каждого пакета ролей
   и после правок), 5–6 — gates (heartbeat после чтения выводов
   гейтов), 7 — merge; финиш — accepted/aborted/failed, затем idle;
   остановка прохода — aborted с note до парковки сессии. Инструмента
   нет — названный пробел, проход идёт; телеметрия не меняет изоляцию
   worktree. — носители: `skills/ship/SKILL.md`, контрактный тест;
   переходы фаз доказываются живой пробой (пункт 8).
6. **Скилл chain.** Dispatch при выдаче каждого тикета (executorSession
   из спавна); `runId` и `boardRoot` в каждом сообщении выдачи
   (`send_message`) и в handoff-промпте пенсии; пенсия — старый
   исполнитель пишет idle, оркестратор dispatch'ит новый runId того же
   тикета (idle не жив → конфликта нет); уборка только через dispatch.
   — носители: `skills/chain/SKILL.md`, контрактный тест; поведение —
   живая проба (пункт 8).
7. **Документация.** Плагин: DESIGN.md (активность — машинный реестр,
   не проза; новые элементы), ARCHITECTURE.md (таблица формат→писатель,
   правила истины, задел ActivitySource, параллельность и
   пользовательские фильтры), CONTINUE.md, README.md, DETAIL.md,
   AGENTS.md и description локалей — утверждения «ничего не хранит /
   только чтение» правятся: доска читает, host-инструменты пишут lease.
   Метод: приписка о реестре активности в `docs/reference/harnesses.md`.
   — носители: документы; доки плагина — чтение и тесты плагина
   (`lint --strict` корпуса этого репо их не видит), KB метода — lint.
8. **Живая проба.** Мини-цепочка одного игрушечного тикета в
   temp-проекте. Фикстура — посев по прецеденту `/tmp/sa06-chain`: ядро
   и пак копией, init, игрушечный юнит (спека, тикеты, запись гейта
   проекций и приёмка нарезки — «установка пробы», названный пробел).
   Preflight: host перезапущен после правки `index.js`, инструменты
   `ontoship_run_*` присутствуют; проба без lease-артефактов не
   принимается доказательством пунктов 2, 5, 6. Ожидания: фазы
   starting → working → review → gates → merge → accepted в run-файле;
   `runId` dispatch и run совпадают; путь lease = boardRoot
   оркестратора; heartbeat до панели (рост `updatedAt`); шапка «в
   работе 1» во время прогона и 0 после; dispatch-only «выдан, сигнала
   нет» до первого update. Именованная пауза пробы: оператор смотрит
   доску после dispatch и первых фаз. Цена: ~20–30 мин живого прогона.
   — носители: артефакты пробы (идентификаторы сессий, lease-файлы,
   подтверждение вида оператором) в тикете.
9. **Набор и проверка.** Тесты плагина зелёные (модель, клиент, host,
   дизайн), контрактные тесты скиллов метода зелёные; красные пробы
   новых наборов названы на два базовых коммита (HEAD плагина и HEAD
   метода). — носители: выводы прогонов в тикетах.

## Рамки

- Только названное целью: реестр, инструменты, модель и UI доски,
  скиллы ship/chain, документация, живая проба.
- Пользовательские фильтры по юнитам/оркестраторам и граница
  ActivitySource (замена файлового источника host-событиями) — задел в
  ARCHITECTURE.md, не код v1; скоуп до текущего юнита — v1-код
  (существующее поведение доски).
- Бейдж-гигиена прозы «в runbook „в работе“, сигнала нет» — задел, не
  v1 (решение оператора, триаж 2026-11-12).
- Канон и зеркало `method-phases.md` не правятся: фазы метода не
  меняются, телеметрия — не фаза.
- Доска — наблюдатель, не замок: никаких claim-блокировок в UI;
  координация прогонов остаётся у оркестратора.
- Реестр эфемерен (`.scratch/`), в git не попадает; continue.md остаётся
  durable-каналом очереди, приёмки и остановки цепочки.
- Плагин — отдельный репо; его коммиты названы в тикетах юнита.

## Ограничения

- Правка канона сверх принятых решений — точка остановки: вопрос
  оператору, не «доделка на ходу».
- Неразобранное расхождение ожидание/факт — точка остановки ship
  ([testing.md](../reference/testing.md), «Артефакт доказательства»).
- Один проход ship на тикет, один прогон панели; циклов сходимости нет.
- TTL — эвристика: протухший lease показывается как «нет сигнала», не
  скрывается и не маскируется под живой; таймер UI пересчитывает
  свежесть без событий реестра.
- Запись lease — raw fs (прецедент маркера): сессионная файловая
  политика к raw fs не применяется — названное ограничение доверия,
  как у гейтов пака; ошибка ФС → `scope: local`.
- Запись lease вне worktree — только телеметрия в boardRoot; реализация
  остаётся в worktree, изоляция ship не нарушается. Терминальная фаза
  local-lease теряется при сносе worktree — названное следствие
  фолбэка: dispatch остаётся «выдан, сигнала нет» до уборки.
- Инструментов нет в сессии — названный пробел, цепочка и ship идут без
  активности; тихая подмена прозой не делается; живая проба без
  lease-артефактов доказательством не считается.
- Живая проба проводится в temp-проекте; артефакты пробы фиксируются в
  тикетах до отчёта оператору.
