# chain-live-activity — живая активность прогонов на доске цепочки

Спека юнита. Повод — оператор 2026-11-12: доска цепочки — единственный
оперативный источник правды об исполнителях, а статус «в работе» на ней
не обновляется. Разбор (сессия плагина `session-cdc352e6`, 2026-11-12):
доска выводит active из прозы continue.md, которая о факте работы не
знает; исполнитель сидит в worktree, невидимом доске до merge; перехода
«остановился» нет — «в работе» живёт вечно. В будущем — параллельное
исполнение, схема должна нести множественность с первого дня.

## Цель

Доска показывает живую активность прогонов — кто держит тикет, в какой
фазе, насколько свеж сигнал — поверх plan-статусов из markdown+git.
Активность — эфемерный реестр lease с правилами истины; durable-канал
очереди и приёмки не меняется.

## Решения

Приняты оператором ask-проходом grilling 2026-11-12 (раунды 1–2).
Спека утверждена на план-гейте ask-проходом 2026-11-12 (вариант
«утвердить»); контрольная вычитка до гейта правила блокер 07+09.

## Готово

1. **Реестр и схема.** `.scratch/board/runs/<runId>.dispatch.json` и
   `<runId>.run.json` в рабочей папке доски; схема v1: `v`, `seq`,
   `runId`, `unit`, `ticket`, `phase`, `executor` (label, model, session),
   `orchestrator` (session), `branch`, `worktree`, `boardRoot`, `scope`,
   `startedAt`, `updatedAt`, `ttlSec`, `note`. Атомарная запись tmp+rename;
   один писатель на файл: dispatch — оркестратор, run — исполнитель;
   `runId` рождается на dispatch и едет в handoff. — носители: контракт
   формата в доках плагина, тесты модели (парсинг, версия, толерантность
   к неизвестным полям, битый JSON).
2. **Host-инструменты.** `ontoship_run_dispatch` (unit, ticket → runId,
   dispatch-файл; уборка терминальных lease старше 24 ч) и
   `ontoship_run_update` (runId, phase, boardRoot?, note → run-файл;
   session вызывающей сессии автоматическая; отказ записи вне cwd →
   `scope: local`). Плагина нет — названный пробел, проход идёт. —
   носители: `index.js` плагина, host-тесты, живая проба (пункт 8).
3. **Модель доски.** `parseRunLease` + `mergeActivity(board, leases,
   now)`: accepted/done из markdown перебивает activity; run перебивает
   dispatch того же runId, больший seq/updatedAt побеждает; протухший
   lease — stale («нет сигнала N мин»), не считается живым в шапке и не
   исчезает молча; два живых прогона на тикет — конфликт; lease на
   заблокированный или отсутствующий тикет — бейдж-несогласованность;
   чужой юнит UI игнорирует (поле unit — задел); проза active колонку не
   задаёт. — носители: `src/model.js` плагина, тест-кейсы (stale/граница
   TTL, конфликт, dispatch без run, orphan, битый JSON, accepted
   перебивает, чужой юнит).
4. **UI доски.** Шапка «N тикетов · frontier M · в работе K»; поповер
   прогонов (роль, модель, сессия, тикет, фаза, давность сигнала);
   карточки «В работе» с фазой; stale-бейдж и конфликт-бейдж; idle —
   «между тикетами»; watch каталога реестра тем же паттерном, что
   `tickets/<unit>`. — носители: `src/ui.js`, локали, client-тесты,
   дизайн-тест.
5. **Скилл ship.** Lease на границах шагов: 1 — starting (boardRoot из
   входа), 2–3 — working, 4 — review (heartbeat до запуска панели),
   5–6 — gates, 7 — merge, финиш — accepted/aborted/failed; между
   тикетами продолжаемый исполнитель — idle. Инструмента нет — названный
   пробел, проход идёт; телеметрия не меняет изоляцию worktree. —
   носители: `skills/ship/SKILL.md`, контрактный тест.
6. **Скилл chain.** Dispatch при выдаче тикета исполнителю; `runId` и
   `boardRoot` в первом сообщении исполнителю и в handoff-промпте
   пенсии; уборка реестра при старте цепочки. — носители:
   `skills/chain/SKILL.md`, контрактный тест.
7. **Документация.** Плагин: DESIGN.md (активность — машинный реестр, не
   проза; новые элементы), ARCHITECTURE.md (схема, правила истины, задел
   ActivitySource и параллельность), CONTINUE.md. Метод: приписка о
   реестре активности в `docs/reference/harnesses.md`. — носители:
   документы, `lint --strict` чист.
8. **Живая проба.** Мини-цепочка одного игрушечного тикета в
   temp-проекте: доска открыта в сессии оркестратора, dispatch при
   выдаче, lease исполнителя по фазам, finish; артефакты (идентификаторы
   сессий, lease-файлы, подтверждение вида оператором) — в тикете. —
   носители: артефакты пробы.
9. **Набор и проверка.** Тесты плагина зелёные (модель, клиент, host,
   дизайн), контрактные тесты скиллов метода зелёные, красная проба
   новых наборов на базовом коммите названа в тикетах. — носители:
   выводы прогонов в тикетах.

## Рамки

- Только названное целью: реестр, инструменты, модель и UI доски,
  скиллы ship/chain, документация, живая проба.
- Фильтры по юнитам/оркестраторам и граница ActivitySource (замена
  файлового источника host-событиями) — задел в документации, не код v1.
- Канон и зеркало `method-phases.md` не правятся: фазы метода не
  меняются, телеметрия — не фаза.
- Доска — наблюдатель, не замок: никаких claim-блокировок в UI;
  координация прогонов остаётся у оркестратора.
- Реестр эфемерен (`.scratch/`), в git не попадает; continue.md остаётся
  durable-каналом очереди, приёмки и остановки цепочки.
- Плагин — отдельный репо; его коммиты названы в тикетах юнита.

## Ограничения

- Правка канона сверх принятых решений — точка остановки: вопрос
  оператору, не «доделка на ходу».
- Неразобранное расхождение ожидание/факт — точка остановки ship
  ([testing.md](../reference/testing.md), «Артефакт доказательства»).
- Один проход ship на тикет, один прогон панели; циклов сходимости нет.
- TTL — эвристика: протухший lease показывается как «нет сигнала», не
  скрывается и не маскируется под живой.
- Запись lease вне worktree — только телеметрия в boardRoot; реализация
  остаётся в worktree, изоляция ship не нарушается.
- Инструментов нет в сессии — названный пробел, цепочка и ship идут без
  активности; тихая подмена прозой не делается.
- Живая проба проводится в temp-проекте; артефакты пробы фиксируются в
  тикетах до отчёта оператору.
