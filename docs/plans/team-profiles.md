# team-profiles — личная команда агентов на пресетах DSH

Draft-спека юнита. Повод — оператор 2026-11-13: команда агентов нужна
как личная команда (архитектор-аналитик, оркестратор, исполнитель,
сборщики контекста), где оператор — продакт-оунер; профили DSH —
нативный механизм ролей. Вход — концепт-основа (сессия планирования
2026-11-13) и проба динамического allowlist
([dsh-preset-allowlist.md](../reference/dsh-preset-allowlist.md)).

## Цель

Роли команды поставляются нативными пресетами DSH: оператор выбирает
архитектора и оркестратора, оркестратор сам выбирает исполнителя под
задачу по реестру, стек-бандл (1C-DSH) добавляет своего исполнителя без
оверрайда пресетов команды. OntoShip остаётся методом и KB; контур
поставки получает глобальный (профиль) и проектный скоупы и один канал
обновления.

## Готово

Черновой перечень; пункты уточняются раундами и доказываются артефактами.

1. **Team-бандл.** Пресеты `architect`, `orchestrator`, `executor`,
   `scout`: персона, набор инструментов, `agentOptions`, командные
   секции; служебные пресеты помечены. — носители: файлы бандла,
   контрактные тесты композиции, живая проба в новой сессии.
2. **Реестр исполнителей.** Хост-плагин `ontoship-executors` до
   деклараций пресетов читает `executors.json` и отдаёт синхронный
   `executors()`; `allowedAgentPresets` оркестратора — `!!js` от него;
   дефолт при ошибке чтения — `["executor"]`. — носители: код плагина,
   контрактный тест allowlist, проба с неизвестным id.
3. **Выбор исполнителя оркестратором.** Правило выбора по манифесту
   пака/спеке, запись выбора в отчёт; универсальный `executor` —
   безопасный дефолт. — носители: текст скилла `chain`, контрактный
   тест, живая проба.
4. **Стековая специализация.** 1C-DSH поставляет пресет `1c-executor`
   (persona + те же инструменты) и проектные скиллы/стандарты; team-id
   не переопределяются. — носители: патч стек-бандла, запись в
   `executors.json`, проба в 1С-проекте; без проектных скиллов пресет —
   названная пустая оболочка.
5. **Маршруты ролей.** Правила выбора модели (per-call через
   `modelSelection`/`agentOptions`) для исполнителя, scout'а и
   оркестратора; реестр панели остаётся в `.agents/config.toml`. —
   носители: конфиг пресетов, правило в скилле, отчёт выбора.
6. **Контур поставки.** `contour.lock` двух уровней (profile и project),
   команда `contour update`, bootstrap нового ПК; глобальные бандлы не
   трогают проекты, проектные — профиль. — носители: скрипт и манифесты,
   контрактные тесты, живой bootstrap в temp.
7. **OntoShip-носители.** Скилл `chain` — контекстный промпт и выбор
   исполнителя; канон, зеркало `method-phases`, `harnesses.md`,
   ревизия решения 2 `standards-autoship` (хостовый канал). — носители:
   тексты, якорные тесты паритета, красная проба на базе.
8. **Живая проба.** Temp-проект: team-бандл в профиль, init, архитектор →
   план-гейт → проекции → нарезка → оркестратор выбирает исполнителя по
   реестру → цепочка → панель → автоприёмка → финишная приёмка; отдельная
   проба 1С-проекта. — носители: артефакты пробы (сессии, коммиты,
   отчёты), запись в тикетах.
9. **Набор и KB.** Полный набор, `lint --strict`, `install.sh --check`;
   индексы, continue.md, справочник контура. — носители: вывод прогонов.

## Рамки

- Только нативные примитивы DSH: пресеты, `subagent`, `agent-team`,
   `workflow`; второго рантайма нет.
- Пресеты глобальны; per-project скоупа пресетов не вводится.
- Меняется носитель ролей, не метод: гейты, доказательства, проекции,
   паки, ticket-DAG и ручные гейты оператора сохраняются.
- 1C-DSH — первый стек-потребитель; другие стеки — по тому же контракту.
- `chain-live-activity` и замороженный тикет 08 — вне юнита.

## Ограничения

- Пресет не несёт модель: маршрут — отдельная привязка (`agentOptions`
  инструмента, per-call поля, профиль).
- `allowedAgentPresets` вычисляется при монтировании; позже
  установленный пресет сам в allowlist не попадёт — реестр читается на
  старте.
- `require` в выражении `!!js` недоступен; реестр пресетов в выражении
  пуст при монтировании (проба).
- Лимит активных детей хоста 4; `maxDepth` 3 — панель и scout'ы идут
  рассрочкой.
- Inter-root messaging отсутствует: handoff архитектор → оркестратор
  идёт через оператора и файлы.
- Маршрутная политика сессии снимается при создании; правки — новым
  сессиям.
- Оверрайд пресета заменяет весь список детей; стек вводит новые id.
