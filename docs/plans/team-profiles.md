# team-profiles — личная команда агентов на пресетах DSH

Draft-спека юнита. Повод — оператор 2026-11-13: команда агентов нужна
как личная команда (архитектор-аналитик, оркестратор, исполнитель,
сборщики контекста), где оператор — продакт-оунер; пресеты DSH —
нативный механизм ролей. Вход — концепт-основа сессии планирования
2026-11-13, проба динамического allowlist
([dsh-preset-allowlist.md](../reference/dsh-preset-allowlist.md)) и гейт
проекций ([00-projection-report.md](../../tickets/team-profiles/00-projection-report.md)).

## Цель

Роли команды поставляются нативными пресетами DSH: оператор выбирает
архитектора и оркестратора, оркестратор выбирает исполнителя при старте
работы по задаче, стек-бандл (1C-DSH) добавляет свои роли без оверрайда
пресетов команды. OntoShip остаётся методом и KB: гейты, доказательства
и проекции не меняются. Контур поставки — отдельный юнит; здесь роли,
реестр исполнителей, поставка бандла и живая проба.

  Черновой список согласован.
- **Канал:** dev `link:` + stable git-пин, упаковка здесь; отдельный
  DSH-маркет — потом (за юнитом).
- **Протокол 08:** переписать под профильный поток со ссылкой на

## Готово

Каждый пункт доказывается артефактом; носители названы. Классификация
доказательств: существующий носитель — красная проба на базе; инвариант
— падает при дрейфе; новая поверхность — composition/mount/live;
поведение — live/target-проба.

1. **Team-бандл и репозиторий.** Отдельный репо `ontoship-team`:
   `package.json` (`dsh.bundle.patch`, `engines.dsh`), сборка, тесты,
   semver-тег. Пресеты `architect`, `orchestrator`, `executor`, `scout`:
   персона на русском, набор инструментов, командные секции (носитель —
   именованные секции `persona` composition), `modelSelection: true` на
   spawn-инструментах; `ask_user_question` у architect и orchestrator;
   spawn-инструмент каждой роли несёт `scout` в allowlist; служебные
   пресеты помечены конвенцией id/description/order (hidden-флага у DSH
   нет). Каждый ролевой агент (корневой и ребёнок) автоматически
   получает личное псевдореальное имя при старте сессии и осознаёт
   его: seed-генерация из пула без реестра уникальности, имя в
   контексте агента с первого хода, заголовок «Имя · Роль»
   (решение 18; механизм и разведка имени дерева — тикет 09).
   — носители: файлы
   бандла, контрактные тесты композиции
   (набор инструментов и ask по каждому пресету, scout в allowlist),
   тесты генератора и инъекции имени (тикет 09),
   live-smoke team-architect в новой сессии. Новая поверхность:
   red-on-base не заявляется.
2. **Реестр исполнителей.** Хост-плагин `ontoship-executors` в
   team-бандле, строка ДО деклараций пресетов; путь резолвит через
   `ctx.get('profileContext').dir` (не env); читает
   `<profile>/ontoship/executors.json` один раз при apply; схема —
   массив `{id, provider, model, level}`, запись `executor` обязательна;
   отдаёт синхронный `executors()` (массив id) для `!!js`-allowlist;
   валидирует и дедуплицирует, при ошибке/пустом/без `executor` —
   громкий лог и дефолт `["executor"]`. Правило истины: allowlist
   заморожен при apply, маршруты читает спавнящая роль через `read`,
   неизвестный id — отказ при вызове. Инструмент оркестратора несёт
   `agentPreset: executor`. — носители: код плагина, контрактные тесты
   (allowlist, `[]`, дубли, без `executor`, фейковый profileContext,
   неизвестный id), проба. Новая поверхность.
3. **Выбор исполнителя оркестратором.** Гранулярность: пресет+маршрут
   выбираются при спавне продолжаемой сессии-исполнителя и при
   пенсии/handoff; внутри сессии тикеты исполнителя не меняют. Сигнал
   стека: архитектор фиксирует указатель в спеке/continue.md;
   оркестратор читает указатель → id стека из реестра → иначе дефолт
   `executor`; неоднозначность — остановка с вопросом; выбор называется
   в отчёте (кандидаты, id, причина). Маршрут — per-call через `read`
   реестра. — носители: текст скилла `chain`, контрактный тест (два
   кандидата, 1C/не-1C, неоднозначность), живая проба. Поведение.
4. **Стековая специализация 1C.** Новое стековое репо `ontoship-team-1c`
   в тим-контуре поставляет `1c-architect`, `1c-orchestrator`,
   `1c-executor`: копия composition team-бандла + дельта (персона,
   доставка контура); team-id не переопределяются; паритетный тест в
   стек-репо против пинованного `teamVersion`. Доставка и гейты
   `dsh-1c-contour` переиспользуются как зависимость; в 1C-DSH —
   минимальный аддитивный шов: фильтр доставки становится
   конфигурируемым набором трёх id (дефолт `1c` цел, судьба legacy `1c`
   называется); весь состав инструментов 1C-DSH доступен всем трём
   ролям (дифференциация позже). Стек-копия требует team-бандл в
   профиле (порядок установки назван). Кросс-репо: аддитивный шов
   1C-DSH — свой тикет/спека/приёмка в 1C-DSH; тикет этого юнита несёт
   адрес, ребро зависимости, ссылку на доказательство и ждёт чужого
   мержа. — носители: репо `ontoship-team-1c`, патч стек-бандла, запись
   в `executors.json`, паритетный тест, unit-тест доставки (три id
   получают контур, team-architect — нет), проба в 1С-проекте. Фильтр
   доставки — существующий код, red-on-base есть.
5. **Маршруты ролей.** Per-call выбор спавнящей ролью через `read`
   `executors.json`: исполнитель —
   `qwen-token-plan-deepseek/deepseek-v4.1-flash-1017`/`max`, scout —
   `qwen-token-plan/qwen3.8-flash`/`medium`; полная форма
   `provider/model`+level; выбор называется в отчёте; реестр панели
   остаётся в `.agents/config.toml`; дефолт маршрута в `agentOptions` —
   страховка. — носители: схема реестра, правило в скилле, отчёт выбора.
   Поведение.
6. **OntoShip-носители.** Скилл `chain` — контекстный промпт, выбор
   исполнителя, проверка `methodContract` (версия 1) через сервис
   плагина, остановка с вопросом при mismatch/отсутствии; init называет
   team-бандл ссылкой в §5/отчёте (без имени репо и литералов маршрутов);
   содержательная правка канона, зеркала `method-phases`, `harnesses.md`
   (уполномочена решением 9); приписка-ревизия решения 2
   `standards-autoship` И строки «Рамок» одним изменением. — носители:
   тексты, якорные тесты паритета, красная проба на базе для
   chain/init/canon/mirror; поведение проверки версии — live-проба с
   mismatch (стоп) и совпадением (продолжение).
7. **Релиз и поставка.** Сборка/тесты репо, semver-тег, stable git-пин
   полным коммитом / dev `link:`; установка из пина в temp-профиль +
   новая сессия с пресетами; `teamVersion` пинован в стеке. Отдельный
   DSH-индекс маркета и CI validate — контур-юнит (названный пробел).
   — носители: артефакты релиза (тег, пин, лог установки, композиция
   новой сессии). Новая поверхность.
8. **Живая проба.** Один temp-проект с `1C-DSH`; профиль назван (temp
   `DSH_HOME`/копия или рабочий с before/after sha256); `executors.json`
   записан ДО установки team-бандла (или явный reload после записи);
   порядок установки и точки рестарта названы. Поток: `1c-architect` →
   план-гейт → проекции → нарезка → `1c-orchestrator` выбирает
   `1c-executor` по реестру → цепочка → ревью-панель (четыре роли из
   `config.toml`, один прогон, вердикты) → автоприёмка → финишная
   приёмка; один игрушечный тикет с 1C-содержимым и ожидаемым контурным
   наблюдением (скиллы/MCP/гейт на 1C-правке); scout спавнится и
   наблюдается. Чек-лист «шаг → артефакт → ожидание» с путями, ids,
   хешами, логами, ask-записями; тикет `tickets/team-profiles/<NN>` +
   durable-копия финального отчёта. Отрицательные условия: оператор не
   читал и не писал код, других ручных гейтов кроме трёх нет, циклов
   правок нет. Бюджет — ex-ante предел + измеренный факт + стоп по
   нормам chain; доска опциональна, не гейт. — носители: артефакты
   пробы (сессии, коммиты, отчёты), запись в тикете.
9. **Набор, KB и протокол 08.** Per-repo команды и ожидаемые выводы:

## Рамки

- Только нативные примитивы DSH: пресеты, `subagent`, `send_message`;
  `agent-team` и `workflow` в этом юните не используются.
- Пресеты глобальны; per-project скоупа пресетов не вводится.
- Меняется носитель ролей, не метод: гейты, доказательства, проекции,
  паки, ticket-DAG и ручные гейты оператора сохраняются.
- 1C-DSH — первый стек-потребитель; другие стеки — по тому же контракту.
- Контур поставки (`contour.lock`, `contour update`, bootstrap,
  DSH-индекс маркета) — отдельный юнит; здесь место для
  `executors.json`, ручное обновление и поставка бандла (link/git-пин).
- `chain-live-activity` — вне юнита; тикет 08 заморожен, его возврат
  описан в «Готово» 9 (сам 08 — вне юнита).

## Ограничения

- Пресет не несёт модель на верхнем уровне; строка инструмента пресета
  может нести `agentOptions` (дефолт маршрута), маршрут — per-call через
  `read` реестра или профиль.
- `executors.json` читается один раз при apply плагина; список id
  заморожен; позже установленный пресет выбираем, только если его id
  был в списке; маршруты читаются live.
- `require` в выражении `!!js` недоступен; реестр пресетов DSH в
  выражении пуст при монтировании; путь профиля — через
  `profileContext.dir`, не `DSH_PROFILE_DIR` (env только модельным
  shell-вызовам).
- Лимиты: глубина root 0 → исполнитель 1 → панель/scout 2 (запас до
  `maxDepth` 3); ёмкость `maxActiveSubagents` 4 — общая под одним
  корнем на всех уровнях, исполнитель занимает слот; сверх лимита —
  отказ, не очередь; носитель рассрочки — исполнитель/ship; scout и
  панель сериализуются или стартуют по свободным слотам.
- Inter-root messaging отсутствует: handoff архитектор → оркестратор
  через оператора и файлы.
- Маршрутная политика сессии снимается при создании; правки — новым
  сессиям.
- Оверрайд пресета заменяет весь список детей; стек вводит новые id;
  стек-копия требует team-бандл в профиле.
- Проба — один игрушечный тикет, один прогон панели, один проход
  правок; циклов сходимости нет; превышение бюджета — остановка по
  нормам chain, состояние в continue.md, незакрытая часть — пробел.
- Правки `1C-DSH` — только аддитивный шов фильтра id, ship-проход в его
  репозитории со своей приёмкой; стек живёт в новом репо
  `ontoship-team-1c`; этот юнит несёт тикет с адресом изменения и ждёт
  чужого мержа, чужой код здесь не коммитится.
