# team-profiles — личная команда агентов на пресетах DSH

Draft-спека юнита. Повод — оператор 2026-11-13: команда агентов нужна
как личная команда (архитектор-аналитик, оркестратор, исполнитель,
сборщики контекста), где оператор — продакт-оунер; профили DSH —
нативный механизм ролей. Вход — концепт-основа сессии планирования
2026-11-13 и проба динамического allowlist
([dsh-preset-allowlist.md](../reference/dsh-preset-allowlist.md)).

## Цель

Роли команды поставляются нативными пресетами DSH: оператор выбирает
архитектора и оркестратора, оркестратор сам выбирает исполнителя под
задачу по реестру, стек-бандл (1C-DSH) добавляет свои роли без оверрайда
пресетов команды. OntoShip остаётся методом и KB: гейты, доказательства
и проекции не меняются. Контур поставки — отдельный юнит; здесь роли,
реестр исполнителей и живая проба.

## Готово

Каждый пункт доказывается артефактом; носители названы.

1. **Team-бандл.** Пресеты `architect`, `orchestrator`, `executor`,
   `scout`: персона на русском, набор инструментов, `agentOptions`,
   командные секции; `ask_user_question` только у оркестратора; служебные
   пресеты помечены. — носители: файлы бандла, контрактные тесты
   композиции, живая проба в новой сессии.
2. **Реестр исполнителей.** Хост-плагин `ontoship-executors` до
   деклараций пресетов читает `<DSH_PROFILE_DIR>/ontoship/executors.json`
   и отдаёт синхронный `executors()`; `allowedAgentPresets` оркестратора —
   `!!js` от него; формат файла — массив объектов `{id, model, level}`,
   запись `executor` обязательна; дефолт при ошибке чтения —
   `["executor"]`. — носители: код плагина, контрактный тест allowlist,
   проба с неизвестным id.
3. **Выбор исполнителя оркестратором.** Правило выбора по
   `executors.json`, запись выбора в отчёт; универсальный `executor` —
   безопасный дефолт. — носители: текст скилла `chain`, контрактный тест,
   живая проба.
4. **Стековая специализация.** 1C-DSH поставляет `1c-architect`,
   `1c-orchestrator`, `1c-executor`: копия composition team-бандла + дельта
   (персона, доставка контура); team-id не переопределяются; паритетный
   тест в стек-репо сверяет копию с версией команды. — носители: патч
   стек-бандла, запись в `executors.json`, паритетный тест, проба
   в 1С-проекте; без проектных скиллов пресет — названная пустая оболочка.
5. **Маршруты ролей.** Per-call выбор модели оркестратором по
   `executors.json`: исполнитель — `deepseek-v4.1-flash-1017`/`max`,
   scout — `qwen3.8-flash`/`medium`; выбор называется в отчёте; реестр
   панели остаётся в `.agents/config.toml`. — носители: конфиг пресетов,
   правило в скилле, отчёт выбора.
6. **OntoShip-носители.** Скилл `chain` — контекстный промпт, выбор
   исполнителя и проверка версии метод-контракта (версия 1) из манифеста
   бандла; init называет team-бандл ссылкой, не дублируя маршруты; канон,
   зеркало `method-phases`, `harnesses.md`, приписка-ревизия решения 2
   `standards-autoship`. — носители: тексты, якорные тесты паритета,
   красная проба на базе.
7. **Живая проба.** Один temp-проект с `1C-DSH`: team-бандл в профиль,
   init, `1c-architect` → план-гейт → проекции → нарезка →
   `1c-orchestrator` выбирает `1c-executor` по реестру → цепочка → панель
   → автоприёмка → финишная приёмка; один игрушечный тикет. — носители:
   артефакты пробы (сессии, коммиты, отчёты), запись в тикете.
8. **Набор и KB.** Полный набор, `lint --strict`, `install.sh --check`;
   индексы, continue.md, справочник ролей и реестра. — носители: вывод
   прогонов.

## Рамки

- Только нативные примитивы DSH: пресеты, `subagent`, `agent-team`,
  `workflow`; второго рантайма нет.
- Пресеты глобальны; per-project скоупа пресетов не вводится.
- Меняется носитель ролей, не метод: гейты, доказательства, проекции,
  паки, ticket-DAG и ручные гейты оператора сохраняются.
- 1C-DSH — первый стек-потребитель; другие стеки — по тому же контракту.
- Контур поставки (`contour.lock`, `contour update`, bootstrap) —
  отдельный юнит; здесь только место для `executors.json` и ручное
  обновление.
- `chain-live-activity` и замороженный тикет 08 — вне юнита.

## Ограничения

- Пресет не несёт модель: маршрут — отдельная привязка (`agentOptions`
  инструмента, per-call поля, профиль).
- `allowedAgentPresets` вычисляется при монтировании; позже
  установленный пресет сам в allowlist не попадёт — реестр читается на
  старте.
- `require` в выражении `!!js` недоступен; реестр пресетов в выражении
  пуст при монтировании (проба).
- Лимит активных детей хоста 4; `maxDepth` 3 — панель и scout'ы идут
  рассрочкой.
- Inter-root messaging отсутствует: handoff архитектор → оркестратор
  идёт через оператора и файлы.
- Маршрутная политика сессии снимается при создании; правки — новым
  сессиям.
- Оверрайд пресета заменяет весь список детей; стек вводит новые id.
- Проба юнита — один игрушечный тикет, один прогон панели, один проход
  правок; циклов сходимости нет. Прогон дорог по токенам и времени —
  бюджет назван в отчёте пробы.
- Правки `1C-DSH` идут ship-проходом в его репозитории; этот юнит несёт
  тикет с адресом изменения и приёмкой, чужой код не коммитится здесь.
