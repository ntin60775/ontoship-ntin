# core-team-boundaries — разделение метода и ведения

Спека юнита. Повод — оператор 2026-11-16: проект стал бесконечной
недоделкой из-за размытых границ; исследование сессии планирования
показало, что канон ядра несёт нормы ведения, а скилл `chain` в ядре
зависит от плагинов team-бандла. Модель границ принята оператором
ask-проходом 2026-11-16; прототипы `chain-live-activity`,
`chain-viz-panel` и доска `ontoship-chain-board` удалены тем же
решением (коммит `574241d`).

## Цель

OntoShip core — метод (KB + grilling → to-tickets → ship),
самодостаточный на голом хосте; OntoShip Team — ведение метода
(пресеты, плагины, chain). Инвариант: **ядро не зависит от team**.
Четыре односторонних коннектора: methodContract, артефакты KB/тикеты,
ссылка init, пин стека. Проекты становятся конечными: ядро завершается
этим юнитом, team полирует ведение, не блокируя ядро.

## Решения план-гейта

Спека **утверждена на план-гейте** ask-проходом 2026-11-16 (вариант
«утвердить») после уточнения оператора о существующем team-репо
(новое репо не создаётся, перенос — в `ontoship-team`). Решения 1–8
приняты оператором ask-проходами grilling 2026-11-16
(раунды 1–3); решение 9 — подтверждение харнесс-стратегии фактами.

Тривиальные решения агента (фильтр решения 23 канона, названы):

- Slug юнита — `core-team-boundaries`; имя строки плагина —
  `ontoship-chain` (машинные литералы, обратимы).
- Установщик при update снимает выведенные бандлы с отчётом — правило
  уборки рядом с правилом создания; снимаются только известные
  выведенные бандлы, неизвестные каталоги не трогаются. Потребители:
  erp-demo, 1C-DSH, deepseek-harness (consumer-registry).
- Версия ядра — git-тег; машинного файла версии нет (`.zcode-plugin`
  снят 2026-11-10); `method-contract.json` несёт только контракт.
- Живое доказательство загрузки chain из бандла — каталог скиллов
  свежей сессии (правило [harnesses.md](../reference/harnesses.md):
  каталог — единственное доказательство загрузки) плюс пробы
  match/mismatch контракта; полный прогон цепочки не делается.

## Готово

1. **Канон и зеркало несут границы, нормы ведения сняты.** Секция
   «Границы» в `docs/decisions/ontoship-core.md`: назначение core и
   team, четыре коннектора, инвариант «ядро не зависит от team».
   Абзацы chain, ролей команды, methodContract, READ-канала и стражей
   бюджета из канона сняты; критерии автоприёмки остаются в фазе ship.
   Зеркало `skills/ship/references/method-phases.md` в паритет;
   якоря `tests/test_canon_sync.py` правятся тем же изменением.
   Доказательство: контрактные тесты паритета, вычитка.
2. **Эталон контракта — файл ядра.** `method-contract.json` в корне
   с `methodContract: 3`; chain читает эталон из файла проекта,
   сверяет с объявлением team (`package.json`, ключ
   `ontoship.methodContract: 3`) через `cordis_inspect_query`;
   mismatch/отсутствие — остановка вопросом. Доказательство:
   контрактные тесты чтения и сверки, живые пробы match/mismatch.
3. **Ядро не поставляет chain и не знает словаря ведения.** Массив
   `SKILLS` — 10 бандлов (`scripts/install.sh`), `skills/chain/`
   снят, `skills/README.md` и кортеж `tests/test_install.py` в
   паритет; установщик доставляет `method-contract.json` в корень
   проекта (эталон читается chain из проекта-потребителя);
   to-tickets без шага «Передача в цепочку» и «орк-промт»;
   контекстные строки ship о драйвере сняты; блок init — команды
   ядра и ссылка на team-бандл. Новый инвариантный тест: ядро не
   несёт team-литералов (`session_read`, `ontoshipExecutors`,
   пресеты команды) и chain в `SKILLS`. Доказательство: install
   `--check`, контрактные тесты, инвариантный тест.
4. **Team-бандл поставляет chain.** Строка `ontoship-chain` в
   `cordis.patch.yml`, SKILL.md в assets, регистрация через сервис
   `skills`; текст chain несёт нормы ведения, включая генерацию
   стартового промпта (бывший «орк-промт») и чтение эталона из
   `method-contract.json`; README team — канон ведения (нормы из
   канона ядра: READ-канал, стражи, пенсия, диктовка записей).
   Доказательство: тесты team-репо, живой каталог скиллов свежей
   сессии с chain из бандла, пробы match/mismatch.
5. **Установщик снимает выведенные бандлы; потребитель обновлён.**
   Update снимает `chain` из проектных установок с отчётом;
   update erp-demo — chain отсутствует, `check: ok`, rollout в
   consumer-registry. Доказательство: проба update в temp-проекте,
   акт rollout.
6. **Самодостаточность ядра живьём (DoD канона).** Изолированный
   хост, чистый профиль без team-бандла, temp-проект, установка
   ядра, init, игрушечный юнит: ручной `/ship` доводит тикет до
   main, панель зелёная, каждый гейт объясним. Доказательство:
   артефакты пробы (лог сессии, merge, отчёт панели) в тикете.
7. **Team-репо — проект метода.** Ядро установлено (скиллы + KB),
   спека `team-profiles` и открытые тикеты 07/08 перенесены
   (`git mv` в team-репо, содержимое спеки не меняется — только
   пути и ссылки), индексы team-репо созданы, `lint --strict`
   чист в обоих репо; закрытые тикеты и evidence team-profiles
   остаются в ядре, ссылки из ядра на перенесённое названы.
   Доказательство: lint обоих репо, вычитка ссылок.
8. **Релизы в порядке core → team → стек.** Core v0.7.0: тег на
   origin, чистая установка по каналу `install.sh`; selfhost-миграция:
   повторный init, блок AGENTS.md этого репо обновлён; team v0.3.0:
   тег, собранный `lib/` в git, объявление контракта 3; 1C-стек:
   перепин `teamVersion`/`teamCommit`, паритетный тест зелёный.
   Доказательство: `ls-remote`, паритетные тесты, чистая установка
   team из пина в temp-профиль.
9. **sa08 разморожен и переписан.** Запись решения в continue.md и
   тикете 08 `standards-autoship`; тикет 08 — дымовой тест
   pack-потока (установка пака → init с паком → ship исполняет
   гейты пака → отчёт), критерии падают на базовом коммите.
   Доказательство: текст тикета, красная проба критериев.
10. **Справочник харнессов в паритет.** Секция «Цепочка и проекции»
    `harnesses.md`: chain-часть — указатель на team-репо, проекции
    (critic) остаются в ядре; описание methodContract — эталон из
    файла; состав бандлов — 10. Доказательство: вычитка, якорные
    тесты где закреплены.

## Рамки

- Меняются носители и границы, не нормы метода: гейты, правила
  доказательств, правило качества, критерии автоприёмки сохраняются.
  Автоприёмка — критерий ядра (ship); механизм ведения (диктовка,
  записи, пенсия, таймер) — team.
- Team-репо получает минимальную KB-структуру (docs/plans, tickets,
  индексы); полный онто-док bootstrap KB team — вне юнита.
- Проба 07/08 team-profiles исполняется в team-контуре после
  разделения — вне этого юнита; спека переезжает без правки содержания.
- Исполнение sa08 — отдельный прогон после разделения; юнит только
  размораживает и переписывает тикет.
- Write/lifecycle сессионный поток A — будущее team, вне юнита.
- 1C-специализация — парк стека; здесь только перепин.
- Маркет-канал снят 2026-11-10 — релизы через git-тег и `install.sh`;
  каталог не возрождается.
- ZCode/Qoder-рельсы не возвращаются; харнесс-агностичность знания
  сохраняется (единый корень `.agents/skills`).

## Ограничения

- Правка канона сверх принятых решений 1–9 — точка остановки: вопрос
  оператору, не «доделка на ходу».
- Живая проба DoD: панель красная после одного прохода правок или
  маршрут недоступен — остановка по правилу ship, вопрос оператору;
  автоприёмка на таком контуре не делается.
- Установщик снимает только известные выведенные бандлы с отчётом;
  неизвестные каталоги в `.agents/skills` не трогаются.
- Перенос спеки team-profiles — без правки содержания; содержательная
  ревизия — решением оператора.
- Неразобранное расхождение ожидание/факт — точка остановки ship
  ([testing.md](../reference/testing.md), «Артефакт доказательства»).
- Релиз team до релиза ядра — разрыв порядка решения 6; остановка.
