# registry-source — config единственный источник маршрутов, тесты-потребители

Спека юнита. Повод: смена маршрута пула валидации краснила
`test_role_registry` — тест хардкодил `STANDARD_POOL` и сравнивал с
конфигом точным равенством. Консилиум 2026-11-25 вскрыл переобещание:
маршруты дублировались в конфиге, тестах, init-скилле и спеке, «смена =
один файл» была верна лишь для отклонения проекта. Решение оператора
2026-11-25: config — единственный источник значений, init — структура
и выбор, тесты — потребители.

## Цель

`.agents/config.toml` — единственный источник значений маршрутов
существующего проекта (роли, пул, chair). Спека несёт структурный
инвариант: пул — три различных модели, роли на месте, у записей пула
уровень непустой. Тесты читают конфиг и проверяют инвариант, не
хардкодят значения пула. Init — bootstrap-производитель: пул пишет как
структуру и выбор пар на бутстрапе (ask оператора из живого каталога),
литералов пар не несёт; раскладка шести ролей — шаблон-рекомендация, не
проект-значение. Смена проект-маршрута = правка одного файла (config);
контур зелёный, пока инвариант цел. Значения пула живут в конфиге
проекта; спека их не несёт (ревизия 2026-11-25).

## Термины

- **Источник значений** — `config.toml`: конкретные маршруты проекта.
- **Инвариант** — спека: структура (3 различных модели, роли, непустой
  уровень записей пула); независимый источник ожидания для тестов.
- **Шаблон** — init bootstrap: структура пула и выбор пар на бутстрапе,
  не значения; раскладка шести ролей — рекомендация-шаблон, не
  проект-значение.
- **Значение** — конкретный маршрут в конфиге.
- **Живость** — runtime-сверка с каталогом `list_subagent_models` (host),
  не pytest.

## Решения план-гейта

| # | решение | принято | альтернатива |
|---|---|---|---|
| 1 | config — источник значений; `test_role_registry` читает конфиг (tomllib) + структурный инвариант спеки; `STANDARD_POOL` и литералы маршрутов убраны; `CHAIR_ROUTE` читается из конфига | оператор, ask 2026-11-25 | тест пинит точные маршруты |
| 2 | На план-гейте выбраны три различных маршрута с уровнями; значения — проектное, единственный носитель `.agents/config.toml` (ревизия 2026-11-25) | оператор, ask 2026-11-25 | прежний стандарт аккаунта |
| 3 | Init — структура (3 различных модели) + выбор маршрутов на бутстрапе из живого каталога, без хардкода маршрутов; `test_skill_init` проверяет структуру init | оператор, ask 2026-11-25 (резолюция консилиума) | init пишет дефолты-маршруты (два источника) |
| 4 | Инвариант структурный в pytest (3 различных модели по model-части, роли, непустой уровень); живость и per-model уровни — runtime-префлайт консилиума, CI-пробел назван | оператор, ask 2026-11-25 | словарь уровней в pytest (второй источник) |
| 5 | Мутации структурные (дубль модели, неполный пул, потеря роли); зелёная проба — замена маршрута на структурно-различный без литерала | агент, канон testing | мутация «смени маршрут X» литералом |
| 6 | `test_skill_critic` `POOL_MODELS` из конфига + падающая проба; приписка `critic-consilium` — инвариант, паритет config↔init по инварианту, не значениям | агент, канон одно правило — один текст | хардкод маршрутов в тестах/спеке |
| 7 | Порядок правки: потребители (тесты/init) первыми, конфиг последним или тем же изменением | агент, следует из инварианта | config-first (краснит контур) |

**Ревизия 2026-11-25 (решение оператора).** Init без литералов только в
пуле: раскладка шести ролей остаётся шаблоном-рекомендацией, маршруты
ролей в config не трогаются. Выбор пар пула на бутстрапе — ask
оператора: варианты из живого каталога, запись после ответа (единое
правило с отсутствующей секцией `[validation]`); делегированный прогон —
названный стоп. Цель, Готово, Рамки и Ограничения читаются с этой
ревизией.

## Готово

- `.agents/config.toml` `[validation]`: пул из трёх различных моделей по
  model-части, у каждой записи непустой уровень; значения живут в конфиге
  (целевые для юнита — в тикете 02). Носитель: файл, читается.
- `tests/test_role_registry.py`: читает конфиг (`tomllib`); инвариант —
  пул из трёх записей, три различных модели (по model-части маршрута),
  роли ядра и critic на месте, у записей пула уровень непустой (level
  роли может отсутствовать — дефолт модели); `STANDARD_POOL` и
  литерал `CHAIR_ROUTE` убраны (chair читается из конфига). Мутации
  строятся из разобранного конфига, без литералов: дубль записи, неполный
  пул, пустой уровень записи пула, потеря секции роли — красные; смена
  model-части (`-probe`, провайдер тот же) — зелёная. Пробы `drifted-route`
  и `chair-route` сняты: смена структурно валидного значения законна
  (живость — runtime). Действующие
  пробы `no-pool-section`, `lost-level`, `duplicate-entry`,
  `same-model-twice`, `lost-core-section` остаются. Носитель:
  `test_role_registry.py`.
- `tests/test_skill_critic.py`: `POOL_MODELS` читается из конфига,
  падающие пробы — пустой пул и дубль model-части; паритет config↔init —
  по инварианту. Носитель: `test_skill_critic.py`.
- `skills/init/SKILL.md`: пул — структура (три различных модели по
  model-части) + ask на бутстрапе (варианты из живого каталога, запись
  после ответа; делегированный прогон — названный стоп); литералов пар
  пула нет; раскладка шести ролей не меняется.
  `tests/test_skill_init.py`: `POOL_NEEDLES` и пуловые пробы — по
  структуре; раскладка и её пробы остаются.
  Носители: `skills/init/SKILL.md` (симлинк `.agents/skills/init`),
  `test_skill_init.py`.
- `docs/plans/critic-consilium.md`: приписка — инвариант «3 различных
  модели», пары пула — значения конфига; хардкод пар в Готово и «паритет
  с init» по значениям сняты, паритет по инварианту; пар пула в тексте
  нет. Носитель: файл, читается.
- Живость: вывод живого `list_subagent_models` по парам пула и
  председателя, дата — в отчёт исполнения/гейта; неживая пара или
  уровень вне каталога — стоп с причиной и вариантами, не тихая замена.
  Носитель: отчёт.
  CI-пробел: pytest оффлайн живость не проверяет — назван в Рамках.
- Доказательство single-source: смена структурно валидного маршрута в
  конфиге не краснит тесты (структурная зелёная проба), нарушение
  инварианта краснит. Носитель: мутационные пробы `test_role_registry.py`.
- Полный `pytest tests/ -q` зелёный, `gitmark.py lint --strict` чист.

## Рамки

- Меняется конфиг, тесты-потребители, init bootstrap и приписка спеки;
  маршруты ролей reviewer/critic/curator не трогаются (кроме пула
  валидации); раскладка шести ролей в init остаётся шаблоном-
  рекомендацией.
- Новых ролей и секций `[agents.*]` нет.
- config — источник значений; init — bootstrap структуры и выбора
  (производитель конфига для новых проектов); спека — инвариант. Смена
  проект-значения = config; смена инварианта = спека и носители одним
  изменением.
- Живость и per-model допустимость уровней — runtime-префлайт консилиума
  (host-инструмент); pytest оффлайн проверяет только структуру —
  CI-пробел назван.
- Зависимость: flash-1017 — инцидентный маршрут ревьюеров (`PI_AI_ERROR`);
  юнит `review-output` чинит его контракт вывода. Панельный прогон на
  flash-1017, если он понадобится, идёт после review-output, иначе риск
  назван. Сверка маршрутов через `list_subagent_models` прогоном не
  считается и этим порядком не ограничена.

## Ограничения

- Тесты не хардкодят значения пула: читают конфиг и проверяют
  структурный инвариант спеки. Литералы маршрутов в тестах остаются
  только у шаблона раскладки шести ролей; дрейф шаблона против config
  тестом не охраняется — названная цена ревизии 2026-11-25.
- Различность — по model-части маршрута (`provider/model`): одна модель
  на двух провайдерах не различна.
- Уровень записей пула структурно непустой; level роли может
  отсутствовать — дефолт модели. Per-model допустимость и живость —
  runtime-префлайт, не pytest-словарь (словарь в тесте — второй источник).
- Порядок правки: потребители (тесты/init) первыми, конфиг последним или
  тем же изменением; config-first краснит контур.
- Пул — три различных модели; дубль модели или неполный пул — красное.
- Разбор расхождений ожидание/факт — точка остановки ship: дефект —
  правка и target-тест; не дефект — записанная причина; расхождений не
  было — строка «не было». Неразобранное блокирует merge.

## Контекст

- Повод: правка пула на flash-1017 краснила `test_role_registry`
  (`sorted(entries) != sorted(STANDARD_POOL)`); консилиум показал
  стандарт в трёх носителях. Оператор: init — структура и выбор, config
  — единственный источник значений.
- Канон testing: ожидаемое значение из независимого источника (инвариант
  спеки), а не пересчитано кодом; значения — из конфига, инвариант — из
  спеки.
- Канон «одно правило — один полный текст»: инвариант пула живёт в спеке,
  значения — в конфиге; тесты связывают их, не дублируют.
- Стандарт flash-1017 — инцидентный маршрут ревьюеров; юнит
  `review-output` чинит его контракт вывода (сухие находки без эха).
