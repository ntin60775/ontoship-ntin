# registry-source — config единственный источник маршрутов, тесты-потребители

Спека юнита. Повод: смена маршрута пула валидации краснила
`test_role_registry` — тест хардкодил `STANDARD_POOL` и сравнивал с
конфигом точным равенством. Маршруты дублировались в конфиге, тесте,
init-скилле и спеке. Решение оператора 2026-11-25: config — единственный
источник, остальные — потребители; правка маршрута в одном месте.

## Цель

`.agents/config.toml` — единственный источник маршрутов проекта и
стандарта пула. Тесты и спека потребляют его: читают конфиг и проверяют
инвариант спеки (пул — три различных модели, роли на месте, уровни
валидны), а не хардкодят значения. Смена маршрута = правка одного файла;
контур зелёный, пока инвариант цел. Стандарт пула —
`qwen-token-plan-deepseek/deepseek-v4.1-flash-1017`/`max`,
`qwen-token-plan/qwen3.8-flash`/`xhigh`,
`qwen-token-plan-glm/glm-5.3`/`max`.

## Решения план-гейта

| # | решение | принято | альтернатива |
|---|---|---|---|
| 1 | config — источник; `test_role_registry` читает конфиг и проверяет инвариант спеки (3 различных модели пула, роли, уровни), не точные значения; хардкод `STANDARD_POOL` убран | оператор, ask 2026-11-25 | тест пинит точные маршруты |
| 2 | Стандарт пула — flash-1017/max, qwen3.8-flash/xhigh, glm-5.3/max; init-скилл пишет те же дефолты | оператор, ask 2026-11-25 | flash-1017 только отклонение проекта; deepseek-account стандарт |
| 3 | `test_skill_critic` `POOL_MODELS` читает из конфига (потребитель); `test_skill_init` проверяет текст init (bootstrap-источник дефолтов) | агент, следует из цели | хардкод маршрутов в тестах |
| 4 | Спека `critic-consilium`: приписка — инвариант «3 различных живых модели», конкретные маршруты — выбор конфига; хардкод маршрутов в Готово снят | агент, канон одно правило — один текст | оставить хардкод в спеке |
| 5 | Мутационные пробы нарушают инвариант (дубль модели, неполный пул, невалидный уровень), не смену валидного значения | агент, канон testing | мутация «смени маршрут X» |

## Готово

- `.agents/config.toml` `[validation]`: пул flash-1017/max,
  qwen3.8-flash/xhigh, glm-5.3/max. Носитель: файл, читается.
- `tests/test_role_registry.py`: читает конфиг (`tomllib`), проверяет
  инвариант — пул из трёх записей, три различных модели, уровни валидны,
  роли ядра и critic на месте; точное сравнение с `STANDARD_POOL` убрано.
  Мутации: дубль модели пула, неполный пул, невалидный уровень — красные;
  смена валидного маршрута — зелёная. Носитель: `test_role_registry.py`.
- `tests/test_skill_critic.py`: `POOL_MODELS` читается из конфига, не
  хардкод. Носитель: `test_skill_critic.py`.
- `skills/init/SKILL.md`: дефолты пула — flash-1017/max,
  qwen3.8-flash/xhigh, glm-5.3/max; `tests/test_skill_init.py` обновлён
  под текст init (bootstrap-источник). Носители: `skills/init/SKILL.md`
  (симлинк `.agents/skills/init`), `test_skill_init.py`.
- `docs/plans/critic-consilium.md`: приписка — инвариант пула «3 различных
  живых модели», маршруты — выбор конфига; строки Готово с хардкодом
  маршрутов переведены на инвариант. Носитель: файл, читается.
- Доказательство single-source: смена валидного маршрута в конфиге не
  краснит тесты (мутация значения зелёная), нарушение инварианта краснит.
  Носитель: мутационные пробы `test_role_registry.py`.
- Полный `pytest tests/ -q` зелёный, `gitmark.py lint --strict` чист.

## Рамки

- Меняется реестр-конфиг, тесты-потребители, init-дефолты и приписка
  спеки; маршруты ролей reviewer/critic/curator не трогаются (кроме
  пула валидации).
- Новых ролей и секций `[agents.*]` нет.
- Инвариант спеки (3 различных живых модели) — независимый источник
  ожидания (канон testing); значения маршрутов — из конфига.
- Init-скилл — bootstrap-производитель конфига для новых проектов; его
  дефолты — стандарт, отдельный от проект-конфига источник шаблона.

## Ограничения

- Тесты не хардкодят значения маршрутов проект-конфига: читают конфиг и
  проверяют инвариант спеки.
- Пул — три различных живых модели; дубль модели или неполный пул —
  красное; маршруты и уровни сверяются с живым каталогом.
- Смена валидного маршрута (инвариант цел) не должна краснить тесты —
  это и есть single-source.

## Контекст

- Повод: правка пула на flash-1017 краснила `test_role_registry`
  (`sorted(entries) != sorted(STANDARD_POOL)`); маршрут дублировался в
  конфиге, тесте, init-скилле, спеке. Оператор: источник только конфиг.
- Канон testing: ожидаемое значение из независимого источника (инвариант
  спеки), а не пересчитано кодом; значения — из конфига, инвариант — из
  спеки.
- Канон «одно правило — один полный текст»: инвариант пула живёт в спеке,
  маршруты — в конфиге; тесты связывают их, не дублируют.
- Стандарт flash-1017 — инцидентный маршрут ревьюеров; юнит
  `review-output` чинит его контракт вывода (сухие находки без эха).
