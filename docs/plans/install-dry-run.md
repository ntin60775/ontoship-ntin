# install --dry-run — план установки без записи

**Состояние (2026-10-22): план утверждён, гейт прошёл задним числом.** Прогон начался
без живого план-гейта: спеку и реализацию исполнитель сделал по тикету 06, а решения
взял по рекомендованным умолчаниям. Оператор утвердил спеку и код после отчёта и
оставил их в репозитории; это процессный дефект прогона, записанный в отчёте
([tickets/workflow-skills/06-dogfood.md](../../tickets/workflow-skills/06-dogfood.md)).
Детализацию каждого решения оператор оценивает отдельно; правка решения идёт новой
спекой, а не правкой задним числом.

## Цель

Оператор видит план установки до записи на диск: какие каталоги появятся, какие
скиллы свяжутся или скопируются, какие останутся без изменений и где установка
откажется. `--check` отвечает «что уже есть», `--dry-run` — «что скрипт сделает»;
второго ответа сейчас нет.

## Факты

- `scripts/install.sh` знает три режима — link (умолчание), `--copy`, `--check` — и
  `-h/--help`; справка `usage()` перечисляет их. Запись идёт только после
  `preflight_install`; `install_links` печатает `unchanged`/`linked`,
  `install_copies` — `unchanged`/`copied`.
- `--check` только читает и печатает `ok`/`drift`; на вопрос, что сделает установка,
  он не отвечает.
- Контракт установки в `tests/test_install.py` держит раскладку `.agents/skills`,
  идемпотентность, дрейф, отказы и запрет записи вне цели; помощник `tree()`
  сравнивает вид, inode, mtime и содержимое.
- Remote нет (`git remote -v` пуст), поэтому PR-путь в прогоне недостижим.

## Решения прогона

Оператор не отвечал на раунд до реализации. Ниже — решения, принятые исполнителем, и
отвергнутые альтернативы; оператор утвердил план после отчёта и оценивает каждое
решение по детализации.

| # | решение | принято в прогоне | альтернатива и почему отвергнута |
|---|---|---|---|
| 1 | предмет юнита | режим установщика | правка движка — вне рамок KB-ядра; документация не даёт наблюдаемого результата |
| 2 | что делает `--dry-run` | печатает план и проводит preflight, диск не трогает | план без preflight не показывает главный риск — отказ на занятом пути |

| 5 | legacy-предупреждения | не печатать: реальная установка их не печатает | печатать — режим перестал бы зеркалить установку |

## Готово

1. `scripts/install.sh --dry-run <project>` печатает `would create <dest>`, затем по
   строке на скилл — `would link <name> -> <src>` или `would leave <name>
   unchanged`; код 0; `.agents` не появляется.
2. `--dry-run` проводит preflight: занятый не-симлинком путь даёт `refusing to
   replace …`, код 1, диск не меняется; `--dry-run --check` — ошибка использования,
   код 2.
3. `--dry-run --copy` печатает `would copy <name> -> <path>` или `would leave …
   unchanged`, а разошедшаяся копия даёт `copy differs`, код 1 и отсутствие записи.
4. Справка `usage()` и шапка скрипта называют режим; `tests/test_install.py` держит
   пункты 1–3 spec-тестами, и каждый падает на базовом коммите.

## Рамки

- `scripts/install.sh` и `tests/test_install.py`.
- Скиллы, движок `skills/kb-search/gitmark.py`, онтология и `vendor/` не меняются.

## Ограничения

- Точка остановки: перед merge пройти этот раздел. Прогон не останавливается —
  тикет dogfood разрешает локальный коммит; remote нет, PR-путь остаётся названным
  пробелом.
- Судьбу спеки и фичи оператор решает после отчёта: оставить, переутвердить или
  удалить. Решение не меняет поведение на ходу.
- Решения 1–7 вживую не подтверждены; менять их в проходе `ship` нельзя — только
  новой спекой.

## Контекст

`--check` закрывает половину нужды: он говорит, что лежит в проекте сейчас. Перед
первой установкой оператору нужен ответ на другой вопрос — что скрипт создаст,
свяжет или скопирует и где откажется. Dogfood-тикет требует сквозного прогона
grilling → to-tickets → ship; режим установщика даёт маленький юнит с наблюдаемым
результатом и контрактным тестом, не задевая движок.
