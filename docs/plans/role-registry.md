# role-registry — машинный источник перечня ролей ядра

Спека мини-юнита. Повод — разбор пользы с оператором 2026-11-01 после среза
зацепок: перечень ролей ядра — последний перечень проекта без машинного
источника; у бандлов источник — массив `SKILLS` установщика с паритетом
на четыре носителя. Решения 1–4 приняты оператором ask-раундом того же
дня, все по рекомендациям.

## Цель

Перечень ролей ядра живёт в одном машинном источнике; рассинхрон носителей
перечня краснет набором, а не ловится панелью следующего юнита. Состав
ролей не меняется: ядро — шесть, панель — четыре, как сегодня.

## Решения план-гейта

| # | решение | принято | альтернатива |
|---|---|---|---|
| 1 | Носитель — `skills/init/roles.py`: прод-файл в бандле init рядом с `gen_agents.py`; тесты парсят текстом, как массив `SKILLS` установщика | оператор, ask 2026-11-01 | блок в SKILL.md; справочник полным ядром; кортеж в тесте источником |
| 2 | Семантика — два кортежа: ядро и панель, панель — подмножество ядра (инвариант тестом); фикстуры `test_gen_agents` выравниваются до ядра | оператор, ask 2026-11-01 | плоский список с флагами; кодифицировать три среза как есть |
| 3 | Механика — один якорный тест `tests/test_role_registry.py`: парсит реестр и сверяет кортежи потребителей, перечень скилла и секции справочника; потребители не переписываются | оператор, ask 2026-11-01 | все тесты читают реестр напрямую |
| 4 | Стандарт доказательств полный: спека → нарезка ask-ом → критик после приёмки нарезки → панель в ship; один тикет | оператор, ask 2026-11-01 | экономно без панельных прогонов |

## Готово

1. **Реестр.** `skills/init/roles.py` — кортеж `CORE_ROLES` (ядро: четыре
   ревью-роли, `critic`, `curator`) и `PANEL_ROLES` (панель: четыре
   ревью-роли), без исполняемой логики — только данные и комментарий
   о происхождении. — носитель: файл в репозитории; инвариант
   «панель ⊆ ядро» проверяется якорным тестом.
2. **Якорный тест.** `tests/test_role_registry.py` парсит реестр текстом
   и сверяет паритетом: `CORE_ROLES` из `tests/test_skill_init.py` ↔ ядро,
   `ROLES` из `tests/test_review_roles.py` ↔ панель, `CORE_ROLES` из
   `tests/test_gen_agents.py` ↔ ядро, перечень строки сверки скилла
   `skills/init/SKILL.md` ↔ ядро, заголовки секций базового набора
   `docs/reference/review-roles.md` ↔ панель. Мутационные пробы — на каждый
   носитель: убранная роль, фантомная роль, урон реестра. — носитель:
   прогон на базовом коммите красный по кортежу `test_gen_agents` (пять
   ролей без `curator` против шести) и зелёный после выравнивания фикстур.
3. **Выравнивание фикстур.** `tests/test_gen_agents.py` строит конфиги из
   шести ролей ядра; ручная дописка `set(CORE_ROLES) | {"curator"}`
   уходит. — носитель: прогон тестов генератора зелёный; паритет
   якорного теста зелёный.
4. **Доставка.** Бандл `init` ставится целиком: `roles.py` доезжает
   в link- и copy-режимах без правки `scripts/install.sh`. — носитель:
   расширение copy-проверки бандла init до `roles.py` рядом
   с `gen_agents.py`.
5. **Критик и панель.** Критик — после приёмки нарезки, до первого ship;
   панель четырёх ролей — ревью-шаг ship. — носитель: идентификаторы
   прогонов строкой в критериях тикета.

## Рамки

- Только перечень ролей и его носители: реестр, якорный тест, фикстуры
  генератора, copy-проверка бандла, строка реестра в continue.md.
- Состав не меняется: ядро — шесть, панель — четыре; новые роли — вне
  рамок, реестр лишь делает их добавление правкой одного файла.
- `gen_agents.py` не трогается: генератор работает от конфига проекта
  и перечня ядра не знает; `skills/init/SKILL.md` — только если паритет
  потребует, проза не переписывается.
- Установщик не правится: доставка бандла уже цельная.
- Попутная правка runbook: строка «расширенный паритет отвергнут
  оператором по цене» в continue.md ошибочно приписывает оператору решение
  исполнителя — исправляется плановым обновлением вместе с состоянием
  юнита.

## Ограничения

- Состав бандлов не меняется: `roles.py` — новый файл существующего
  бандла `init`, установщик и перечень `SKILLS` не трогаются.
- Один тикет, один ship-проход; панель — обязательный шаг (решение 4).
- Неразобранное расхождение ожидание/факт — точка остановки ship
  ([testing.md](../reference/testing.md), «Артефакт доказательства»).

## Контекст

- Рассинхрон существует в коде: `CORE_ROLES` из шести ролей
  (`tests/test_skill_init.py:30`), `ROLES` из четырёх
  (`tests/test_review_roles.py:40`), `CORE_ROLES` из пяти без `curator`
  (`tests/test_gen_agents.py:37`) с ручной допиской куратора в проверке
  схемы конфига (`set(CORE_ROLES) | {"curator"}`, строка 461).
- Прецедент машинного источника — массив `SKILLS` установщика и тест
  паритета на четыре носителя (юнит `review-loose-ends`, «Готово» 1);
  парсинг текстом, без импорта.
- Срез зацепков того же дня уже закрыл счётчики ролей нейтральными
  формулировками, двусторонним паритетом перечня скилла с `CORE_ROLES`
  из `test_skill_init` и сторожем числительных; реестр встаёт над этой
  цепочкой источником, не отменяя её.
- Польза и цена разобраны с оператором до открытия юнита: страховка
  тихого рассинхрона кортежей плюс консистентность нормы «правила живут
  в механизмах»; частота события низкая — состав менялся дважды за десять
  юнитов.
