# review-loose-ends — зацепки ревью 03–04 onto-doc

Спека мини-юнита. Дизайн и цена доказательства — ask-раунд оператора
2026-11-01: обе зацепки одним мини-юнитом с одним тикетом, полный стандарт
доказательств.

## Цель

Две зацепки ревью юнита `onto-doc`, оставленные панелями тикетов 03
(`dwfrun-f933a3d1`) и 04 (`dwfrun-75996917`), закрыты механизмами, а не
только текстом: состав бандлов сторожится тестом паритета, формулировки
реестра ролей нейтральны к росту числа ролей, счётчики-срезы не живут
в справочниках.

## Решения план-гейта

| # | решение | принято | альтернатива |
|---|---|---|---|
| 1 | Обе зацепки — один мини-юнит, один тикет | оператор, ask 2026-11-01 | два тикета; отложить |
| 2 | Утверждённая спека `review-config.md` не переписывается — durable-приписка-вставка у строки «Роли ядра — пять» (раздел «Рамки» спеки) | оператор, ask 2026-11-01 | правка строки решения |
| 3 | Доказательства — полный стандарт: контракты, красные там, где правится текст, критик после нарезки, панель в ship | оператор, ask 2026-11-01 | экономно без панели; минимум без панельных прогонов |

## Готово

1. **Паритет состава бандлов.** Тест в `tests/test_install.py` читает
   список `SKILLS` из `scripts/install.sh` и бандл-строки из
   `skills/README.md`, требует равенство в обе стороны (нет пропавших
   и фантомных) и связку «Раскладка» → `skills/README.md` в `AGENTS.md`;
   число бандлов нигде не хардкодится. — носитель: тест зелёный
   на базовом состоянии (паритет уже выполняется), мутационные пробы
   краснят — убранная строка индекса, фантомный бандл в `SKILLS`,
   оборванная связка.
2. **Формулировки реестра ролей.** `skills/init/SKILL.md` — «реестр
   ролей ревью» → «реестр ролей» во всех трёх местах (description, тело);
   контракт `tests/test_skill_init.py` правится тем же изменением
   и запрещает старую формулировку; `docs/plans/review-config.md` получает
   приписку-вставку у строки «Роли ядра — пять»: ролей ядра шесть с юнита
   `onto-doc` (решение 3 его спеки), добавлен `curator`. — носитель:
   контракт красный на базовом коммите (запрещённая формулировка
   присутствует) и зелёный после; diff приписки — в тикете.
3. **Счётчик-срез убран.** `docs/reference/harnesses.md` — строка «девять
   скиллов» с перечислением заменяется указателем на `skills/README.md`
   без числа и перечня; состав живёт в одном месте. — носитель: греп
   «девять скилл» по `docs/reference/` пуст, вывод в тикете; правило
   «числа-срезы не живут в знании» уже несёт канон текстов.
4. **Критик и панель.** Критик — после приёмки нарезки, до первого ship;
   панель четырёх ролей — ревью-шаг ship. — носитель: записи прогонов
   в тикете.

## Рамки

- Только названные зацепки: формулировки `skills/init/SKILL.md`,
  приписка в `review-config.md`, указатель в `harnesses.md`, тест паритета.
  Формулировки «реестр ролей» в `review-roles.md` и `harnesses.md` уже
  нейтральны — эти тексты не трогаются; в `harnesses.md` меняется только
  строка счётчика.
- Строки спеки вне зацепки (в том числе «пять пунктов чек-листа» у
  решения 10) не правятся.

## Ограничения

- Утверждённые спеки не переписываются: только приписка-вставка
  (решение 2).
- Состав бандлов не меняется: юнит ставит сторож и правит текст, бандлы
  не добавляются и не убираются.
- Один тикет, один ship-проход; панель — обязательный шаг (решение 3).
