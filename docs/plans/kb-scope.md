# kb-scope — настраиваемый корпус KB в движке GitMark

## Цель

Корпус KB задаёт проект отслеживаемым файлом `gitmark.scope.json` в корне
репозитория, и движок применяет его в одном месте — `iter_md`. `index`, `search`,
`stat`, `map` и `lint` считают покрытие по одному определению, поэтому
`lint --strict` годится в checkpoint прогона: он красный по KB и зелёный, когда
внутри KB чисто, даже если рядом лежат генерируемые ожидаемые выводы тестов и
поддеревья, чью форму определяет внешний гейт.

Предмет — механизм, не чужое дерево: движок не знает имён `snapshots/` и
`docs/upgrade-guide/`, их называет файл проекта.

## Решения

Приняты оператором ask-проходом 2026-11-10 (три раунда фронтира). План-гейт
2026-11-10 утвердил спеку вместе с решениями 16–17, сняв их условность.

| # | решение | отвергнутая альтернатива |
|---|---|---|
| 1 | Носитель — `gitmark.scope.json` в корне, отслеживаемый git | `.gitmark/scope.json` (производное, в [.gitignore#L2](../../.gitignore) — не переживает clone); секция в `.agents/config.toml` (в consumer-дереве файла нет в git, нужен tomllib 3.11+); блок в `AGENTS.md`; жёсткие префиксы в `EXCLUDE_DIRS` перенесли бы чужую политику в ядро |
| 2 | Семантика — только исключение, без `include`-списка | whitelist KB: каждый проект обязан исчерпывающе перечислить `docs` и корневые `.md`, иначе покрытие тихо теряется |
| 3 | Формат — единственный ключ `exclude_prefixes`, без поля версии схемы | `{version, exclude_prefixes}`: второе поле ничего не переключает, но требует ветки в валидаторе |
| 4 | Scope режет корпус для всех команд разом | резать только линт: «покрыто / не покрыто» разошлось бы с `search` — ровно то, на что жалуется ишью |
| 5 | `WARN I5` снимается исключением поддерева из корпуса; отдельного маркера нет | `.gitmark-ignore-index` в папке: второй способ замолчать об инварианте плюс правка текста I5 в обоих носителях канона |
| 6 | Контракт «пути сужают только per-file» остаётся; вывод печатает «в выборке / вне выборки» | сужать глобальные проверки — пересмотр утверждённой спеки и её стража |
| 7 | exit-коды 0/1/2 не меняются | отдельный код «красно только вне корпуса»: дублирует п.1 и ломает зафиксированную семантику отказа |
| 8 | Невалидный scope — строгий отказ до любых проверок | предупреждение + весь корпус: зелёный lint означал бы «scope не прочитан» |
| 9 | `lint` всегда печатает строку об исключениях при ненулевом excludes | только в `--json`: у `lint` флага `--json` нет ([#L1090-L1091](../../skills/kb-search/gitmark.py)); человек без машинного вывода не увидел бы сужения |
| 10 | Доказательство — тест-фикстура на временном git-репозитории плюс живой прогон на consumer-дереве | только фикстуры: «ноль находок на реальном дереве» остаётся необязанным; только живой прогон: парсинг scope не регресситестится |
| 11 | Consumer-доказательство — скопированный вывод команды в закрытом тикете | автотест, клонирующий consumer: сеть и чужие 5084 `.md` в детерминированном наборе |
| 12 | Догфуд: `gitmark.scope.json` в этом репозитории исключает `tickets/` | оставить корпус как есть: 55 файлов трекера остаются в поиске и статистике KB |
| 13 | Полный текст правила живёт в `skills/kb-search/SKILL.md` | `docs/reference/kb-corpus.md` (правило уборки уезжает от механизма); только спека плана (после закрытия тикетов правило остаётся в истории git) |
| 14 | Планка файла движка поднимается до ~1400 строк записанным решением | оставить ~1300 и резать существующий код: фикс требует выноса, риск растёт |
| 15 | Bump версии, тег и rollout в consumer-registry — вне юнита | тот же юнит до релиза: ship-тикеты смешиваются с релизной механикой реестра |
| 16 | Префикс обязан заканчиваться `/` (папка) или называть существующий файл, иначе — отказ (решение план-гейта) | матчинг подстроки: `snapshots` зацепил бы `snapshots-notes/` |
| 17 | `stat --json` несёт поле `scope` — число исключённых файлов и префиксов (решение план-гейта) | машинный вывод не видит сужения: `stat` остаётся единственным местом, где покрытие читают скрипты прогона |

## Готово

1. **Scope режет корпус целиком.** `iter_md` ([#L262-L268](../../skills/kb-search/gitmark.py))
   применяет `exclude_prefixes` из `gitmark.scope.json`, найденного от корня
   репозитория; файла нет — сегодняшнее поведение, обратная совместимость
   сохранена. — носитель: `tests/test_scope.py` на временном git-репозитории;
   фикстуру такого репозитория заводит этот же тикет — сегодня `git init`
   повторяется инлайн в `tests/test_engine.py`, общей фикстуры нет. Файл под
   префиксом исчезает из `stat --json` (счётчик `files`), из `search`, из корпуса
   `lint` (`checked`) и из `map`; без файла те же файлы в корпусе. Каждый пункт
   падает на базовом коммите.
2. **Корпус не зависит от наличия git.** Фильтр стоит в `iter_md`, до её развилки
   на `git_md_files` и `iter_md_fallback` ([#L246-L259](../../skills/kb-search/gitmark.py)),
   поэтому путь без git уважает scope так же. — носитель: инвариантный тест
   `tests/test_scope.py` с monkeypatched-`subprocess.run` (git недоступен): корпус
   совпадает с git-путём.
3. **Отказ вместо молчания.** Битый JSON, `exclude_prefixes` не список, элемент не
   строка, неизвестный ключ и префикс без завершающего `/`, не именующий
   существующий файл (решение 16) — сообщение в stderr, exit 2, stdout пуст, ни
   одна проверка не выполнена; тот же контур, что `LintPathError`
   ([#L1129-L1144](../../skills/kb-search/gitmark.py)). — носитель: пять
   spec-теста (по одному на случай) плюс инвариант «exit 2 и пустой stdout» в форме
   `test_cli_refusal_exit2_stderr_stdout_empty`.
4. **Исключения видны.** При ненулевом excludes `lint` печатает строку
   `scope: <N> файлов исключено по <K> префиксам`; при пустом или отсутствующем
   scope строки нет. — носитель: spec-тест сверяет литерал и числа с фикстуры;
   молчаливый случай (без scope) сторожится вторым тестом того же файла.
5. **Выборка путей не меняет контракт.** `lint <paths>` печатает две строки —
   `в выборке: <X> ERR · <Y> WARN` и `вне выборки: …`; `checked` остаётся размером
   корпуса, `_lint_global` ([#L896-L905](../../skills/kb-search/gitmark.py)) не
   сужается. — носитель: spec-тест `tests/test_scope.py` плюс существующий страж
   `tests/test_lint_paths.py` (`test_selection_narrows_only_per_file_checks`),
   который проходит без правки (инвариант
   принятого контракта).
6. **Consumer-кейс закрыт.** На consumer-дереве с тремя префиксами
   `snapshots/`, `apps/web/tests/expected/`, `docs/upgrade-guide/` линт даёт
   `✓ чисто`, а `lint --strict` — exit 0. Ожидание: до фикса
   `19 ERR · 119 WARN (2345 файлов · I4×19 · I5×119)` (замерено 2026-11-10).
   — носитель: ручной прогон, скопированный вывод в закрытом тикете.
7. **Догфуд в этом репозитории.** `gitmark.scope.json` с `tickets/`:
   `lint --strict` exit 0; `stat --json` даёт ровно на столько файлов меньше,
   сколько `.md` лежит в `tickets/` на базовом коммите тикета, и `files` равна
   `checked` из `lint`; `tickets/**` в корпусе нет; поле `scope` присутствует
   всегда — без scope-файла или с пустым списком оно несёт нули (решение 17);
   `search` не находит трекер. Числа на момент спеки — перездмер 2026-11-10:
   корпус 106 файлов, в `tickets/` 58 `.md` (55 отслеживаемых + 3 тикета этого
   юнита), значит после догфуда ожидается 48. — носитель: вывод команд на
   базовом коммите тикета и на срезе, скопированный в закрытый тикет; тест-инвариант,
   что корпус пакета не содержит `tickets/` (фикстура читает реальный
   `gitmark.scope.json` репозитория); абсолютные числа в критерий не входят —
   они drift'ят вместе с трекером.
8. **Носители правил.** Полный текст про корпус и scope — в
   `skills/kb-search/SKILL.md`; `skills/kb-curate/SKILL.md` ссылается на него без
   пересказа; `docs/ontology.md` и его копия `skills/kb-curate/ontology.md` не
   правятся (I4 и I5 остаются текущими текстами); в
   [core-kb.md#готово-4](core-kb.md) «≤ ~1300» меняется на «≤ ~1400» с припиской
   решения оператора. — носитель: контрактный тест скилла сверяет якоря текста,
   I8 (twin-проверка онтологии) проходит, `git diff` не затрагивает онтологию —
   проверяется в критерии тикета.

## Рамки

- `vendor/ontoship-zcode/gitmark.py` — MIT-база движка, не правится; предмет —
  поставляемая копия `skills/kb-search/gitmark.py`.
- Установщик (`scripts/install.sh`) и `skills/init` `gitmark.scope.json` не
  создают и не правят: файл принадлежит дереву проекта.
- `.gitignore` остаётся механизмом для файлов, которых нет в git; scope — для
  git-visible не-KB markdown.
- Источник юнита — [ишью #1](https://github.com/ntin60775/ontoship-ntin/issues/1);
  закрытие ишью — после merge тикета, со ссылкой на эту спеку.
- Релиз (версия, тег, rollout в consumer-registry) — вне юнита, решение 15.

## Ограничения

- Якоря `#L…` в этой спеке — указатели, сверенные прогоном 2026-11-10: место в
  коде называют именем символа (`iter_md`, `_lint_readme_index`,
  `gitignore_warnings`), якорь гниёт при правке движка и не несёт норму.
- Scope — свойство корпуса, не инвариант онтологии: I1–I6 и I8–I10 не растут,
  текст `docs/ontology.md` не меняется.
- Префикс — относительный путь от корня репозитория. Glob-диалект, `..` и
  абсолютные пути вне формата (решение 3); нормализация целей — NFC, как в
  выборке путей (`_nfc`, страж `test_unicode_forms_are_byte_exact`).
- Условных мест не осталось: формат префикса закрешён решением 16, поле `scope`
  в `stat --json` — решением 17, оба приняты на план-гейте 2026-11-10.
- Пробел: поведение на дереве, где `git ls-files` отдаёт `.md` вне рабочей копии
  (submodule, symlink), не замерено; фолбэк-предупреждение `gitignore_warnings`
  ([#L232-L243](../../skills/kb-search/gitmark.py)) про такие файлы не докладывает.

## Контекст

Ишью [#1](https://github.com/ntin60775/ontoship-ntin/issues/1) (OPEN, автор
ntin60775, 2026-11-10): consumer-репозиторий с DSH-форком даёт `19 ERR · 119 WARN`,
ни одна находка не относится к KB, `lint --strict` всегда красен, «чисто ли в KB»
вычитается руками.

Замерено в этом прогоне (2026-11-10, consumer-дерево):

```console
$ python3 .agents/skills/kb-search/gitmark.py lint | tail -1
19 ERR · 119 WARN  (2345 файлов · I4×19 · I5×119)
$ python3 .agents/skills/kb-search/gitmark.py lint docs/README.md | tail -1
19 ERR · 119 WARN  (2345 файлов · I4×19 · I5×119)
```

Находки: `snapshots/` — 18 `ERR I4`, `apps/web/tests/expected/` — 1 `ERR I4`,
`docs/upgrade-guide/` — 119 `WARN I5`. Три префикса закрывают все 138. В consumer
4423 из 5084 `*.md` лежат вне `docs/`; снапшоты содержат литеральный
`<path/to/image.png>`, который `LINK_RE` ([#L50](../../skills/kb-search/gitmark.py))
читает как ссылку, а файлы сравниваются тестами байт в байт.

Почему так выходит: корпус = `git ls-files --cached --others --exclude-standard`
минус `EXCLUDE_DIRS` ([#L39-L46](../../skills/kb-search/gitmark.py),
[#L137-L161](../../skills/kb-search/gitmark.py)); `I4` считается по всему корпусу
без выборки ([#L805-L837](../../skills/kb-search/gitmark.py)), `I5` — сканом папок
`docs/**` ([#L840-L848](../../skills/kb-search/gitmark.py)), `checked` — размер
корпуса ([#L935](../../skills/kb-search/gitmark.py)), и docstring `cmd_lint`
([#L911](../../skills/kb-search/gitmark.py)) это объявляет. Поведение следует из
правила, а не является сбоем.

Места вызова: `iter_md` используют `index` ([#L411](../../skills/kb-search/gitmark.py)),
`lint` ([#L914](../../skills/kb-search/gitmark.py)) и `map`
([#L993](../../skills/kb-search/gitmark.py)); `stat` читает `.gitmark/index.db`
([#L543](../../skills/kb-search/gitmark.py)) — значит фильтр обязан действовать и
при сборке индекса, иначе `search`/`stat` разойдутся с `lint`. `json` уже в
импортах движка ([#L23](../../skills/kb-search/gitmark.py)), `tomllib` — нет.

Контракт сужения путей несёт страж `tests/test_lint_paths.py`
(`test_selection_narrows_only_per_file_checks`) и докстринги `cmd_lint` и
`_lint_global` в движке; в тексте [core-kb.md#готово-3](core-kb.md) этой нормы
нет — названный пробел: durable-текст контракта в KB отсутствует, носитель —
тест. Выход `lint` — `✓ чисто`/счётчики, `1` при ERR под
`--strict`, `2` — отказ использования; у `lint` нет `--json`
([#L1090-L1091](../../skills/kb-search/gitmark.py)). Собственный `lint --strict`
этого репозитория чист (exit 0, 106 файлов на перездмере 2026-11-10).

Практика релиза — bump с тегом и rollout в consumer-registry
([continue.md:515](../ops/continue.md)); в этом юните — вне объёма (решение 15).
