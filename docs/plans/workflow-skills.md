# workflow-skills — фазы метода как скиллы

**Состояние (2026-10-21): утверждена на план-гейте.** Оператор подтвердил опросом
все четыре решения ниже; альтернативы не выбраны. Тикетов нет — нарезает
`to-tickets` по вызову оператора; исполнение идёт по одному тикету за прогон.

## Цель

Метод получает свои фазы как исполняемые скиллы: `grilling`, `to-tickets`, `ship`,
`testing` — четыре `SKILL.md` в стиле ядра, каждый с контрактным тестом. После юнита
новый оператор ведёт изменение от интервью до коммита носителями, которые хост
загружает, а не по пересказу канона.

## Решения план-гейта

| решение | умолчание в черновике | альтернатива |
|---|---|---|
| состав юнита | все четыре скилла | только `grilling`; или `grilling` + `to-tickets` |
| установка | `install.sh` ставит семь скиллов | workflow-скиллы остаются в этом репозитории |
| готовность | сквозное демо отдельным тикетом | без демо — скиллы и контрактные тесты |
| автономный флаг `grilling` | вне рамок v1 | явный флаг в первой версии |

## Факты

Проверено по канону, источникам и прецеденту ядра; каждое утверждение имеет путь,
а не догадку.

- **grilling** (Pocock, sources.md §2): предмет раскладывается в дерево дизайна;
  каждый раунд спрашивает весь фронтир, нумерует вопросы и даёт к каждому
  рекомендованный ответ. «Факты — работа агента; решения — пользователя»; агент,
  отвечающий за оператора, ломает скилл. Готово, когда фронтир пуст и оператор
  подтвердил общее понимание. Выход — спека `docs/plans/<slug>.md` на план-гейт.
- **to-tickets** (Pocock, sources.md §2): tracer-bullet вертикальные срезы, у
  каждого демо-путь и блокирующие рёбра; квиз перед публикацией; критерии приёмки
  падают на базовом коммите; никаких якорей `file:line`. Маркер
  `disable-model-invocation: true` — агент никогда не вызывает его сам. Тикеты
  эфемерны: `.scratch/<slug>/issues/` или реальный трекер; в этом репозитории —
  `tickets/` (прецедент двух юнитов).
- **ship** (OntoShip dev-flow, sources.md §1): один проход worktree → реализация →
  доказательные тесты → один прогон ревью → проверки dev/prod → merge. Точки
  остановки берутся из «Ограничений» спеки; ревью даёт зацепки, а не цикл
  сходимости.
- **testing** (стратегия оператора + ESEM 2026, testing.md): три класса — spec,
  инвариант, target; каналы — инструменты, а не цели; ожидаемое значение берётся из
  независимого источника; планка target-теста (реальный путь, red→green,
  стабильность, читаемость, ревью) и агентный цикл из семи шагов.
- **Канон о вызовах** (ontoship-core.md, «Три фазы»): `grilling` вызывает модель;
  `to-tickets` и `ship` вызывает пользователь; скилл, вызванный пользователем,
  никогда не вызывает другой пользовательский скилл.
- **Прецедент ядра:** скилл — `skills/<name>/SKILL.md` на русском с машинными
  литералами на английском плюс контрактный тест `tests/test_skill_*.py`; установка
  — симлинки `scripts/install.sh` в `<project>/.agents/skills` (harness-agnostic).
- **Границы окружения:** remote и CI нет (`git remote -v` пуст) — путь PR в демо не
  проверяется и фиксируется как пробел, не имитируется.

## Готово

1. `skills/grilling/SKILL.md`: раунды по фронтиру, нумерованные вопросы с
   рекомендованным ответом, разделение фактов и решений, выход в спеку и остановка
   на план-гейте; автономный режим назван как вне рамок v1.
2. `skills/to-tickets/SKILL.md`: tracer-bullet, демо-путь, блокирующие рёбра, квиз,
   критерии, падающие на базовом коммите, запрет якорей `file:line`; маркер
   `disable-model-invocation: true`.
3. `skills/ship/SKILL.md`: один проход от worktree до merge; точки остановки из
   «Ограничений» спеки; ревью даёт зацепки; без remote — честная деградация до
   локального коммита с названным пробелом.
4. `skills/testing/SKILL.md`: три класса тестов, правило независимого ожидаемого
   значения, планка и агентный цикл target-теста, метрики покрытия пунктов спеки,
   инвариантов и исправленных дефектов.
5. `scripts/install.sh` и `tests/test_install.py`: семь скиллов в
   `<project>/.agents/skills` — три ядра и четыре workflow; `--check` называет
   каждый; идемпотентность, режим `--copy` и запрет глобальных корней сохраняются.
6. Контрактные тесты `tests/test_skill_{grilling,to_tickets,ship,testing}.py` —
   текстовые контракты как в ядре: маркер запрета вызова у to-tickets, отсутствие
   якорей `file:line` во всех четырёх, разделение фактов и решений у grilling,
   точки остановки из спеки у ship, три класса у testing.
7. Догфуд-тикет: сквозной прогон на игрушечной спеке — grilling → to-tickets →
   ship до коммита; отчёт прогона лежит в трекере; PR-путь назван пробелом.
8. Документация: индексы планов, runbook и `tickets/README.md` отражают юнит;
   `index`, `lint --strict` и `map` чистые после правок.

## Рамки

- `skills/{grilling,to-tickets,ship,testing}/SKILL.md`, их контрактные тесты.
- `scripts/install.sh`, `tests/test_install.py` — расширение канала установки.
- `docs/plans/README.md`, `docs/README.md`, `docs/ops/continue.md`,
  `tickets/README.md` — состояние и индексы.
- Скиллы ядра `kb-search`, `kb-curate`, `init` не меняются; управляемый блок
  `AGENTS.md` остаётся про KB-ядро.

## Ограничения

- Никаких реестров, provenance, аккордов приёмки и автоматической цепочки
  grilling → to-tickets — это строгий профиль, не ядро (канон).
- `to-tickets` и `ship` недоступны модели; `grilling` и `testing` модельные —
  агент применяет их сам; скиллы не вызывают других пользовательских скиллов.
- Скиллы — проза на русском; машинные литералы — на английском. Движок
  `gitmark.py` не расширяется; тесты — stdlib + pytest.
- `vendor/` не трогаем; канон, тест-стратегия и онтология не переоткрываются.

## Контекст

README называет четыре скилла с первого дня, но исполнять их нечем: канон описывает
фазы прозой. Первый юнит собрал субстрат (KB), второй сделал его переносимым; этот
юнит переносит сам продукт — workflow. Без него передача упирается в пересказ:
новый оператор читает канон, но не получает носителей, и каждый гейт остаётся
ручным соглашением вместо загружаемой инструкции.

## Тикеты

После план-гейта: **01 grilling → 02 to-tickets → 03 ship → 04 testing →
05 install → 06 dogfood.** Тикеты 02–04 независимы после утверждения спеки; 05
меняет канал установки; 06 заблокирован всеми. Решение о нарезке агент принимает
сам, оценив сложность плана, и выносит ask-инструментом, ровно один вопрос на
тикет: выдержка про тикет и варианты действий (канон, «Три фазы»).
