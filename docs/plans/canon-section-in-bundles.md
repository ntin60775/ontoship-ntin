# Секция канона «Три фазы» в бандлах

## Цель

Потребитель после установки может прочитать методные основы, на которые
скиллы ссылаются в шапках и телах: секция канона «Три фазы» едёт в
бандле `ship`, ссылки скиллов на канон указывают на файлы бандлов.
Канон `docs/decisions/ontoship-core.md` в ntin остаётся единым
источником и не худеет. Названный пробел поставки — п. 7 «Что осталось»
continue.md, условие возврата наступило (проба erp-demo 2026-11-04:
пять упоминаний канона висят) — закрывается этим юнитом.

## Готово

1. В бандле `ship` появился `references/method-phases.md` — секция
   «Три фазы» канона (строки 60–101), переписанная стоять
   самостоятельно и без фактов ntin-репо; владелец — ship (решение
   оператора 2026-11-04). Доказательство: якорный тест паритета
   «канон ↔ секция» в `tests/test_bundle_references.py` —
   формулировки-якоря живут в обоих носителях, replace-мутации
   (удаление якоря в любом носителе) краснят.
2. Шесть носителей-упоминаний канона переписаны с пути канона на
   файлы бандлов: шапки `critic`, `grilling`, `ship`, `to-tickets` →
   `../ship/references/method-phases.md`; шапка `testing` → свой
   `references/quality-rule.md` (канон-часть предложения переписана,
   бандл-файл уже несёт якоря правила); тело `to-tickets:69`
   («канон, „Три фазы“») → кросс-ссылка на `method-phases.md`.
   Доказательство: тест ссылок по образцу юнита `bundle-references` —
   по всем ссылкам на `method-phases.md` и `quality-rule.md` в
   поставляемых скиллах файлы существуют на диске после установки
   обоими каналами (link и copy).
3. Guard-фраза на имя `method-phases.md` в каждом ссылающемся скилле:
   файл бандла — первоисточник, проект переопределяет его документом
   `docs/reference/method-phases.md`. Доказательство: расширение
   guard-набора якорей `test_bundle_references.py` с мутациями
   (запрещённые формулировки, императив полной фразой, порядок шагов
   индексами) — продолжение решения оператора 2026-11-03 (guard-фраза
   в каждом ссылающемся скилле).
4. Релиз v0.5.0: bump версии плагина в `.zcode-plugin/plugin.json`,
   тег на origin, перепин каталога маркета. Доказательство:
   `ls-remote` тега, пин в `marketplace.json`, install по пину в
   чистый каталог — `references/method-phases.md` на месте в бандле
   ship.
5. Приёмка потребителя: update erp-demo раннером v0.4.0 → v0.5.0 и
   проба путей по всем скиллам установленного erp-demo — категория
   канон-упоминаний пуста (ни один скилл не указывает на
   `docs/decisions/…`), висящих ссылок на справочники нет; акт
   rollout `v0.4.0 → v0.5.0` записан в consumer-registry. Доказательство:
   `.zcode/deployed.json` erp-demo с пином v0.5.0, вывод
   пробы, запись реестра с датой. Живой панельный прогон в приёмку
   не входит: механизм панели доказан живым прогоном `dwfrun-8cdf4fa8`
   (2026-11-04) и не меняется этим юнитом.

## Рамки

- KB ntin не худеет: канон остаётся целым, секция — производный
  носитель; связь секции с каноном сторожит якорный тест, не ручная
  синхронизация.
- Владелец секции — ship (решение оператора 2026-11-04, ask по оценке
  путей «секции/полная копия»); `grilling`, `to-tickets`, `critic`
  ссылаются кросс-ссылкой `../ship/references/method-phases.md`.
- Имя `method-phases.md` — по смыслу, не по имени канонного раздела
  (прецедент раскладки владельцев юнита `bundle-references`).
- Полная копия канона не заводится: правило качества уже несёт
  `quality-rule.md` — копия создала бы второй носитель одного правила
  в поставке и вечный паритет при правках канона (оценка путей
  2026-11-04, выбор оператора — путь «секции»).
- Механика поставки не меняется: бандлы копируются целиком обоими
  каналами, workflow и deploy.json не трогаются.
- Приёмка их тикетов erp-demo (05–07) — обычным порядком их юнита;
  update парка (erp-mini, project-bp, маркет) — по их потоку, после
  релиза.

## Ограничения

- Одно правило — один полный текст на носитель; якорные
  replace-мутации пишутся по точным фрагментам носителя (уроки юнитов
  onto-doc 02 и bundle-references 01–02: регистр, переносы, якорь на
  каждое смысловое упоминание).
- Текст секции «Три фазы» канона этим юнитом не редактируется:
  секция — производная; если паритет потребует правки канона — точка
  остановки, решение оператора.
- Управляемый блок init не расширяется: вход в метод доставлен v0.3.0.
- Guard-фраза не подменяет поиск проекта: если проект написал свой
  `docs/reference/method-phases.md`, скилл берёт его; бандл — источник
  по умолчанию.

## Контекст

- Пробел: п. 7 «Что осталось» continue.md (юнит `bundle-references`
  сознательно вывел канон за рамки, спека «Рамки»); вскрыт онто-доком
  erp-demo 2026-11-03; проба путей 2026-11-04 — пять скиллов с
  канон-упоминаниями (`critic`, `grilling`, `ship`, `testing`,
  `to-tickets`), все висят; носителей-упоминаний шесть — у
  `to-tickets` шапка и тело (строка 69). Ссылки контекстные, не
  императивные: живой старт панели erp-demo по процедуре из бандла
  (`dwfrun-8cdf4fa8`) канон не задел — пробел умеренный, но носитель
  обещает чтение, которого у потребителя нет.
- Механизм — прецедент юнита `bundle-references` (v0.4.0): один
  бандл-владелец с кросс-ссылками, guard-фраза, якорные наборы
  паритета с мутациями, тест ссылок обоих каналов; решения
  оператора 2026-11-03 «метод-секции (не полные копии)» и guard
  распространяются на новый файл.
- Решения оператора 2026-11-04 (ask после оценки путей): носитель —
  методные секции, не полная копия (аргументы: дубль правила
  качества в поставке, вечный паритет копии, отмена прецедента
  2026-11-03); владелец — ship; объём — с релизом v0.5.0 и приёмкой
  потребителя без панельного прогона.
- Цепочка после план-гейта: нарезка → тикеты → критик → тикет-релиз
  (тег, пин) → update erp-demo и живая проба → приёмка.
