# 04: вендор-README и индексы — честная строка источника

**Спека:** [docs/plans/onto-doc.md](../../docs/plans/onto-doc.md)

**Что построить:** `vendor/ontoship-zcode/README.md` — строка
«Not copied: … workflows, plans …» переформулирована по решению 11 с
оговоркой: док-часть строится из оригинала юнитом `onto-doc`; workflow
док-части живёт в `.zcode/workflows/` этого репозитория; прочая зависимость
от `.zcode` и рантайма агента не вендорится; остальные пункты списка не
тронуты. Индексы и runbook — без противоречий со статусом спеки: строки
`docs/plans/README.md` и `docs/ops/continue.md` не зовут утверждённую спеку
draft (пункт «Готово» 5).

**Дополнено решениями оператора 2026-10-30 (зацепки тикета 02):**

- Корневой `README.md`: счётчик тестов из абзаца «Состояние» убрать —
  счётчики тестов в README не ведутся вовсе (числа живут в runbook и
  закрытых тикетах); соседние устаревшие числа абзаца снимаются той же
  правкой, раздел остаётся снимком без проверяемых счётчиков.
- Связь скиллов из индексов — исследование и решение оператора ДО правки:
  девять бандлов установщика не названы ни одним индексом (`skills/` без
  README, «Раскладка» `AGENTS.md` называет три ядровых, управляемый блок —
  домен init). Варианты — `skills/README.md` с перечнем девяти, строка
  «Раскладки» под фактический состав установщика, строка управляемого блока;
  исследовать цену каждого (кто сопровождает, что ломается при появлении
  десятого скилла, конфликт с каноном «README каждой папки — её индекс»),
  вынести ask-ом с рекомендацией, внести решение в этот тикет и исполнить
  здесь же.

**Решение оператора по связи скиллов (ask 2026-11-01):** вариант
`skills/README.md` — рекомендация исполнителя принята. Варианты и цена:
(а) `skills/README.md` с перечнем девяти — канон «README каждой папки — её
индекс» выполнен для `skills/` (папка была без индекса; инвариант I5
требует индексы только под `docs/`, поэтому lint молчал); цена — перечень
в README становится второй ручной копией состава рядом с `SKILLS`
установщика (перечни живут ещё в usage и в кортеже `test_install.py`),
держится одним коммитом, `AGENTS.md` не растёт; десятый скилл — бандл в
`install.sh` плюс строка в README; (б) перечень прямо в «Раскладке»
`AGENTS.md` — `skills/` остаётся без README, канон не выполнен, тот же
второй реестр плюс загрузка в каждую сессию; (в) строка в управляемом
блоке — блок переписывается init-ом при следующем бутстрапе, строка
потеряется. Проверено перед ask-ом: тестов-якорей на «Раскладку»,
счётчики README и `skills/README` в `tests/` нет.
