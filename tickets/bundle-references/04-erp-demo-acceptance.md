# 04: приёмка в erp-demo

**Спека:** [docs/plans/bundle-references.md](../../docs/plans/bundle-references.md)

**Что построить:** `update` раннером в erp-demo
(`/home/prog7/home/dev/work/erp-demo`) с пина `v0.3.0` на `v0.4.0`;
живой панельный прогон на ближайшем готовом тикете bus-mapping-module
(05) — двойная роль: приёмка юнита и приёмка их тикета 05 (их тикеты
06–07 идут обычным порядком); запись акта rollout в consumer-registry;
проба путей после update — ни одна ссылка скиллов не висит.

**Блокируется:** 03; готовый к ревью-панели тикет erp-demo.

**Демо-путь:** панель в erp-demo стартует по процедуре из бандла.

**Критерии приёмки**:

- [ ] update — артефакт: `.zcode/deployed.json` erp-demo; ожидание:
      пин `v0.4.0`, файлы `references/` в `.agents/skills/*/`
      (спека, «Готово» 7)
- [ ] живой прогон — артефакт: журнал/карточка прогона панели; ожидание:
      роли на моделях конфига erp-demo, запуск по процедуре из бандла,
      карточка сверена с фактом до отчёта оператору (спека, «Готово» 7)
- [ ] ссылки — артефакт: проба путей по всем ссылкам скиллов на
      справочники в установленном erp-demo; ожидание: пустой вывод
      висящих (спека, «Готово» 7)
- [ ] реестр потребителей — артефакт: запись consumer-registry; ожидание:
      акт rollout `v0.3.0 → v0.4.0` в erp-demo назван с датой
      (спека, «Готово» 7)
