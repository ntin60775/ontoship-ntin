# 02: паритет, каналы, канон

**Спека:** [docs/plans/bundle-references.md](../../docs/plans/bundle-references.md)

**Что построить:** якорный тест паритета методных секций KB-док ↔ бандлов
(по образцу `tests/test_canon_sync.py` — бандл-файл встаёт в его набор
носителей; replace-мутации чувствительны к регистру и переносам);
расширение `tests/test_install.py` — `references/` доезжают установщиком
(канал `install.sh`; канал раннера доказывает критерий «чистая
установка» тикета 03); паритет правил панели между `skills/ship/SKILL.md`
и его `references/review-panel.md` (пропуск роли без секции, фолбэк
недоступной модели) — якорем в том же тесте; фраза-граница в
`docs/decisions/ontoship-core.md` — методное знание скиллов возится в их
бандлах, KB проекта — проектное знание; пометки в трёх KB-доках о носителе
методной секции в бандле; индексы README, `gitmark lint --strict` чистый.

**Блокируется:** 01.

**Демо-путь:** одиночная правка одного носителя роняет pytest
паритет-теста (красный прогон в выводе); `install.sh` переносит
`references/` в чистый проект.

**Критерии приёмки**:

- [ ] паритет — артефакт: мутационные пробы якорного теста (правка секции
      в KB-доке без бандла и наоборот); ожидание: обе красные на дереве
      тикета, бандл-файл — в наборе носителей теста (спека, «Готово» 3)
- [ ] каналы — артефакт: `ls references/` после `install.sh` в
      temp-каталог; ожидание: файлы на месте; канал раннера доказывает
      тикет 03 (спека, «Готово» 4)
- [ ] канон — артефакт: фраза в `ontoship-core.md` и список правленых
      файлов коммита; ожидание: пересказы правила, если называются,
      правятся в том же коммите (спека, «Готово» 5)
- [ ] KB — артефакт: `gitmark index && lint --strict`; ожидание: чисто —
      инвариантный охранник (зелёный и на базовом коммите), не
      доказательство тикета (спека, «Ограничения»)

## Доказательства

Исполнение — worktree `ontoship-ntin-wt-brf02` (ветка
`brf-02-parity-channels-canon`) от базового коммита `88a6219`; реализация —
коммит `9dd29db` (тесты, канон, пометки — одним коммитом).

- Критерий 1 (паритет): якорный тест `tests/test_canon_sync.py` —
  бандл `skills/testing/references/quality-rule.md` встал в носители правила
  качества рядом с каноном, скиллом testing и `docs/reference/testing.md`
  (пять якорей во всех четырёх); правила панели — пара носителей
  `skills/ship/SKILL.md` ↔ `skills/ship/references/review-panel.md`
  с четырьмя якорями: «без секции в конфиге не запускается»,
  «молчаливая подмена не делается» (пропуск роли), «модель сессии
  с пометкой в отчёте», «ревью провёл исполнитель» законным исходом
  не является (фолбэк). Пометки носителя — `test_kb_page_names_its_bundle_carrier`:
  `testing.md` → `quality-rule.md`, `harnesses.md` → `review-panel.md`
  и `ontodoc-run.md`, `review-roles.md` → `review-panel.md`. Мутационные
  пробы на дереве тикета (замена, убирающая якорь, прогон, откат) —
  каждая краснит ровно один якорный кейс, остальные 19 зелёные:
  `testing.md` без бандла → failed `red→green`; `quality-rule.md` без KB →
  failed `red→green`; ship SKILL без бандла → failed `молчаливая подмена`;
  `review-panel.md` без ship → failed `модель сессии с пометкой`.
  Долговременная can-fail проба `test_parity_mutations_can_fail` — на
  затравках-носителях (обе стороны правила качества, оба направления пары
  панели, срыв пометки); живая мутация носителя краснит только якорный
  кейс, не пробу. Красная проба на базовом коммите: worktree от `88a6219`
  только с тестом — **4 failed / 16 passed**, падают четыре
  naming-кейса пометок (контента на базе нет), якорные паритеты зелёные.
- Критерий 2 (каналы): `tests/test_install.py::test_install_carries_bundle_references`
  — link-режим (файлы читаются сквозь symlink в бандл репо) и `--copy`
  (файлы в отвязанной копии), drift-проба: удаление
  `references/review-panel.md` из копии → `--check` exit 1, строка
  `drift: ship:`. Демо-путь: `scripts/install.sh --copy` в чистый каталог
  `/tmp/brf02-demo.Eeb3` — `ls references/` трёх бандлов показывает по
  файлу (`review-panel.md`, `ontodoc-run.md`, `quality-rule.md`),
  `--check` → `check: ok`; link-режим в `/tmp/brf02-link.rAwM` — чтение
  заголовков сквозь symlink, `check: ok`. Канал раннера — критерий
  «чистая установка» тикета 03 (так названо в критерии приёмки).
- Критерий 3 (канон): фраза-граница в `docs/decisions/ontoship-core.md`
  после перечня «Три артефакта»: «Методное знание скиллов возится в их
  бандлах (`references/`); KB проекта — проектное знание. Файл бандла —
  первоисточник методной секции; проект переопределяет его документом
  `docs/reference/<имя файла бандла>`.» Правленые файлы коммита `9dd29db`:
  канон, три KB-дока (`testing.md`, `harnesses.md`, `review-roles.md`),
  два теста. Пересказов границы вне канона нет — носитель один; guard-фразы
  скиллов (тикет 01) говорят перекрытие per-file и с границей не спорят.
- Критерий 4 (KB): инвариантный охранник — `gitmark index` (88 файлов ·
  408 чанков · 225 ссылок) и `lint --strict` чист на дереве тикета;
  на базовом коммите `88a6219` lint --strict тоже чист (зелёный и на базе,
  доказательства тикета не несёт). Новых документов нет — индексы README
  не менялись; `lint --strict` подтверждает связность ссылок пометок
  (`../../skills/<бандл>/references/<файл>` резолвятся).
- Полный набор: **417 passed = 404 + 13** (canon_sync 8 → 20 кейсов,
  install +1); `lint --strict` чист.
- Разбор расхождений ожидание/факт: (1) первые пробы 1–2 шли циклом
  с заменой «Red→green»→«red→green» — якорь выживал заменой в другой
  регистровой форме, тест оставался зелёным; дефект пробы, не теста —
  перепроведены заменой обеих форм на «цветовая проба» (в носителях
  якорь живёт в двух регистровых формах: «**Red→green.**» планки и
  строчная в метриках); (2) проба review-panel сначала целилась во
  фрагмент с переносом «модель⏎сессии…» — в этом носителе фраза не
  перенесена (перенос живёт в ship SKILL), no-op отсечён assert-ом
  пробы; перепроведена по точному фрагменту файла; (3) первая версия
  can-fail читала живые носители и при живой мутации краснела вторым,
  шумным отказом (precondition «mutation must remove the anchor»);
  развязана на затравки — при живой мутации краснеет только якорный
  кейс паритет-теста. Остальных расхождений не было.
