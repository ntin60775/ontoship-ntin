# Тикет 03 — Живая проба маршрутизации и протокола

Блокируется: 01, 02
Блокирует: 04

Спека: [deliver.md](../../docs/plans/deliver.md), «Готово» 3, 4, 6,
«Протокол deliver», «Контракт акта», решения 6–7. База нарезки:
`40c0dc6` (ядро), `v0.2.0` (реестр). Один прогон, без двойной цены:
ноги протокола (Готово 3) доказываются прогонами маршрутизации
(Готово 4).

## Задумка

Изолированный хост (копия профиля web без team/stack-строк, свой порт,
живой GUI не перезапускается) доказывает: свежие сессии без контекста
планирования маршрутизируют парафразы интента поставки в скилл deliver
и исполняют протокол до `check: ok` в отдельном потребителе X;
присутствие реестра даёт акт rollout, отсутствие — названный пробел;
контрольный контур без блока входа доказывает чистый description-маршрут.

## Демо-путь

Таблица «парафраз → session id → вызов skill deliver первым ходом →
check: ok в X» на пять сессий; выписка акта rollout из
`.agents/registry.local.json` presence-продюсера, прочитанная против
ожиданий; фраза названного пробела в транскрипте absence-сессии;
запись уборки «остатков 0». Красное на базе: скилла deliver в каталоге
нет — парафраз не маршрутизируется.

## Участники и setup (до сессий)

- Источник канала: worktree среза ядра на зафиксированном sha (после
  merge тикетов 01/02 — main-чекаут на названном sha); sha и путь —
  в install-логе. Поколение фиксировано; правка дерева во время пробы
  делает пробу недействительной.
- Продюсеры P1 (K1), P2 (K2), P3 (K3) — temp-проекты под `/tmp` вне
  git-деревьев ядра, собственные git-репозитории с базовым коммитом.
  P1: ядро link + реестр link + init + старт ведения. P2: ядро link +
  реестр link + старт ведения, **без init** (блока нет). P3: ядро link
  + init, **без реестра**.
- Потребители X1–X5 — отдельные свежие temp-проекты, соседние чекауты
  продюсеров, находимые поиском по имени; git init + базовый коммит.
- Baseline обновлений: установка из дерева `v0.7.0` (временный чекаут
  тега), созданная драйвером до сессии: X2 — copy, X3 — link.
- Реестр в presence-продюсерах ставится из worktree/чекаута реестра
  после merge тикета 02 (поколение фиксировано sha).

прецеденты tp11/ctb04 (launch-token → connect → cookie →
session/create → prompt → wait; транскрипт из session-журнала).

## Критерии приёмки

1. Маршрутизация: первый ход ассистента каждой сессии после парафраза
   содержит вызов инструмента `skill` с `{"name":"deliver"}` (формат
   `TOOL skill` прецедента ctb04), затем шаги протокола. Литерал K1
   доказывает блок-маршрут; разнообразные парафразы K1 и парафраз K2
   (блока нет) — description-маршрут. Артефакт: транскрипты пяти
   сессий с таймстемпами, таблица маршрутов. Ожидание: спека «Готово»
   4, триаж G-1–G-3, G-24. На базе падает: deliver в каталоге нет.
2. Удостоверение сессий: host URL/порт, session id, цепочка создания,
   preset/модель, cwd = продюсер; `pwd`, `git rev-parse --show-toplevel`,
   `readlink -f .agents/skills/deliver` для каждого продюсера; sha и
   путь link-дерева в install-логе. Артефакт: evidence-карточка
   сессий. Ожидание: спека «Готово» 4, триаж G-10–G-12. На базе
   падает: удостоверение не собирается (скилла нет).
3. Ноги протокола: свежая link (S1) и copy (S4) — `check: ok` в X;
   обновление link (S3) — baseline v0.7.0 → срез, `check: ok`, акт
   update; отказ drifted-копии (S2) — «copy differs» назван, протокол
   остановлен на ask, молчаливого обхода нет; идемпотентный init —
   повторный запуск diff пуст (temp-проекты с базовым коммитом);
   diff целевого проекта после поставки — только `.agents/` и файлы
   init, continue.md после init не изменён. Артефакт: логи установщика,
   транскрипты, diff. Ожидание: спека «Готово» 3, триаж G-9, G-22.
   На базе падает: протокол исполняет deliver, на базе его нет.
4. Presence-акт: акт прочитан против ожиданий — consumer X, action
   rollout/update, свежий `at`, result ok, X в `consumers` с версией
   источника (dev+sha дерева среза до тега), `updated_at` изменился;
   followup «свежая сессия потребителя» записан после обновления;
   валидатор зелёный — дополнение (пустой каркас тоже зелёный).
   Старт ведения при отсутствующем файле исполняется по правилам
   скилла (решение 7) — в setup или сессией, факт назван. Артефакт:
   выписка акта (diff/JSON) `.agents/registry.local.json`, прогон
   валидатора. Ожидание: спека «Готово» 6, «Контракт акта», триаж
   G-6, G-7, G-9. На базе падает: коннектора и реестра DSH нет.
5. Absence: файла реестра нет + фраза названного пробела в финальном
   отчёте сессии S5; fallback-записи нет. Артефакт: транскрипт S5,
   отсутствие файла. Ожидание: спека «Готово» 6, решение 2. На базе
   падает: deliver нет.
6. Ask-ноги (поиск X при ненахождении, удаление drifted-копии, смена
   канала, чекаут copy-продюсера) в пробе не исполняются — названы
   пробелами пробы в evidence. Артефакт: секция пробелов evidence.
   Ожидание: спека «Рамки», триаж G-1.
7. Уборка: хост остановлен (PID/порт), список целей (DSH_HOME-копия с
   credential, sessions, cookie/token-файлы, temp-проекты, baseline-
   чекаут), остатков 0, живой профиль/GUI не тронут; неудаляемый
   остаток — остановка/ask. Артефакт: запись уборки со списком целей
   и сканом остатков. Ожидание: спека «Готово» 4, триаж G-13.
8. Красная проба маршрутизации на базовом коммите `40c0dc6`: свежая
   сессия temp-проекта с ядром базы получает парафраз — вызова skill
   deliver нет (скилла в каталоге нет). Артефакт: красный транскрипт
   (одна сессия, контур базы). Ожидание: правило нарезки.

## Ограничения

- Живой GUI не перезапускается; проба — изолированный хост; credential
  вне контекста агента, уборка обязательна.
- Поколение link фиксировано; правка дерева во время пробы —
  недействительность и перезапуск.
- Панель тикета — по правилу ship; правки description после пробы
  требуют повторной пробы от тега или названного пробела (тикет 04).
- Бюджет пробы — страж: превышение ≤ 2.5M — остановка и вопрос
  оператору, не молчаливое продолжение.
