# Зацепки юнита deliver

Реестр зацепок (P3 и наблюдения сверх критериев). Каждая сессия дописывает
свою секцию; файл общий.

## Секция тикета 02 (реестр DSH-нативен, 2026-11-17)

- `.gitignore` репо consumer-registry не несёт `__pycache__/` и `*.pyc`:
  импорт валидатора создаёт bytecode в дереве и замусоривает git status
  (находка reviewer-tests, закрыта в тестах пропуском bytecode в скане
  check_4; гигиена репо — зацепка). Правка вне скоупа тикета 02
  (`.gitignore` — носитель локальных слоёв, решение оператора
  2026-11-02); кандидат — тикет 04 или отдельная малая правка.

## Тикет 01 (бандл deliver и строка входа)

- **Инвентарь корневого README.** `README.md` (раздел «Состояние»)
  перечисляет скиллы ядра без `deliver`; после среза инвентарь неполон.
  Носитель состава там уже назван (`scripts/install.sh`,
  `skills/README.md`), поэтому паритет имён это не ломает. Правка —
  в сводной записи сессии планирования или в тикете 04 (релизы и
  закрытие); в срез тикета 01 не входит — критерий 2 называет три
  носителя, расширение скоупа не делается. Источник: панель
  reviewer-kb, P3.

## Секция тикета 03 (живая проба, 2026-11-17)

- **Контракт акта: `from` без прежней записи.** Контракт определяет `from`
  как прежнее `consumers[].version`; случай «обновление проекта без прежней
  записи в реестре» не описан. S3 взяла `from` из факта прежних ссылок
  (тег baseline-дерева v0.7.0) и назвала отклонение явно. Формулировка на
  уточнение — кандидат тикет 04 или следующий юнит реестра.
- **Контракт акта: followup на свежем rollout.** «Пиши followup после
  обновления»: S1 на свежем rollout followup писал, S4 — не писал
  (буквальное чтение). Разночтение не нарушает критерий 4 (followup после
  обновления — S3 записан), формулировка на уточнение.
- **Гигиена драйвера пробы: credential вне дерева пробы.** host.log
  (launch-токен) и cookie-файлы лежали в /tmp/dlv03/work, видимом сессиям;
  красная сессия прочитала host.log (инцидент 3 тикета). Токен
  изолированного хоста инвалидируется уборкой, но правило драйверу:
  credential-носители — в каталог, недоступный сессиям пробы (или вне
  дерева, которое сессии исследуют).
- **Механика DSH: legacy-ask и API-ведение.** Профиль по умолчанию несёт
  `tool-ask-user` mode `legacy` (блокирующий ask без foreground-таймаута);
  unary `userQuestions/answer` отвечает только на continued-вопросы
  timed-режима. Ведение сессии без GUI требует WS-моста: `/api/remote.mux`
  (interactions=answer) → поток `$events` → forwarded waterfall →
  `POST /api/$events/result` {clientId, eventId, outcome}. Альтернатива —
  timed-режим в копии профиля пробы. Факт для будущих проб этой пробы: механика
  доказана, мост в evidence 03; пробел tp11 «ask_user_question живьём из
  API-сессии» — факт team-контура, его закрытие фиксирует team-runbook,
  не ядро.
- **Повторный init полной сессией** в пробе не делался (драйверский прогон
  по кейсам скилла + хэши сессий) — зацепка на будущую пробу, не дефект.

- **Ревьюеры стандартной раскладки совпадают с моделью сессий пробы.**
  Init в X-проектах пишет стандартную раскладку (ревьюеры flash-1017);
  сессии пробы шли на профильном дефолте flash-1017 — совпадение названо
  сессиями S4/S5. Норма независимости — норма реестра/панели (фолбэк при
  запуске), не init; на живом профиле оператора модель сессии иная.
  Зацепка: формулировка init о совпадении ревьюеров с моделью сессии —
  на уточнение, если оператор сочтёт нужным.
- **Init-исполнение сессиями: завершающие newline (рецидив подтверждён).**
  S4 записала файлы init без завершающего `\n`, S5 правила вручную,
  S4b (clean-контур) — AGENTS.md правила сама, .gitignore/continue.md
  снова без `\n`. Скилл и тесты ядра корректны (804 passed); дефект
  исполнения моделью: правило «не добавляй завершающий перевод строки,
  которого в файле не было» переносится на новые файлы. Зацепка: явная
  формулировка init «новый файл кончается переводом строки по шаблону» —
  кандидат следующего юнита ядра (правка скилла + пин теста).

- **Overlap блока и description deliver.** Литерал «деплой и обновление
  [имя_проекта]» несёт и description скилла, и строка блока init —
  парафраз-литерал не дискриминирует канал маршрутизации; блок-маршрут
  S1 доказан reasoning-трассой (cue AGENTS.md), не лексикой. Критерий 1
  тикета 03 формулировал «литерал блока доказывает блок-маршрут» —
  уточнено панелью. Зацепка: формулировка критерия будущих проб и дизайн
  блока (блок-строка семантически покрыта description; самостоятельная
  ценность блока — discoverability точки входа, не уникальный маршрут).
