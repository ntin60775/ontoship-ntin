# Реестр зацепок юнита team-profiles

P3-находки ревью-панелей и проходов; автоприёмку не блокируют.
Закрытые зацепки остаются в реестре с пометкой носителя.

## Открытые

- **Видимость прогресса субагента** (точка самоконтроля оператора
  2026-11-13): todo субагента оператору в GUI не виден, исполнители
  забывают его обновлять — наглядность прогресса почти нулевая.
  **Решение оператора 2026-11-13: опрос исполнителя каждые 5 минут по
  таймеру оркестратора** (статус-запрос, сверка артефактов, todo,
  корректировка); таймер заведён, норма записана в continue.md.
  **Тикет 10 принят оператором ask 2026-11-13: норма опроса ложится в
  скилл chain с контрактными тестами (блокер 04, блокирует 07);
  имплементация — тикет 10, до него зацепка открыта.**
  Дополнение: прогресс-сообщения на границах шагов ship. Кандидаты
  системного решения: норма отчётности в chain, живая активность на
  доске — юнит `chain-live-activity`, отображение todo субагентов в
  GUI DSH — внешний пробел. Место: бандл chain, спека
  chain-live-activity, DSH. Предложения оркестратора
  2026-11-13: (а) дисциплина todo в самом скилле ship («веди todo шагов
  прохода, обновляй на каждой границе») — тогда каждый исполнитель
  получает её из ship, а не из напоминания handoff; (б) норма chain —
  прогресс-сообщение оркестратору на каждой границе шага ship,
  оркестратор зеркалит в свой todo; (в) прогресс-файл
  `tickets/<slug>/<NN>-progress.md` — чек-лист шагов, переживает смерть
  сессии; (г) системный носитель — chain-live-activity: доска показывает
  текущий шаг ship активного тикета, не только plan-статусы.
- **Личные имена агентов — уточнение оператора 2026-11-13** (запрос
  «псевдореальные имена, уникальные в рамках юнита» уточнён в цепочке):
  семантические имена (executor-2, «Архитектор») не годятся — оператор
  ведёт три проекта одновременно, ролевые ярлыки сливаются; нужно
  личное псевдореальное имя, которое агент ОСОЗНАЁТ (инъекция в
  контекст), и для корневых сессий тоже. Реестр уникальности оператор
  решил не делать — seed-генерация, пересечения маловероятны. Факты
  DSH (сверено оркестратором по исходникам 0.2.2-rc.2):
  `systemPrompt.section()/context()/variable(name, provider)` —
  скоупированные секции и переменные системного промпта на агента
  (packages/core/system-prompt), персона интерполирует `{{…}}` строго
  по зарегистрированным переменным (packages/preset/persona);
  subagent сам инжектит per-child секции (child-agent.ts); событие
  `agent/created` несёт agent, есть creation-time композиция скоупа.
  Имя в контексте с первого хода — точнее, чем «после первого
  сообщения». Имя дерева (`name` спавна) фиксируется при создании —
  механизм передачи сгенерированного имени спавну требует разведки.
  **Тикет 09 принят оператором ask 2026-11-13, ревизия спеки внесена
  (решение 18); имплементация — тикет 09, до него зацепка открыта.**
  Место: спека team-profiles («Готово» 1), team-бандл (плагин
  авто-имени), тикет 09.
