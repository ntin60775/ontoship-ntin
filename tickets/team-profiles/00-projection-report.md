# 00 — Гейт проекций: team-profiles

Запись гейта проекций юнита `team-profiles`. Прогон состоялся 2026-11-13,
спека `docs/plans/team-profiles.md` (draft). **Отклонение от порядка:**
проекции выполнены ДО план-гейта по прямой команде оператора
(«проверь спеку по ортогональным семантическим проекциям перед
утверждением»); обычно проекции идут после план-гейта. Один прогон на
юнит; повторных прогонов нет.

## Срезы

Семя — чек-лист критика и восемь проекций (покрытие, порядок,
доказательства, власть, время, окружение, термины, риск); срезы
динамические, по предмету спеки. Все четыре стартовали в одном
сообщении, `subagent` (spawn). Вход артефактный: спека и названные
документы/исходники, не ход исполнения.

| срез | проекция | маршрут | уровень | причина выбора |
|---|---|---|---|---|
| `proj-coverage-authority` | покрытие + власть | `qwen-token-plan/qwen3.8-flash` | `xhigh` | широкое кросс-чтение спеки, канона, чужих носителей; структурная сверка решений с «Готово» |
| `proj-proof-order` | доказательства + порядок | `deepseek-account/deepseek-flash` | `max` | глубокое рассуждение о доказуемости критериев и графе зависимостей |
| `proj-environment-time` | окружение + время | `deepseek-account/deepseek-flash` | `max` | сверка утверждений с исходниками DSH и временные ловушки |
| `proj-terms-risk` | термины + риск | `qwen-token-plan/qwen3.8-flash` | `xhigh` | терминологическая консистентность и риски с носителями |

Модель сессии — `qwen-token-plan-max/qwen4-max-preview`; все маршруты
пула отличны от сессионной, независимость соблюдена. Маршруты и уровни
сверены с живым `list_subagent_models` до запуска. Идентификаторы
подчинённых сессий — имена срезов выше (DSH spawn).

Сырых находок: 53 (12 + 8 + 18 + 15). После дедупликации между
проекциями — 25: **9 P1 / 12 P2 / 4 P3**.

## Триаж

Вердикт основной сессии: подтверждена / отвергнута, причина. Ключевые
факты перепроверены по исходникам и репо (отмечено «сверено»).

### P1 — блокеры, править до гейта

**1. Ask у архитектора.** Подтверждена (3 среза). Решение 8 «ask только
у оркестратора» лишает архитектора план-гейта, приёмки нарезки и
финишной приёмки — канон вешает их на сессию планирования. «Готово» 7
неисполнимо. Правка: ask у корневых ролей (architect, orchestrator); у
spawn-детей (executor, scout) — нет. Это уточнение области решения 8,
не пересмотр: оператор в раунде 2 разделял «оркестратор/исполнитель»,
архитектор — корневая планирующая роль.

**2. Гранулярность выбора исполнителя.** Подтверждена (coverage).
«Выбор под задачу» + per-call противоречат решению 13 standards-autoship
и якорю канона/зеркала «одна продолжаемая сессия-исполнитель». Правка:
выбор пресета+маршрута — при спавне продолжаемой сессии и при
пенсии/handoff; внутри сессии тикеты исполнителя не меняют; per-call
остаётся только scout. Согласуется с словом оператора «оркестратор
выбирает исполнителя, когда стартанёт работу по задаче».

**3. Контракт `executors.json`.** Подтверждена (4 среза). Схема
`{id, model, level}` без `provider` — per-call маршрут неисполним
(`provider`+`model` передаются вместе, сверено по tool-subagent README).
`executors()` отдаёт только id для allowlist; потребитель `model/level`
не назван; двойной читатель без правила истины; носитель маршрутов
«конфиг пресетов» противоречит «пресет не несёт модель»; дом плагина не
назван. Правка: схема `{id, provider, model, level}`; единственный
читатель файла — плагин; механизм получения маршрутов оркестратором —
**спорное, вынесено оператору** (см. ниже); носитель — team-бандл.

**4. Правило выбора / сигнал стека.** Подтверждена (3 среза). Реестр
глобален, сигнала проекта нет; порядок концепта «манифест пака →
указатель спеки → дефолт» исчез. Манифест пака v1 не несёт
`roles.executor` (сверено по pack-contract.md: роли — только ревью
`{name, checklist}`, неизвестный ключ — отказ). Правка: сигнал стека —
указатель, который архитектор фиксирует в спеке/continue.md; оркестратор
читает указатель → id стека из реестра → иначе дефолт `executor`;
неоднозначность — остановка с вопросом; тест с двумя кандидатами.

**5. Доставка 1C привязана к id `1c`.** Подтверждена (proof-order;
**сверено по исходникам** 1C-DSH: `PRESET_ID = '1c'`,
`if (preset !== PRESET_ID) return` в `deliver`/`ensure`). Новые
`1c-architect`/`1c-orchestrator`/`1c-executor` не получат скиллы/MCP/гейты
контура — оболочки по коду. Затрагивает решение 7. **Спорное, вынесено
оператору**: менять фильтр доставки на набор id / оставить исполнителя
под `1c` / сузить состав ролей стека.

**6. Версия team-бандла и релиз.** Подтверждена (4 среза). Нет
пинованной версии team → паритет и проба не привязаны; нет пункта
«Готово» на репо/сборку/тег/пин/установку; проба ставит dev-копию, не
поставку (решение 13). Правка: пункт релиза (репо, сборка, тесты,
semver-тег, пин, установка из пина в temp-профиль + новая сессия); стек
фиксирует `teamVersion`; паритет — против пинованного снимка; один
именованный проход правок с bump и перерезкой копии после пробы.

**7. Протокол возврата 08.** Подтверждена (3 среза). Критерии 08 —
pack-поток (`--pack`, init с паком, базовые стандарты, гейты пака, панель
с ролью пака, `stop-probe`, закрывающий набор); «Готово» 7 не содержит ни
одного → 7 не доказывает «Готово» 12 standards-autoship. Владелец и
момент переписывания 08 не названы. **Спорное, вынесено оператору**:
переписать 08 под профильный поток (одна проба, pack-шаги — пробел/тикет)
или сохранить pack-поток 08 (две пробы, цена названа).

**8. Живая проба не falsifiable.** Подтверждена (proof-order + terms).
Нет «шаг → артефакт → ожидание», ids/коммитов/ask-записей/вердиктов
панели/отрицательных условий; «проба прошла» удовлетворяет; бюджет
«назван» — не критерий; профиль не изолирован (пресеты глобальны);
панель неоднозначна (ревью-панель vs доска); игрушечный тикет не
1C-специфичен. Правка: чек-лист шагов с путями/ids/хешами/логами;
тикет юнита + durable-отчёт; отрицательные условия (оператор не
читал/писал код, только три ручных гейта, циклов правок нет); бюджет —
ex-ante предел + измеренный факт + стоп по нормам chain; профиль назван
(temp `DSH_HOME`/копия или рабочий с before/after sha256); панель —
ревью-панель четырёх ролей из config.toml, один прогон; доска
опциональна; тикет с 1C-содержимым и ожидаемым контурным наблюдением.

**9. Порядок чтения `executors.json`.** Подтверждена (env-time;
сверено по loader/registry). Файл читается один раз при apply плагина;
HMR за ним не следит; новая сессия пресеты не перемонтирует. Поток
«бандлы → файл → сессия» даёт дефолтный allowlist. Правка: писать
`executors.json` ДО установки team-бандла (стек можно после: неизвестный
id допустим до вызова) либо явный reload профиля после записи до
открытия сессии оркестратора; проба проверяет `1c-executor` в enum до
прогона; формулировка «читается один раз при apply, список id заморожен».

### P2 — надо править

**10. Канал поставки (решение 13).** Подтверждена (3 среза). «Каталог
маркета как у ядра» ссылается на zcode-канал, снятый 2026-11-10; ядро
поставляется `install.sh` (проектные скиллы), корневого package.json нет
(сверено). team-бандл — DSH-бандл: `plugin_manager` (dev — `link:` из
клона; stable — registry/git-пин полным коммитом/запись DSH-индекса).
**Спорное, вынесено оператору**: конкретный DSH-канал и упаковка
(`dsh.bundle.patch`, `engines.dsh`, тег); работа по индексу/CI — контур.

**11. Метод-контракт и авторизация канона.** Подтверждена (3 среза).
Термин только в спеке; нет файла/ключа, эталонной версии, правила bump,
читателя; правка канона/зеркала в «Готово» 6 не уполномочена ни одним
решением (канон: правка сверх решений — точка остановки). **Спорное,
вынесено оператору**: носитель метод-контракта + правило bump + явное
решение о правке канона/зеркала (или снять их из «Готово» 6).

**12. Scout: родитель, allowlist, доказательство.** Подтверждена
(4 среза). Концепт — родитель исполнитель; решение 5 приписывает выбор
маршрута оркестратору; allowlist исполнителя не назван; панель наследует
пресет исполнителя; scout не в пробе. **Спорное, вынесено оператору**:
родитель scout (рекомендация — исполнитель) + чей allowlist + включить в
пробу или назвать пробел.

**13. Лимиты: семантика.** Подтверждена (env-time; сверено по
activation.ts). `maxActiveSubagents` — общая ёмкость под одним корнем на
всех уровнях; исполнитель занимает слот; сверх лимита — отказ, не
очередь; `maxDepth` к рассрочке отношения не имеет (0→1→2, запас до 3).
Правка: развести глубину и ёмкость; носитель рассрочки — исполнитель/ship;
сериализовать scout и панель или стартовать по свободным слотам; проба
проверяет панель ≤ лимита, прогон один.

**14. Дефолт `executor` не механизирован.** Подтверждена (env-time).
Без `agentPreset: executor` опущенный `agent_preset` наследует пресет
оркестратора; `[]`/дубли/отсутствие `executor` валят монтирование, а не
дают дефолт; опущенный маршрут наследует дорогую модель оркестратора.
Правка: `agentPreset: executor` (и `1c-executor` в стековой копии);
валидация+дедупликация файла, громкий лог + дефолт `["executor"]`;
контрактные тесты `[]`/дубли/без `executor`; назвать дефолт маршрута или
обязательные route-поля.

**15. Путь профиля для хост-плагина.** Подтверждена (proof-order;
**сверено** по profile-context.ts / shell-env README). `DSH_PROFILE_DIR`
— только модельным shell-вызовам; хост-плагин резолвит через
`ctx.get('profileContext').dir`. Правка: путь `<profile>/ontoship/executors.json`,
резолв через profileContext; тест с фейковым profileContext и отсутствующим
профилем; `DSH_PROFILE_DIR` — только в модельных/шелл-доках.

**16. Красная проба на базе — классификация.** Подтверждена
(proof-order). Новые поверхности (team-репо/плагин/пресеты) не имеют
базового поведения; red-on-base осмыслен только для якорей существующих
носителей и фильтра доставки 1C. Правка: по каждому пункту — существующий
носитель (base+число падений) / инвариант (дрейф) / новая поверхность
(composition/mount/live) / поведение (live/target с mismatch/двумя
кандидатами); назвать базы и команды.

**17. team-пресеты в пробе; «служебные помечены».** Подтверждена
(3 среза). «Готово» 7 открывает только `1c-*`; team-роли не исполняются;
«служебные помечены» без механизма (у DSH нет hidden-флага). Правка:
короткий smoke team-architect в 7 или отдельном тикете, либо
composition/mount + оговорка о косвенном доказательстве копией; задать
конвенцию служебных (id/description/order) + тест или снять.

**18. Полный набор / `install.sh --check`.** Подтверждена (proof-order).
`--check` проверяет проектные скиллы, не profile-бандлы; тесты team/1C
вне; «справочник ролей и реестра» без пути. Правка: per-repo команды и
ожидаемые выводы (core pytest, team build/vitest, 1C vitest+doctor,
gitmark lint, install.sh --check, проверка plugin_manager/патча профиля);
назвать reference-док; оговорить guard, не доказательство 1–7.

**19. Ревизия «Рамок» standards-autoship.** Подтверждена (2 среза).
Приписка к решению 2 не снимает строку «Рамок» «хостовый канал не
используется». Правка: одним изменением приписка + строка «Рамок»;
назвать источник ссылки init.

**20. Власть над 1C-DSH.** Подтверждена (coverage). Формулировка
допускает приёмку чужого мержа тикетом этого юнита; 1C-DSH требует свой
тикет/гейты. Правка: в 1C-DSH — свой тикет/спека/приёмка; тикет этого
юнита несёт адрес, ребро зависимости, ссылку на доказательство и ждёт
чужого мержа.

**21. Актор записи `executors.json`.** Подтверждена (coverage). Раннер —
другой юнит; кто пишет записи перед пробой — не назван. Правка: актор —
оператор вручную как шаг установки бандла; путь и содержимое фиксируются
в артефакте пробы; делегирование стеком/раннером — пробел контур-юнита.

### P3 — зацепки

**22. Носитель ссылки init.** Подтверждена (coverage). Правка: общий
reference в §5/отчёте init («роли команды — DSH-бандл пресетов уровня

**23. Терминология (пакет).** Подтверждена (terms + coverage + env-time).
«профили DSH — механизм ролей» в Цели → «пресеты»; маршруты без provider
→ полная форма `provider/model`+level; `agent-team`/`workflow` в «Рамках»

`agentOptions` — поле строки инструмента, не пресета → точная формулировка.

**24. Дублирующие доказательства.** Подтверждена (proof-order).

свести live-свидетельства в именованные сессии 7.

**25. Носитель записи заморозки 08.** Подтверждена частично (terms).
Запись заморозки существует (тикет 08, tickets/README, continue.md —
внесены 2026-11-13); в спеке носитель не назван. Правка: назвать носитель
и триггер разморозки (см. также находку 7 — протокол возврата).

## Спорное, вынесенное оператору

Решения план-гейта не перепрашиваются; ниже — находки, требующие
уточнения/дополнения решений или выбора механизма.Recommendation первая.

1. **Доставка 1C (находка 5, решение 7).** Фильтр по точному id `1c`.
   Варианты: (а) менять доставку 1C-DSH на набор id
   `1c-architect/1c-orchestrator/1c-executor` (работа в 1C-репо, юнит-тест);
   (б) исполнитель остаётся под пресетом `1c`, новые только
   `1c-architect`/`1c-orchestrator`; (в) сузить состав ролей стека.
2. **Канал поставки (находка 10, решение 13).** DSH-нативный канал:
   dev — `link:` из клона; stable — git-пин полным коммитом / registry /
   запись DSH-индекса; упаковка `dsh.bundle.patch`+`engines.dsh`+тег;
   индекс/CI — контур-юнит. Уточнить решение 13 (убрать «как у ядра»).
3. **Протокол 08 (находка 7, решение 1).** (а) переписать 08 под
   профильный поток, ссылка на durable-артефакты team-profiles, pack-шаги
   — названный пробел/новый тикет; (б) 08 сохраняет pack-поток, проба 7
   отдельная (две пробы, цена названа). Владелец — сессия планирования,
   триггер — после живой пробы, до финальной приёмки.
4. **Метод-контракт и канон (находка 11, решение 9).** Носитель
   (`methodContract` в манифесте team-бандла), эталон на стороне метода,
   правило bump, читатель через сервис плагина; явное решение о
   содержательной правке канона/зеркала (или снять из «Готово» 6).
5. **Механизм маршрутов (находка 3).** Как оркестратор получает
   `provider/model/level`: (а) читает `executors.json` инструментом read
   (правило истины: allowlist заморожен при apply, маршруты live,
   неизвестный id — отказ при вызове); (б) плагин отдаёт таблицу маршрутов
   в prompt-секцию оркестратора. Рекомендация — (а).
6. **Родитель scout (находка 12, решение 5).** (а) исполнитель спавнит
   scout, его allowlist+`modelSelection`, выбор маршрута исполнителем
