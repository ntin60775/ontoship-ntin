# 11: Разведка API-ведения сессий DSH

**Спека:** [team-profiles](../../docs/plans/team-profiles.md), «Готово» 11,
решение 20 (оператор 2026-11-15: сначала разведка, решение о переделке
потока — после, совместно с оператором).

**Блокируется:** 10 (нормы chain финализированы — разведка даёт основу
их возможной ревизии).

**Блокирует:** 07 (живая проба полного потока ждёт решения о потоке;
после разведки между 11 и 07 может быть вставлен тикет переделки —
решение оператора).

**Что построить:** ТОЛЬКО разведку и отчёт фактов. Никаких правок нормы
chain, контрактных тестов нового потока, ревизии «Рамок»/«Ограничений»
под сессионный поток — это предмет будущего тикета переделки, который
проектируется совместно с оператором ПОСЛЕ этой разведки. Субагентный
поток остаётся рабочим и единственным до решения оператора.

Основание: исполнитель тикетов 03/09 доказал, что сессии живого хоста
создаются через API (launch-токен → v2-cookie → session/create с
agentPreset), видны в GUI и спавнят субагентов. Неизвестно, может ли
ОРКЕСТРАТОР надёжно ВЕСТИ такую сессию как исполнителя — это и есть
предмет разведки.

**Вопросы разведки (каждый — факт с живым логом либо названный блокер):**

1. Семантика `session/prompt`: блокирующий/стрим, как оркестратор
   получает ответ и ход сессии; можно ли слать несколько промптов
   подряд (продолжаемая сессия).
2. Чтение вывода сессии оркестратором: API-эндпоинт либо логи
   `~/.dsh/sessions/<id>`; полнота (инструменты, ответы, отчёт),
   задержка, формат.
3. Время жизни launch-токена и v2-cookie; перевыпуск; что при истечении.
4. Лимиты сессий на хосте (одновременные, всего); поведение при
   превышении; отличие от лимита субагентов.
5. Уборка/завершение сессии: API-эндпоинт либо событие; что остаётся
   в GUI/логах; идемпотентность.
6. Планировщик в корневой API-сессии: доступен ли `schedule_create`
   (запрет DSH — для делегированных субагентов; API-сессия — корень).
7. Пресет и имя: сессия с agentPreset несёт персону/инструменты/личное
   имя (механизм тикета 09); спавн субагентов сессией (глубина, бюджет).
8. Надёжность ведения: что при обрыве связи/рестарте хоста/падении
   сессии; можно ли перечитать ход и продолжить.

**Демо-путь (доказательство фактов, не построенный поток):** пробная
сессия создана с пресетом, промпт отправлен, ответ и ход прочитаны
оркестратором, сессия спавнила субагента, сессия убрана; логи каждого
шага — в `11-evidence/`.

**Выход разведки:** отчёт фактов по 8 вопросам + оценка вариантов
потока (сессионный / субагентный / гибрид) с плюсами-минусами и
ценой — работа агента; РЕШЕНИЕ о переделке и дизайн тикета переделки —
оператора, совместно с оркестратором/планированием, после отчёта.
Неразрешимый блокер ведения — назван, вариант «оставить субагентный
поток» остаётся допустимым исходом.

**Критерии приёмки:**

- [ ] Отчёт фактов — артефакт: ответы на 8 вопросов с живыми логами
      (`11-evidence/`), каждый факт проверен прогоном, не предположение;
      ожидание: механизм ведения понятен либо названы блокеры; на базе
      разведки нет.
- [ ] Пробный цикл — артефакт: id сессии, промпт/ответ, чтение хода,
      спавн субагента, уборка — логи; ожидание: цикл воспроизводим;
      на базе нет.
- [ ] Оценка вариантов — артефакт: раздел отчёта (сессионный/субагентный/
      гибрид, плюсы-минусы, цена, рекомендация агента); ожидание:
      оператору есть из чего выбирать; решение НЕ принимается тикетом.
