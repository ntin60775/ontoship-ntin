# 07: Живая проба универсального team-потока на fin-agent

**Спека:** [team-profiles](../../docs/plans/team-profiles.md), «Готово» 8,
решение 24 (пересмотр решений 12/17: проба общего случая, не 1C).

**Блокируется:** тикет 14 (фильтр тривиальности; проба под новым правилом).

**Блокирует:** 08 (набор, KB и протокол 08).

**Что построить:** живую пробу полного универсального team-потока на
проекте fin-agent (расчётное ядро finance_core, Python). 1C не
тестируется — вынесен решением 24 (1C-тим как интеграция не существует).

Среда: изолированный хост (копия DSH_HOME, свой порт; team v0.2.1
universal — пресеты architect/orchestrator/executor/scout, БЕЗ
1C-контура/стека); копия finance_core (`/home/prog7/home/areas/fin-agent`
→ worktree/копия) + синтетический scenario.json (реальные данные учёта
не трогаются); плагин fin-agent при необходимости; config.toml (4 роли
панели), executors.json (executor, scout). Before/after sha256 копии
ядра; живой профиль и живой GUI не изменяются/не перезапускаются.

Пробный юнит: bounded прикладная задача finance_core — архитектор
grilling-ом с оператором выбирает конкретное улучшение (тривиальности
решает сам по решению 23), правка доказывается реальным pytest;
плюс анализ миграции finance_core на Go (аналитический deliverable,
не реализация миграции — scout/архитектор).

Поток: 1c не используется; architect → план-гейт G1 → проекции →
нарезка G2 → orchestrator выбирает executor по реестру → цепочка
(таймер опроса + READ-канал session_read, контракт 2 match) → executor
(правка + pytest) → ревью-панель (4 роли из config.toml, один прогон,
вердикты) → автоприёмка → финишная приёмка G3; scout спавнится и
читается через session_read. Проверяемый результат — pytest
finance_core + паритет моста плагина.

Бюджет ex-ante: ≤3M токенов суммарно (input+output по tokenUsage),
wall ~150 мин, ≤10 сессий, детей ≤4, ретраев ≤2; роли: architect
≤400k, orchestrator ≤400k, executor ≤600k (пенсия 500k/600k), панель
≤600k, scout ≤100k; два снимка tokenUsage оркестратором; превышение —
стоп по нормам chain, состояние в continue.md, незакрытая часть — пробел.

Отрицательные условия: оператор не читал и не писал код, других ручных
гейтов кроме G1/G2/G3 нет, циклов правок нет. Ревью тайм-боксированы
(≤10 мин на роль, долгие прерываются — политика оператора 2026-11-16).

**Демо-путь:** артефакты пробы (сессии, коммиты, отчёты, pytest) в этом
тикете + durable-отчёт; пробный юнит fin-agent прошёл полный поток.

**Критерии приёмки:**

- [ ] Полный поток — артефакт: чек-лист шаг→артефакт→ожидание (ids
      сессий architect/orchestrator/executor/панель, коммиты, ask-записи
      G1/G2/G3, вердикты панели, автоприёмка, финишная приёмка);
      ожидание: «Готово» 8, 24; на базе universal-пробы нет.
- [ ] Прикладная задача fin-agent — артефакт: правка finance_core +
      pytest зелёный + Go-миграционный анализ (deliverable); ожидание:
      прикладной кейс доказан, миграция проанализирована.
- [ ] Scout — артефакт: спавн scout + чтение через session_read;
      ожидание: scout работает.
- [ ] Отрицательные условия — артефакт: отчёт (оператор не читал/не
      писал код, три гейта, циклов правок нет); ожидание: «Готово» 8.
- [ ] Бюджет и профиль — артефакт: ex-ante предел + измеренный факт +
      стоп; before/after sha256 копии ядра, живой профиль не изменён;
      ожидание: «Готово» 8.

**Точки остановки:** рестарт живого GUI запрещён (только изолированный
хост); реальные данные fin-agent не трогаются (копия + синтетика);
1C не тестируется (вынесен); циклов правок нет; секреты в артефакты
не коммитятся.
