# 12: Гибридный READ-канал — плагин чтения сессий и ревизия норм chain

**Спека:** team-profiles (носитель: `ontoship-team/docs/plans/team-profiles.md`), «Готово» 12,
решение 21 (оператор ask 2026-11-15 после отчёта разведки 11: гибрид C
как шаг к A; клиент — плагин; контракт 2; пенсия по tokenUsage).

**Блокируется:** 11 (разведка дала факты API-ведения; отчёт и evidence —
основа дизайна).

**Блокирует:** 07 (живая проба полного потока идёт на гибридном потоке).

**Что построить:** READ-канал гибридного потока и ревизию норм chain.
Спавн и lifecycle остаются нативными (`subagent`, `send_message`);
оркестратор получает чтение хода исполнителя через API хоста.
Write/lifecycle сессионного потока A — вне рамок: будущий тикет.

1. **Плагин `ontoship-session-read` в `ontoship-team`.** Хост-плагин,
   read-инструмент у пресета orchestrator (дельта композиции; executor,
   scout, architect не меняются). Методы чтения: `session/wait`,
   `session/events` (адрес `kind:'session'` и `kind:'subagent'`),
   `session/projections`, `session/list`. Read-only allowlist в коде:
   write-методы недостижимы, попытка — именованный отказ. Credential-цикл
   внутри плагина: токен из лога хоста (путь — конфиг) → обмен на
   v1-cookie → кэш → на 401 перечитать токен, перевыпустить, один
   повтор → именованный отказ; токен и cookie не покидают плагин
   (редакция по построению). Конфиг: URL хоста и путь лога, дефолты +
   override. Адресация ребёнка: имя дерева → id (механизм разведки
   `11-evidence/08-hybrid-child-rows.json`). Контрактные тесты бандла: allowlist,
   форма вызовов, таксономия ошибок, credential-цикл на мок-хосте,
   редакция секретов, конфиг. Релиз team v0.2.0 (semver minor), тег.
2. **methodContract 2.** Манифест бандла `ontoship.methodContract: 2`,
   ожидание скилла chain — 2; правило bump расширяется категорией
   «обязательные механизмы ведения»; носители правила правятся одним
   изменением, паритет сторожится. Контрактные тесты и живая проба
   match/mismatch (механизм тикета 04).
3. **Ревизия норм chain** (`skills/chain/SKILL.md`,
   `tests/test_skill_chain.py`):
   - опрос: тик = статус-запрос + сверка артефактов + API-снимок
     (projections/state через read-инструмент); полные ходы — при
     подозрении или на приёмке; отказ инструмента — деградация с
     названным пробелом;
   - исполнитель: результат сверяется чтением хода из durable log,
     не только уведомлением (норма инцидента тикета 11);
   - стражи бюджета: пенсия по кумулятивному tokenUsage сессии
     исполнителя; двухуровневый порог — проектный факт continue.md
     (500k — оценка и подготовка handoff, 600k — обязательная пенсия
     на границе тикета); семантика метрики сверяется живьём и
     называется в норме; фолбэк — оценка по ходам с названным
     пробелом при отказе READ; литералы порогов в скилл не носятся;
   - правило тишины: тик заканчивается одним из трёх явных состояний
     (исполнитель работает / готово / ждём пользователя); простой
     исполнителя без сообщения оператору недопустим;
   - доставка steer/queue: коррекция текущей задачи — сразу,
     независимая задача — на границу; напоминания без новой
     информации не шлются.
   Якоря, мутационные пробы, красная проба на базе (chain без
   гибридных норм). Канон и зеркало не трогаются, если носители
   правила bump их не затрагивают (носители назвать в проходе).
4. **Стек `ontoship-team-1c`.** Перепин teamCommit на v0.2.0; копия
   композиции `1c-orchestrator` получает read-инструмент; паритетный
   тест против нового пина зелёный. 1C-DSH не правится (шов уже
   аддитивный).
5. **Спека и записи.** Решение 21, «Готово» 12, ревизия «Рамок»
   внесены публикацией этого тикета; индексы и continue.md обновлены.
