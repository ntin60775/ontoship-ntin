# 01: механизм — конфиг и генерация определений

**Спека:** [docs/plans/review-config.md](../../docs/plans/review-config.md)

**Что построить:** реестр ролей `.agents/config.toml` (секция `[agents.<name>]`,
ключ `model` обязателен) и генератор: по одному определению агента на роль в
`<project>/.zcode/agents/<name>.md` с `model:` из конфига. Сверка модели
определения с конфигом перед запуском, расхождение — перегенерация. Носитель
генератора — `scripts/`, stdlib. Строка `.zcode/agents/` — в `.gitignore`
этого репозитория: определения производные, не коммитятся.

**Блокируется:** —

**Демо-путь:** временный проект: конфиг с пятью ролями ядра → пять определений;
правка `model` в конфиге → сверка называет расхождение → перегенерация;
повторный запуск без изменений — файлы не меняются; без конфига генератор не
пишет ничего.

**Критерии приёмки** (каждый падает на базовом коммите `0b54a62`):

- [x] конфиг парсируется: незнакомая секция или ключ — предупреждение, не отказ;
      секция роли без `model` — отказ с внятной ошибкой; битый TOML — отказ
- [x] генератор создаёт по одному определению на роль с `model:` из конфига;
      идемпотентен: повторный запуск без изменений конфига не меняет файлы
- [x] расхождение `model` конфига и определения фиксируется и лечится
      перегенерацией; без конфига ничего не пишется
- [x] `.zcode/agents/` в `.gitignore` репозитория; определения не попадают
      в `git status`
- [x] spec-тесты пунктов выше живут в `tests/` и падают на базе
