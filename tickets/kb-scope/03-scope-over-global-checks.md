# 03: scope над глобальными проверками — I10 и рёбра графа

**Спека:** [docs/plans/kb-scope.md](../../docs/plans/kb-scope.md)

**Блокируется:** [01](01-scope-corpus.md) — без ридера scope проверять нечего.

**Что построить:** срезанное поддерево не должно оставлять находок там, где
файлов уже нет в корпусе. Две дыры, найденные панелью тикета 01
(`reviewer-code` P2, `reviewer-kb` P3, `reviewer-spec` P3):

1. `index_chain_issues` (I10) обходит `docs/` через `rglob`/`iterdir` мимо
   корпуса: исключённое поддерево с собственным `README.md` продолжает
   требовать ссылки от родительского индекса — `ERR I10 docs/README.md`
   переживает срезку.
2. Рёбра графа (`resolve_link(..., known)`) строятся по корпусу, поэтому после
   исключения соседа у оставшегося KB-файла пропадает связь и появляется
   `WARN I3 — сирота`: срез окрашивает дерево, которое до среза было чистым.
   Связь пропадает в двух направлениях — исходящем (файл ведёт в срезанное
   поддерево) и входящем (в срезанном поддереве лежал единственный связчик).
   Исходящую срез чинит резолвом цели по файловой системе; входящая сиротой
   и остаётся — решение оператора 2026-11-11, решение 19 спеки: за связность
   KB отвечают документы KB.

**Предусловие:** замер панели 2026-11-10 (repro: фикстура с `docs/gen/`,
префикс `docs/gen/` — `ERR I10` выживает, `WARN I3` переезжает на
`docs/reference/x.md`). Замер среза 03 уточняет направление находки:
мнимый сирота — это исходящая связь в срезанное поддерево; входящая связь
остаётся законной сиротой по решению 19 спеки. В consumer-дереве обе дыры
не проявляются: у `docs/upgrade-guide/` нет `README.md` (только `WARN I5`),
ложных сирот дерево не даёт — критерий 3 потому и сверяет отсутствие
регресса, а не факт починки.

**Демо-путь:** на временном git-репозитории с `docs/gen/README.md` и ссылкой
на него из `docs/README.md`: до среза `lint` даёт `ERR I10` на `docs/README.md`
и `WARN I3` на файле `docs/gen/`; с `gitmark.scope.json` =
`{"exclude_prefixes": ["docs/gen/"]}` — обе находки исчезают, `✓ чисто`,
exit 0. Тот же прогон на consumer-дереве закрывает «Готово» 6 спеки без
оговорок.

**Критерии приёмки**:

- [x] I10 по корпусу — артефакт: `tests/test_scope.py` (новый кейс) и вывод
      `lint` на фикстуре; ожидание: подраздел, исключённый scope, не участвует
      в цепочке индексов — ни `ERR I10` на родителе, ни `ERR I10` на самом
      себе; подраздел вне `docs/` не затрагивается (спека «Готово» 1,
      «Ограничения»)
- [x] рёбра не создают мнимых сирот — артефакт: `tests/test_scope.py`, вывод
      `lint`; ожидание: документ, потерявший связь из-за исключения соседа, не
      даёт `WARN I3`, если цель существует на файловой системе; решение —
      резолвить рёбра по ФС (как I4 через `fs_resolve`), а `known` оставить для
      мягкого графа; входящая связь из исключённого поддерева сироту не
      оправдывает (спека «Готово» 1, решения 18–19, «Ограничения»)
- [x] consumer-прогон без оговорок — артефакт: скопированный вывод `lint`
      consumer-полигона с тремя префиксами; ожидание: `✓ чисто` и exit 0 —
      без исключения `docs/upgrade-guide/` из-под I10 и без оговорки «на этом
      дереве дыра не проверяется» (спека «Готово» 6). Доказательство по
      существу — фикстура среза: она краснеет на базе и зелёная на срезе.
- [x] онтология и тексты I4/I5/I10 не правятся — артефакт: `git diff` по
      `docs/ontology.md` и `skills/kb-curate/ontology.md`; ожидание: изменений
      нет, I8 проходит; в SKILL.md (тик. 04) цепочка описывается по корпусу
      (спека «Рамки», решение 5)
- [x] набор цел — артефакт: вывод pytest полного набора; ожидание: 00-проверки
      `test_lint_paths.py`, `test_engine.py`, `test_canon_sync.py` без правок,
      новые кейсы краснеют на базовом коммите тикета (спека «Ограничения»)

**Вне рамок тикета:** штамп корпуса в `.gitmark/index.db` (решение оператора —
обязанность `index`, тикет 04) и дедупликация текстов отказа (P3 панели). Туда
же — два обхода дерева, которые scope не сужает и которые находок не создают,
а только снимают: словарь сервисов в `cmd_lint` (`docs_root.rglob`) и
существование индекса папки в `_lint_readme_index` (I5 проверяет
`(d/"README.md").exists()` по ФС, а не по корпусу). Названы в отчёте среза.
