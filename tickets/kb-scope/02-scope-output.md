# 02: поле `scope` в `stat --json` и две строки при выборке путей

**Спека:** [docs/plans/kb-scope.md](../../docs/plans/kb-scope.md)

**Что построить:** вывод движка, механизм не трогается. `stat --json` несёт поле
`scope` (число исключённых файлов и число префиксов; нули, когда scope нет или
он пуст). `lint <paths>` по-прежнему считает `I4`, `I5` и глобальные проверки по
всему корпусу — контракт «пути сужают только per-file» остаётся в силе, — но итог
печатает двумя строками: `в выборке: <X> ERR · <Y> WARN` и
`вне выборки: <X′> ERR · <Y′> WARN`.

**Блокируется:** [01](01-scope-corpus.md) — без ридера scope печатать нечего.
**Предусловие:** решения 6, 7 и 17 спеки (ask и план-гейт 2026-11-10);
exit-коды 0/1/2 не меняются.

**Демо-путь:** фикстура с находкой внутри выборки и находкой вне её:
`gitmark.py lint docs/a.md` печатает обе строки, их суммы равны общему числу
находок, `checked` остаётся размером корпуса; `stat --json` показывает
`scope` с ненулевым числом исключённых; без path-аргументов второй пары строк
нет. Новые тесты краснеют на базовом коммите.

**Критерии приёмки**:

- [x] поле `scope` — артефакт: вывод `gitmark.py stat --json` на фикстуре;
      ожидание: при ненулевом excludes JSON несёт `scope` с числом исключённых
      файлов и префиксов; без scope-файла — нули, поле на месте
      (спека «Готово» 7, решение 17)
- [x] две строки при выборке — артефакт: stdout `lint <paths>` на фикстуре со
      смешанными находками; ожидание: строки `в выборке: <X> ERR · <Y> WARN` и
      `вне выборки: <X′> ERR · <Y′> WARN`, суммы равны общему числу находок,
      без path-аргументов пара строк отсутствует (спека «Готово» 5, решение 6)
- [x] контракт сужения не тронут — артефакт:
      `tests/test_lint_paths.py`, тест `test_selection_narrows_only_per_file_checks`;
      ожидание: проходит без правки; `checked` остаётся размером корпуса;
      helper глобальных проверок не сужается (спека «Готово» 5, решение 6)
- [x] exit-коды прежние — артефакт: коды трёх прогонов (чистый, ERR под
      `--strict`, отказ использования); ожидание: 0, 1, 2 — новых кодов нет
      (спека, решение 7)

## Доказательства

**Срез.** worktree `.scratch/worktrees/kb-scope-02`, ветка `kb-scope-02` от
`755f648`. `create_worktree` снова упал («command "node" was not found on
PATH») — срез отделён `git worktree add -b`, снос тем же способом. Коммиты:
`2a16145` — тесты первыми и реализация, `e4e70dc` — правки панели,
`47555e1` — три решения оператора. Merge ff в `main` (`47555e1`), ветка
удалена, worktree снесён.

Отдельный факт про базу: `main` ушёл на `05c736e` (amend сообщения коммита
перенумерации) после отделения ветки, поэтому срез переставлен
`git rebase --onto main 755f648 kb-scope-02`; деревья `755f648` и `05c736e`
совпадали (`git diff --stat` пуст), содержимое среза не изменилось.

**Красная проба на базе: 4 failed / 32 passed** (слепок `git archive 755f648`
в /tmp + новые тесты поверх; повторено ролью `reviewer-tests`). Краснеют
`test_selection_prints_two_lines`, `test_stat_json_carries_scope`,
`test_stat_json_scope_is_zero_without_file`,
`test_stat_json_scope_present_before_any_index`. Зелёные по построению и
обязаны быть зелёными: `test_no_selection_lines_without_paths` (негативный
охранник: пары и не должно быть), `test_checked_is_full_corpus_under_selection`
и `test_exit_codes_unchanged_under_selection` (стражи неизменного контракта).
В первой редакции блок давал «4 failed / 32 passed» с другим составом —
переписанный после панели набор даёт те же 4 красных.

**Мутационные пробы.** Снятие scope-поля в `cmd_stat` → 4 красных (3 stat-теста
+ контракт `test_stat_json_contract`); возврат `checked` по selection → 4
красных (новый тест + два стража `test_lint_paths.py`); инверсия членства
`x[2] in sel` → красен. После панели закрыты два слепых пятна, которые роли
ловили выживанием мутаций: `in_warn = 0` (фикстура была пуста по WARN) → теперь
красен `test_selection_prints_two_lines`; перестановка двух `print` местами →
теперь красен тот же тест через проверку `i_out == i_in + 1`.

**Демо-путь живьём.** Фикстура (6 md: `docs/README.md`, `docs/keep.md` и
`docs/other.md` с `relates_to`, `docs/orphan.md` — сирота, `docs/sub/x.md`,
`snapshots/shot.md`, плюс три битые ссылки):

```console
$ gitmark lint docs/keep.md
в выборке: 1 ERR · 0 WARN
вне выборки: 2 ERR · 1 WARN
3 ERR · 1 WARN  (6 файлов · I4×3 · I5×1)

$ printf '{"exclude_prefixes": ["snapshots/"]}' > gitmark.scope.json
$ gitmark index >/dev/null && gitmark stat --json
{"indexed": true, "files": 3, …, "scope": {"excluded_files": 1, "prefix_count": 1}}
$ gitmark stat --json          # scope-файла нет
{"indexed": false, "scope": {"excluded_files": 0, "prefix_count": 0}}
```

Собственное дерево (`gitmark.scope.json` ещё не заведён — догфуд у тикета 04):
`stat --json` → `"scope": {"excluded_files": 0, "prefix_count": 0}`,
`lint docs/README.md` → «в выборке: 0 ERR · 0 WARN» + «вне выборки: 0 ERR ·
0 WARN» + «✓ чисто (107 файлов · —)», `lint --strict` exit 0.

проверка rc 0, парсинга и post-index ветки сохранены, равенство стало строже.

**Разбор расхождений ожидание/факт** (правило testing-бандла):

- ожидание первой редакции — «вне выборки 2 ERR · 2 WARN» при выборе одного
  файла; факт — 2 ERR · 1 WARN. Причина: per-file проверки (I1/I2/I3/I6) по
  контракту ядра считаются только по выбранным файлам, поэтому `WARN I3` на
  не-selected orphan вообще не появляется в прогоне. Тест переписан так, чтобы
  отражать контракт, а не спорить с ним; трактовка записана в
  `tickets/README.md`;
- ожидание панели — «фикстура смешанная по severity» (строка тикета «со
  смешанными находками»); факт первой редакции — смешаны только по выборке,
  обе строки давали `0 WARN`, и мутация `in_warn = 0` выживала весь набор.
  Закрыто фикстурой `_repo_mixed`;
- ожидание — «новые тесты краснеют на базовом коммите»; факт — краснеют 4 из
  7, три обязаны быть зелёными (состав выше);
- ожидание — `SKILL.md` описывает форму доиндексного JSON; факт — с этого
  среза строка `{"indexed": false}` ложна, якорного теста на неё нет.
  Исправлено этим срезом по твоему решению, а не отложено в тикет 04;
- ожидание — планка решения 14 «≤ ~1400»; факт — 1411. Планка стала
  измеренной «≤ ~1450» (твое решение), критерий проверки длины добавлен в
  тикет 04 — до этого планку не сторожил никто, из-за чего она уплыла дважды;
- опечатка этого тикета (строка «без path-аргументов второй пары строк нет»)
  при буквальном прочтении вакуумна; норма спеки — «пара строк отсутствует»,
  её держит `test_no_selection_lines_without_paths`. Текст тикета не правлен,
  чтобы не подменять принятое утверждение нарезки задним числом;
- остальных расхождений ожидание/факт не было.
