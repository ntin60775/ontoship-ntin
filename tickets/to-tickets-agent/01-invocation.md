# 01: to-tickets вызывает агент

**Спека:** [docs/plans/to-tickets-agent.md](../../docs/plans/to-tickets-agent.md)

**Что построить:** замена фразы о вызове нарезки в каноне и его зеркале
с оговоркой о «вручную», снятие флага и пользовательских формулировок
со скилла, переворот контрактного теста с переписыванием теста
снятого инварианта, формулировки докстринга в тесте testing — одним
срезом.

**Дословные тексты правки** (носитель держит дословно;
несовместимость «новый текст ↔ существующие пробы» — точка остановки,
решение оператора):

1. `docs/decisions/ontoship-core.md`, три места:
   - абзац «Переходы»: «`to-tickets` **вызывает пользователь**» →
     «`to-tickets` **вызывает агент**»; остальные предложения абзаца
     не меняются;
   - строка «Tracer-bullet, блокирующие рёбра, демо-путь, критерии
     приёмки. Пишется `to-tickets` вручную.» → «…Пишется `to-tickets`
     вручную — «вручную» значит без автоматических цепочек, не про
     способ вызова: скилл вызывает агент.»;
   - фаза 2 «2. **to-tickets** — вручную: tracer-bullet…» → «2.
     **to-tickets** — вручную, то есть без автоматических цепочек:
     tracer-bullet…».
2. `skills/ship/references/method-phases.md` — та же замена абзаца
   «Переходы» и та же оговорка в фазе 2 («вручную, то есть без
   автоматических цепочек:»).
3. `skills/to-tickets/SKILL.md`, frontmatter: строка
   `disable-model-invocation: true` удаляется; description —
   «Скилл вызывает только пользователь.» → «Скилл вызывает агент.»
4. То же, тело: «Скилл вызывает пользователь; модель его не вызывает.
   Вызванный пользователем скилл может звать модельные скиллы
   (`kb-search`, `kb-curate`), но не другой пользовательский.» →
   «Скилл вызывает агент: нарезка идёт ask-проходом сразу после
   план-гейта.»
5. То же, «Когда использовать»: «Оператор позвал скилл после
   план-гейта и назвал спеку.» → «Фронтир пуст и спека утверждена на
   план-гейте: нарезка следует сразу.»; bullet «Не запускай
   самостоятельно: frontmatter несёт `disable-model-invocation:
   true`» удаляется.
6. `tests/test_skill_to_tickets.py`:
   - якорь «вызывает пользователь» → «вызывает агент»
     (REQUIRED_PHRASES);
   - frontmatter-проверка инвертируется — флаг должен отсутствовать
     (образец — `tests/test_skill_critic.py`, «disable-model-invocation
     must be absent»);
   - мутационные пробы переворачиваются: вставка флага в frontmatter
     краснит, удаление якорной фразы краснит (case-insensitive, все
     вхождения);
   - тест снятого инварианта `test_skill_is_user_invoked_only`
     переписывается тем же изменением (канон: «когда инвариант
     выводится из эксплуатации, его тесты уходят тем же изменением»):
     новый тест требует отсутствия флага и наличия «Скилл вызывает
     агент»;
   - docstring: «and stay user-invoked: the frontmatter pins
     ``disable-model-invocation: true``» → «and agent-invoked:
     invoked right after the plan gate; the frontmatter carries no
     ``disable-model-invocation``»; строка инварианта «the model
     never invokes this skill» снимается вместе с инвариантом.
   - Точные фрагменты существующих проб читаются до правки — соседние
     якоря не рвать.
7. `tests/test_skill_testing.py` — только формулировки: строка
   инварианта «only to-tickets and ship are model-inaccessible» →
   «ship is model-inaccessible»; текст сообщения об ошибке
   «only to-tickets and ship are model-inaccessible» → «ship is
   model-inaccessible». Ассерты о самом testing не меняются.

**Красная проба** — процедура ship, до реализации: отдельный worktree
от базового коммита, только тестовый файл `test_skill_to_tickets.py`;
перечень упавших перевёрнутых, переписанных и новых проверок
записывается в этот тикет при пробе.

**Блокируется:** нет.

**Демо-путь:** полный набор `python3 -m pytest tests/ -q` зелёный
после среза; живая демонстрация контракта: временная вставка флага в
