# 03: Скиллы пишут lease — ship и chain

**Спека:** [chain-live-activity](../../docs/plans/chain-live-activity.md),
«Готово» 5, 6; решения 2, 5, 6, 7.

**Блокируется:** тикет 01 (контракт инструментов стабилен).

**Что построить:** скилл `ship`: lease на границах и внутренних рубежах
шагов — 1 starting (runId из входа; runId нет — self-dispatch,
boardRoot = cwd), 2–3 working (heartbeat после чтения лога тестов),
4 review (heartbeat до панели, на старте/финише пакетов ролей и после
правок), 5–6 gates (heartbeat после чтения выводов гейтов), 7 merge;
финиш — accepted/aborted/failed, затем idle; остановка прохода —
aborted с note до парковки; инструмента нет — названный пробел, проход
идёт; изоляция worktree не меняется. Скилл `chain`: dispatch при выдаче
каждого тикета (executorSession из спавна), runId и boardRoot в каждом
сообщении выдачи (send_message) и в handoff-промпте пенсии; пенсия —
старый исполнитель пишет idle, оркестратор dispatch'ит новый runId
того же тикета; уборка только через dispatch. Контрактные тесты обоих
скиллов.

**Демо-путь:** контрактные тесты скиллов: lease-правила названы в
SKILL.md на своих шагах (мутации снимают правило — тест краснеет);
поведение фаз в живом прогоне доказывает тикет 04.

ожидание: исполнитель и оркестратор пишут lease по шагам, ручной /ship
тоже виден на доске; на базе метода lease-правил в скиллах нет —
контракты красные.

      self-dispatch без runId, остановка → aborted, финиш → терминал
      и idle, пробел без инструмента назван; на базовом коммите метода

- [ ] Контракт chain — артефакт: лог контрактного теста chain;
