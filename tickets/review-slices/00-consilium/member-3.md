- Маршрут: `qwen-token-plan-glm/glm-5.3`, уровень `max`
- Фокус: термины / риск
- Статус: живой
- Спека: `docs/plans/review-slices.md` (131 строка), прочитана полностью; носители

## Находки

### 1. Прецедент «critic уже режет спеку на срезы» — снятый механизм

- Проекция: термины / связность
- Приоритет: **P2**
- Место: «Контекст», строка 127–128 («Прецедент: `critic` уже режет спеку на
  смысловые срезы, но там срез — проекция спеки»)
- Утверждение: спека называет прецедентом текущее поведение `critic`, которого
  нет в носителе.
- Доказательство: `rg -c "срез" skills/critic/SKILL.md` — 0 вхождений; спека
  `critic-consilium` (закрыт 2026-11-24, коммиты `8c54433`→`c5f1fc5`) заменила
  срезы консилиумом полных чтений; приписка 2026-11-24 в
  `docs/plans/standards-autoship.md` (строки 65–73): «динамические срезы и выбор
  модели под срез сняты». Коммит план-гейта review-slices `4aca764` стоит ПОСЛЕ
  закрытия critic-consilium — на момент утверждения спеки срезов в критике уже
  не было. Абзац размежевывает термин «срез» через механизм, которого больше нет.
- Что править: переписать прецедент как историю: «прецедент снят — critic
  перешёл на консилиум полных чтений (юнит critic-consilium, 2026-11-24);
  размежевание держится определением в этой спеке». Или убрать абзац.

### 2. Коллизия термина «срез» с живым значением в изменяемом носителе

- Проекция: термины
- Приоритет: **P2**
- Место: «Решения» 1 (строка 34), «Готово» строка 54–56; носители —
  `skills/ship/SKILL.md`, канон
- Утверждение: спека вводит «срез = кусок диффа», но в `ship/SKILL.md`, который
  спека же правит, «срез» уже означает срез тикета (tracer-bullet). После
  реализации один файл понесёт два значения термина; спека оговаривает
  размежевание только со снятым critic-значением и не оговаривает живое.
- Доказательство: `skills/ship/SKILL.md:33` — «Веди срез как tracer-bullet»;
  `docs/decisions/ontoship-core.md:51` — «ticket — эфемерный срез спеки»;
  `skills/to-tickets/SKILL.md:3,26` — «вертикальные срезы» = тикеты. Спека
  (строка 127–128) размежевывается только с проекционными срезами критика.
  Попутно: решение 1 «срез — область» перекраивает термин «область» носителей
  (область = весь артефактный вход роли: дифф, тикет, спека), оговорки нет; в
  решении 7 поле плана названо «модель», в «Готово» то же поле — «маршрут».
- Что править: назвать размежевание в самой спеке и потребовать его в
  носителях: срез ревью ≠ срез тикета (или ввести отдельный термин, например
  «срез ревью»/«дифф-срез»); зафиксировать, что «область» после правки — часть
  входа, а справка роли — вторая часть; одно имя для поля плана (маршрут).

### 3. Факт повода «по отдельности те же файлы проходят» не подтверждён артефактом

- Проекция: риск / честность
- Приоритет: **P2**
- Место: «Повод», строки 18–19; «Контекст», строка 112–113
- Утверждение: спека заявляет как установленный факт, что одиночные файлы
  упавшего диффа проходят по упавшему маршруту; артефакт фиксирует только
  тривиальную пробу маршрута. Повод также подаёт причину («падали, когда…
  клали весь дифф») как факт, хотя артефакт описывает отказ вывода, а
  причинность — гипотеза «Контекста».
- Доказательство: единственный носитель инцидента —
  `tickets/critic-consilium/01-evidence/panel-report.md:10–12`: «Провайдер
  отклонил вывод всех ролей: PI_AI_ERROR … (content-filter, не таймаут;
  тривиальная проба маршрута отвечала)». Поиск «одиночн/по отдельности» по
  `tickets/`, `docs/`, `.scratch/` даёт вхождение только в самой спеке.
- Что править: привести повод к артефакту: «тривиальная проба маршрута
  отвечала; одиночные файлы упавшего диффа по отдельности не проверялись» —
  либо зафиксировать такую пробу до утверждения повода. Причину в поводе
  формулировать как гипотезу, как это уже сделано в «Контексте».

### 4. Критерий приёмки контроля не различает причину падения

- Проекция: риск / честность критериев
- Приоритет: **P2**
- Место: «Готово», строки 65–69 (живая проба)
- Утверждение: приёмка «контроль упал» зачитывает падение контроля по любой
  причине; падение не с `PI_AI_ERROR` (таймаут, отказ маршрута) обнуляет
  сравнение так же, как проход, но критерий его пропускает — проба будет
  «принята» на ложном позитиве.
- Доказательство: спека, строки 67–69: «его проход обнуляет сравнение —
  остановка и вопрос оператору. Приёмка: контроль упал, все срезы вернулись,
  `PI_AI_ERROR` нет» — сигнатура ошибки demanded только для срезов («нет»), не
  для контроля («упал» без причины). Сам механизм сравнения в спеке уже
  назван («проба их не различает» — про соперниц, строка 116–118), но для
  контроля причина не оговорена.
- Что править: одна строка в приёмку: «контроль упал с `PI_AI_ERROR`; иная
  причина падения — как проход: сравнение обнулено, остановка и вопрос
  оператору».

### 5. Цена пробы не посчитана: ~50 детей, ~13 волн

- Проекция: риск / цена доказательства
- Приоритет: **P3**
- Место: «Готово», строка 63 (дифф пробы); «Контекст», строки 129–131
- Утверждение: для названного диффа пробы срезов ≥12 на роль (2336 строк / 200),
  4 роли → ≥48 детей + контроль, при лимите 4 — ~13 волн; порядок цены пробы
  из спеки не выводится без git-расчёта, оператор утверждал «большой дифф»
  без числа.
- Доказательство: `git diff --stat a72f94a..8c54433` — 17 файлов, 2336
  вставок; спека задаёт кап ≤200 строк на срез (решение 2) и «один subagent на
  срез» (решение 5); крупнейший файл диффа 562 строк режется на 3 части.
  Контекст называет волны качественно («при лимите 4 — волны»), без масштаба.
- Что править: строка в «Контексте»/«Готово»: ожидаемый порядок — ≥12 срезов
  на роль, ~50 детей, ~13 волн на лимите 4; проба одноразовая, без повтора.

### 6. «4 роли × 2 попытки» — артефакты дают три прогона

- Проекция: честность / факт
- Приоритет: **P3**
- Место: «Контекст», строка 112
- Утверждение: спека understates инцидент: заблокированных прогонов панели
  три, не два.
- Доказательство: `tickets/critic-consilium/01-evidence/panel-report.md`,
  `02-evidence/panel-report.md`, `03-evidence/panel-report.md` — каждый тикет
  01–03 вёл панель на заблокированном `qwen-token-plan-deepseek/…`
  (03: «штатный маршрут заблокирован провайдером, как в 01/02»), все три
  артефакта существовали до коммита план-гейта `4aca764`.
- Что править: «4 роли × 3 прогона (тикеты 01–03 critic-consilium)».

### 7. Формулировка ограничения: «файл… дробится по файлам»

- Проекция: термины
- Приоритет: **P3**
- Место: «Ограничения», строки 94–96
- Утверждение: одиночный файл больше капа не может дробиться «по файлам» —
  только по хункам/диапазонам строк; решение 2 (строка 35) корректно говорит
  «дробить по файлам/хункам» для диффа целиком, ограничение переносит это на
  один файл и получается бессмыслица.
- Доказательство: текст спеки, строки 94–96: «файл/хунок больше — дробится по
  файлам или диапазонам строк до спавна».
- Что править: «файл/хунок больше — дробится по хункам или диапазонам строк».
