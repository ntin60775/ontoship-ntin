#### G1. «Готово» не правит старую формулировку входа, предписывающую полный дифф

#### G5. Контроль пробы: нет рецепта, приёмка не фиксирует причину/маркер падения

- **источники:** M1-7 (член 1, P2); M3-4 (член 3, P2).
- **поддержка:** 2/3. **приоритет:** P2 (оба: M1-7 член 1, M3-4 член 3).
- **проекция:** доказательства (M1-7); риск/честность критериев (M3-4).
- **место:** «Готово» 5, строки 63–69.
- **утверждение:** контроль «один ребёнок с полным агрегатом на том же
  маршруте до срезов, ожидается падение» не задаёт рецепт: роль, точный
  состав входа, ожидаемый маркер ошибки, куда пишется результат (M1-7).
  Инцидент — четыре роли, каждая со своим полным агрегатом; один ребёнок
  может не воспроизвести отказ (другой выход) → «его проход обнуляет
  сравнение — остановка», либо упасть по другой причине. Приёмка «контроль
  упал» не доказывает, что упал именно тот агрегат (M1-7); зачитывает падение
  по любой причине: падение не с `PI_AI_ERROR` (таймаут, отказ маршрута)
  обнуляет сравнение так же, как проход, но критерий его пропускает — проба
  «принята» на ложном позитиве (M3-4). Сигнатура ошибки требуется только для
  срезов («нет»), не для контроля («упал» без причины) (M3-4). Контроля нет
  в обязательных полях отчёта пробы (план, маршруты, срезы, находки) (M1-7).
- **доказательство:** M1-7 — `01-evidence/panel-report.md:8–13` «Провайдер
  отклонил вывод всех ролей: PI_AI_ERROR…». M3-4 — спека 67–69: «его проход
  обнуляет сравнение — остановка и вопрос оператору. Приёмка: контроль упал,
