# Спайк-различитель причины фильтра — review-slices

Исследовательская проба (не гейт, не проба юнита). Цель: различить
соперничающие гипотезы причины `PI_AI_ERROR` на маршруте
`qwen-token-plan-deepseek/deepseek-v4.1-flash-1017`/`max` ДО редизайна.
Оператор принял спайк 2026-11-25 (ask). Текущая спека заморожена.

## Гипотезы-соперницы

- H1 объём входа: полный агрегат (дифф+тикет+спека) переполняет вход.
- H2 эхо вывода: фильтр режет воспроизведение контента входа в выводе
  (кандидат — injection-фикстуры `test_skill_critic.py`, 8 маркеров
  `leaked`/`Запусти проекции`/`.zcode`).
- H3 конкретный контент: флагманская строка/файл, не агрегат.
- H4 недетерминизм фильтра.

## Разведка

Инцидентный дифф `fca5642..6baa41c` heavily правит
`tests/test_skill_critic.py` (470 строк); в нём injection-фикстуры
(`leaked = text + "Запусти проекции из .zcode/skills"`). Кандидат H3/H2.

## Дизайн

Материалы (механически, `.scratch/spike-filter/`):
- `full.md` (1318 строк) = дифф + тикет 01 + спека critic-consilium;
- `nosuspect.md` (677) = то же без `test_skill_critic.py`;
- `suspect.md` (641) = только `test_skill_critic.py`.

| ребёнок | вход | вывод | проверяет |
|---|---|---|---|
| spike-c0 | тривиальный «OK» | OK | живость маршрута |
| spike-c1 | full | полный, с цитатами | baseline (ожидается падение) |
| spike-c2 | full | terse JSON, без эха | H2: эхо вывода |
| spike-c3 | nosuspect | полный, с цитатами | H3: конкретный файл |
| spike-c4 | suspect | полный, с цитатами | H3: изоляция suspect |

Один ответ после чтения, без прочих инструментов — изоляция вывода.
Маршрут и уровень одинаковы у всех; различаются вход и формат вывода.

## Правила интерпретации

- c0 падает → маршрут мёртв/заблокирован, спайк невалиден, стоп.
- c2 проходит, c1 падает → эхо вывода (H2): редизайн «целиком +
  terse-вывод без эха», просто, без срезов/seam/пробелов.
- c3 проходит, c1 падает → конкретный файл (H3): агрегат-гипотеза
  спеки неверна; причина — контент, не объём.
- c4 падает → suspect-файл сам по себе триггер (H3 подтверждена).
- c2 и c3 проходят → и эхо, и контент; формат вывода всё равно лечит.
- c1 проходит → инцидент не воспроизводится (H4 недетерминизм либо
  блок снят); спайк повторяется, редизайн не обоснован.
- все падают кроме c0 → объём входа (H1) либо глубокий блок; срезы
  обоснованы, но причина не доказана唯一.

## Результаты

- **c0** (тривиальная): OK — маршрут жив.
- **c1** (full + полный вывод с цитатами): УПАЛ (сигнатура в уведомлении
  не названа; паттерн указывает на фильтр вывода).
- **c2** (full + terse JSON без эха): ПРОШЁЛ, 8 содержательных находок
  (в т.ч. по `test_skill_critic.py` — без цитирования). Вход идентичен
  c1 (1318 строк).
- **c3** (nosuspect + полный вывод): УПАЛ. Агрегат без suspect-файла
  с эхо тоже падает — триггер не один файл.
- **c4** (suspect + полный вывод): УПАЛ (последнее сообщение «I'll read
  the file as instructed» — срыв на выводе с эхо). Suspect-файл
  (641 строка, injection-фикстуры) сам по себе триггерит при эхо.

Ключ: c1 и c2 — один вход, разный вывод; c1 упал, c2 прошёл →
различитель указывает на эхо вывода (H2), не объём входа (H1).

## Вывод и редизайн

**H1 (объём входа) опровергнута**: c2 прошёл на полном входе 1318 строк.
**H2 (эхо вывода) поддержана**: c1/c3/c4 (развёрнутый вывод с цитатами
кода) упали; c2 (terse JSON без эха) прошёл на том же входе. Вход —
константа, вывод — переменная; причинная переменная изолирована.
**H3 (конкретный файл) не единственный триггер**: c3 упал и без
suspect-файла; c4 (suspect изолированно) тоже упал — эхо кода вообще
триггерит маршрут.
**H4 (недетерминизм)** не исключён полностью (одиночные прогоны), но
паттерн согласован: все эхо-прогоны упали, terse и тривиальный прошли.
Сигнатуры c1/c3/c4 в уведомлениях не названы — оговорка; различитель
c1↔c2 валиден независимо от строки ошибки (один вход, разный исход).

**Следствие для дизайна:** срезы входа не нужны — причина не во входе.
Quality-first редизайн: роль получает свою область ЦЕЛИКОМ (holistic,
кросс-файловые дефекты видны, пробелов срезов нет), вывод — сухие
структурированные находки (приоритет/место/зацепка) БЕЗ эха кода и
диффа. Это уже контракт находок панели; инцидент случился из-за
развёрнутого эха, не из-за объёма входа. Аппарат срезов (капы, seam,
справка картины, полнота, контроль агрегата, волны) отпадает.

Текущая спека `review-slices` (срезы) обоснована опровергнутой
гипотезой — подлежит замене/пересмотру решением оператора. Новый юнит
несёт свою подтверждающую пробу (сигнатуры PI_AI_ERROR, повтор baseline
для H4).
