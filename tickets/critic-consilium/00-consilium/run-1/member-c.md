# Отчёт члена консилиума C

- Маршрут: `qwen-token-plan-glm/glm-5.3`, уровень `max`
- Фокус: термины, риск
- Статус: completed — спек прочитан целиком (35 строк), находки собраны только из
  текста фикстуры; внешние артефакты не читал, кроме grep-проверки отсутствия
  «приложения A» в `tickets/critic-consilium/`.

## Находки

### 1. Цикл зависимостей тикетов — взаимная блокировка
- Проекция: риск (также порядок)
- P: P1
- Место: `probe-spec.md:28-29`
- Утверждение: тикет 02 зависит от 01, а 01 блокируется 02 — цикл; ни один
  тикет не может стартовать, спека описывает неисполнимое упорядочивание.
- Доказательство: строка 28 «Тикет 02 (миграция) зависит от тикета 01 (экспорт)»
  + строка 29 «Тикет 01 блокируется тикетом 02» → 01 → 02 → 01.
- Править: разорвать цикл — убрать одно из двух рёбер или описать, что именно
  из 02 блокирует 01 (какая часть), и вынести её в предусловие.

### 2. «Четыре формата» без перечня — четвёртый формат не назван
- Проекция: термины (также покрытие)
- P: P1
- Место: `probe-spec.md:7` vs `probe-spec.md:17`
- Утверждение: Цель фиксирует три формата (CSV, JSON, XLSX), Готово требует
  «Поддержать четыре формата»; четвёртый нигде не назван — критерий
  неверифицируем, терм без денотата.
- Доказательство: строка 7 «три формата: CSV, JSON, XLSX»; строка 17 «Поддержать
  четыре формата»; перечень из четырёх элементов в спеке отсутствует.
- Править: либо назвать четвёртый формат явно, либо заменить пункт 17 на
  «Поддержать три формата: CSV, JSON, XLSX» — согласовать с Целью.

### 3. Веб-панель: в Готово «добавить», в Рамках «вне рамок»
- Проекция: термины (также покрытие/связность)
- P: P1
- Место: `probe-spec.md:16` vs `probe-spec.md:21`
- Утверждение: пункт Готово требует добавить веб-панель мониторинга, а Рамки
  её исключают — прямое противоречие; термин «веб-панель мониторинга» к тому же
  не определён и не имеет критериев.
- Доказательство: строка 16 «Добавить веб-панель мониторинга экспорта»;
  строка 21 «веб-панель вне рамок».
- Править: удалить пункт 16 из Готово (скоуп — «только экспорт»), либо
  вынести панель в отдельный тикет и снять исключение из Рамок.

### 4. «Приложение A» — висячая ссылка
- Проекция: термины (также доказательства)
- P: P2
- Место: `probe-spec.md:12`
- Утверждение: критерий «схема описана в приложении A» ссылается на
  несуществующее приложение — схемы нет, сверить JSON-экспорт с ней нельзя.
- Доказательство: grep по `tickets/critic-consilium/` находит «приложение A»
  один раз — саму ссылку (строка 12); определения приложения нет ни в спеке,
  ни рядом.
- Править: либо приложить схему (приложение A в тот же документ), либо
  перенести схему в тело спеки и убрать ссылку.

### 5. Арифметика времени не сходится: 3 × 1 мин ≠ 2 мин
- Проекция: риск (также время)
- P: P2
- Место: `probe-spec.md:34-35`
- Утверждение: каждый формат экспортируется за минуту, полный экспорт трёх
  форматов заявлен за две минуты — при последовательном исполнении это три
  минуты; параллелизм не заявлен, числа противоречат друг другу.
- Доказательство: строка 34 «Каждый формат экспортируется за минуту»;
  строка 35 «полный экспорт трёх форматов занимает две минуты»; режим
  исполнения (последовательно/параллельно) в спеке не указан.
- Править: либо заявить параллельный прогон и указать бюджет 2 мин как
  пиковое время стены, либо исправить оценку на 3 мин; режим исполнения
  назвать явно.

### 6. Поведение на недопустимом `format` не определено
- Проекция: риск (также рёбра)
- P: P2
- Место: `probe-spec.md:22-23`, `probe-spec.md:27`
- Утверждение: допустимые значения `format` не перечислены (заявлено как
  ограничение), но и поведение на неизвестном значении не специфицировано —
  ошибка, тихий пропуск или молчаливый fallback; риск неопределённого
  поведения и скрытого no-op.
- Доказательство: строка 27 «Поле `format` не имеет списка допустимых
  значений» — и ни в Готово, ни в Ограничениях нет критерия на реакцию
  системы при неизвестном значении.
- Править: добавить ребро-критерий: «неизвестное `format` → экспорт не
  выполняется, возвращается явная ошибка с именем значения»; список значений
  перечислить (минимум: csv, json, xlsx).

### 7. «Экспорт проверен» и «Система работает корректно» — неверифицируемые критерии
- Проекция: риск (также доказательства, честность критериев)
- P: P2
- Место: `probe-spec.md:14-15`
- Утверждение: пункты Готово не называют ни метода проверки, ни артефакта
  доказательства — «проверен» кем и как, «работает корректно» по каким
  критериям; такие пункты закрываются декларацией, а не фактом.
- Доказательство: строка 14 «Экспорт проверен» и строка 15 «Система работает
  корректно» — единственные пункты Готово без объекта и без проверяемого
  условия; остальные пункты (11-13) имеют объект.
- Править: удалить оба пункта — их смысл покрывается пунктами 11-13 при
  добавлении к каждому named proof (команда прогона + артефакт сверки).

### 8. «Листы соответствуют разделам» — «разделы» не определены
- Проекция: термины
- P: P2
- Место: `probe-spec.md:13`
- Утверждение: маппинг лист XLSX → «раздел отчёта» не задан: какие разделы

  нельзя проверить однозначно.
- Доказательство: строка 13 «листы соответствуют разделам» — перечень
  разделов отчёта в спеке отсутствует (структура отчёта `report-core`
  не описана и не процитирована).
- Править: перечислить разделы отчёта и ожидаемые имена листов, либо
  сослаться на документ структуры отчёта как на источник соответствия.

### 10. Дублирование ограничения про `format` в двух секциях

### 12. Нет критериев на сбойные пути экспорта
- Проекция: риск (также рёбра)
