# 08: Дымовой pack-тест ядра

**Разморожен:** решением оператора ask 2026-11-16 (решение 7 спеки
[core-team-boundaries](../../docs/plans/core-team-boundaries.md),
раунд 2 + триаж G9) тикет разморожен и переписан под быстрый дымовой
pack-тест ядра. Заморозка ask 2026-11-13 («до закрытия team-profiles,
вернётся пробой профильного потока») снята: полная живая проба потока
вытеснена пробой 07 team-контура, пак-часть остаётся в ядре этим
дымовым тестом. Исполнение и красная проба критериев — отдельный
прогон вне юнита core-team-boundaries: юнит только размораживает и
переписывает тикет (Рамки спеки).

**Спека:** [standards-autoship](../../docs/plans/standards-autoship.md),
«Готово» 12, 14 (судьба ниже), решение 18; ревизия — решение 7 спеки
core-team-boundaries, триаж G9.

**Блокируется:** тикеты 01–07, 09 юнита (закрыты); исполнение — после
разделения границ core-team-boundaries, отдельным прогоном.

**Что построить:** быстрый дымовой pack-тест ядра в temp-проекте:
установка пака → init с паком → ship исполняет гейты пака → отчёт.

1. Установка пака — `install.sh --pack` эталонного пака
   (`skills/pack/reference-pack`) в temp-проект; `install.sh --check`
   валидирует манифест установленного пака.
2. Init с паком — обнаружение `.agents/packs/`, валидация манифеста,
   регистрация роли пака в `.agents/config.toml` бутстрап-вопросом.
3. Ship исполняет гейты пака — один ручной `/ship` заранее написанного
   игрушечного тикета (правка опечатки README temp-проекта; grilling и
   нарезка в прогон не входят): панель с ролью пака по чек-листу её
   манифеста, механические гейты пака исполняет `run_gates.py` бандла
   pack, вывод каждого гейта сверен с `expect_exit` манифеста.
4. Отчёт — шаги пробы, идентификаторы сессий и прогонов, коммиты
   temp-проекта, пробелы названы пробелами; durable-копия в этом
   тикете.

**Судьба «Готово» 12/14 спеки standards-autoship:**

- «Готово» 12 (живая проба полного потока) — вытеснено пробой 07 team:
  место доказательства полного потока с цепочкой — проба 07 юнита
  team-profiles (универсальный team-поток) после разделения, вне этого
  юнита; сейчас она не исполнена — названный пробел. Ядро chain не
  поставляет. Пак-часть потока сужена до этого дымового теста;
  остальной полный поток (цепочка, финишная приёмка) и проба остановки
  цепочки (stop-probe) — механизм ведения team, в ядре не исполняются;
  grilling и нарезка — шаги метода, в дымовой прогон не входят
  (тикет написан заранее).
- «Готово» 14 (закрывающий набор) — ядровая часть закрыта прогонами
  тикетов 01–07, 09 (счета и красные пробы названы в тикетах) и
  охраняется каждым ship-прогоном ядра (набор, `lint --strict`,
  `install.sh --check`); отдельный закрывающий прогон юнита и
  team-часть набора — названный пробел (новые тесты team сняты
  решением оператора 2026-11-16, активация team отложена).

Живая проба шага базовых стандартов («Готово» 4) — носитель пункта 12;
в дымовой прогон шаг не входит — названный пробел. Документ базовых
стандартов этого репозитория утверждён ask 2026-11-11 (тикет 03).

Живой 1С-пак — названный пробел до его создания (1C-стек вне юнита
core-team-boundaries).

**Что краснит:** мутация конфига гейта установленного пака —
`expect_exit` не совпадает с фактическим кодом выхода команды:
механический гейт ship красный, проход стоит, критерий гейтов падает.
Красная проба критериев — вход прогона sa08 (вне юнита); смок-поток
паков существует на базе, критерии на базе зелёные (триаж G9).

**Демо-путь:** сквозной дымовой прогон четырёх шагов в temp-проекте:
пак установлен и валиден, init зарегистрировал роль пака, ship
исполнил гейты пака и довёл игрушечный тикет до merge, отчёт записан.

**Критерии приёмки**:

- [x] Установка пака — артефакт: лог `install.sh --pack` и
      `install.sh --check` temp-проекта; ожидание: пак в
      `.agents/packs/<имя>/`, манифест валиден, `check: ok`
      («Готово» 2, решение 5 спеки).
- [x] Init с паком — артефакт: отчёт init (блок «Паки стандартов») и
      реестр `.agents/config.toml`; ожидание: пак обнаружен, манифест
      валиден, роль пака зарегистрирована бутстрап-вопросом
      («Готово» 3, 9).
- [x] Ship исполняет гейты пака — артефакт: отчёт ship-прогона
      игрушечного тикета (вердикты панели с ролью пака, вывод каждого
      гейта `run_gates.py` рядом с `expect_exit` манифеста, запись
      автоприёмки, merge); ожидание: конфиги-данные исполняет ядро без
      shell, красный гейт останавливает проход («Готово» 8).
- [x] Отчёт — артефакт: финальный отчёт пробы в этом тикете;
      ожидание: каждый шаг назван и доказан, пробелы названы
      пробелами (решение 18, триаж G9).
