# Отчёт триажа проекций — weekly-digest (живая проба тикета 04)

Прогон проекционной валидации по скиллу `critic` (срез `4e806fc` юнита
`standards-autoship`, тикет 04). Спека: `docs/plans/weekly-digest.md`
(temp-проект `/tmp/sa04-projections`). Дата прогона: 2026-11-11.
Основная сессия — исполнитель тикета 04 (модель сессии
`qwen4-max-preview`, провайдер `qwen-token-plan-max`); проекции на
flash-пуле, не на модели сессии.

## Срезы и модели

Срезы сгенерированы основной сессией из спеки динамически: семя —
чек-лист критика (покрытость, связность, рёбра, демо-пути, честность
критериев, цена доказательства) и восемь проекций валидации плана
(покрытие, порядок, доказательства, власть, время, окружение, термины,
риск). Три среза — связки близких граней под предмет игрушечной спеки.

| срез | проекции и грани | маршрут | уровень | подчинённая сессия |
|---|---|---|---|---|
| Покрытие и доказательства | покрытие, доказательства; покрытость «Готово», честность критериев, цена доказательства | `qwen-token-plan/qwen3.8-flash` | `xhigh` | `proj-coverage` |
| Власть и порядок | власть, порядок, время; связность | `deepseek-account/deepseek-flash` | `max` | `proj-authority` |
| Термины, окружение, риск | термины, окружение, риск | `qwen-token-plan/qwen3.8-flash` | `xhigh` | `proj-terms` |

Причины выбора модели под срез:

- **proj-coverage** — `qwen3.8-flash`/`xhigh`: срез — структурная сверка
  разделов спеки и носителей, задача внимательного чтения; взят маршрут
  пула с максимальным уровнем рассуждения для текстовой сверки.
- **proj-authority** — `deepseek-flash`/`max`: срез ищет неочевидные
  противоречия между разделами о власти и порядке; взят второй маршрут
  пула с максимальным уровнем, чтобы проба покрыла оба маршрута.
- **proj-terms** — `qwen3.8-flash`/`xhigh`: терминологический анализ —
  та же природа внимательного чтения, что у среза покрытия; тот же
  маршрут для сопоставимости текстовых срезов.

Названное ограничение пробы: сильные и слабые стороны маршрутов пула
измеренными данными не подтверждены — выбор по характеру среза и уровню
рассуждения, не по бенчмаркам.

Сверка с живым каталогом (`list_subagent_models`, 2026-11-11): оба
маршрута присутствуют; `deepseek-flash` несёт уровни off/low/high/max
(max доступен), `qwen3.8-flash` — medium/xhigh (xhigh доступен).
Фолбэков не было. Все три среза стартовали в одном сообщении, вход
артефактный (спека), ролевой промпт и цель у каждого. Идентификаторы
подчинённых сессий — имена субагентов DSH (таблица выше); числовой
идентификатор сессии агенту не выдаётся, имя — доступный идентификатор.

## Находки и триаж

Сырые находки: proj-coverage — 4, proj-authority — 6, proj-terms — 12;
всего 22. После дедупликации — 9 (одинаковые находки разных срезов
сливаются в одну строку с именами заметивших). Триаж основной сессии:
каждая находка сверена с текстом спеки, подтверждена или отвергнута
с причиной; проверен оверинжиниринг.

### F1 — P1 — подтверждена

**Пункт 3 «Форматы»: конфликт власти, дыра покрытости, нереализуемость,
оверинжиниринг.** Заметили: proj-coverage (Н1), proj-authority (P1-1,
P1-2), proj-terms (1, 2, 3, 8).

Сверка с текстом: «агент выбирает формат автоматически по содержимому
заметок» (Готово 3) против «Формат дайджеста утверждает оператор: агент
не меняет формат без решения оператора» (Ограничения) — прямое
противоречие; «носители: не названы» — принимать нечем; PDF против
«Python, stdlib; внешних зависимостей нет» (Рамки) — нереализуемо;
HTML/PDF-вывод против «Только чтение каталога и печать» (Рамки) и
«оператор читает дайджест в терминале» (Цель); система плагинов не
выводится из цели. Цена доказательства несоразмерна.

Вердикт триажа: подтверждена целиком, включая проверку оверинжиниринга —
плагины для произвольных форматов несоразмерны цели игрушечной утилиты.
Зацепка: переписать п. 3 (сузить до терминального текста, назвать
носители) или убрать; автовыбор снять.

### F2 — P2 — подтверждена (приоритет снижен с P1)

**Контракт вывода не зафиксирован.** Заметили: proj-terms (4, P1),
proj-authority (P1-1 частично, P3-6).

Сверка: носитель п. 1 — «контрактный тест вывода», эталон вывода в спеке
отсутствует; «заголовки», «краткие выдержки» не определены; утверждение
формата оператором не встроено в план как шаг.

Вердикт триажа: подтверждена. Приоритет снижен с P1 до P2: дефект не
делает план невыполнимым и закрывается одной строкой контракта вывода
до нарезки; блокирующим остаётся только F1. Зацепка: скелет вывода
(блоки: заголовок / выдержка / статистика) в спеку.

### F3 — P2 — подтверждена

**Критерий README не проверяет своё требование.** Заметили:
proj-coverage (Н2), proj-authority (P2-3), proj-terms (7).

Сверка: требование «README описывает запуск», критерий «файл README.md
существует и читается» — проходит на базовом дереве с любым текстом,
упасть на заявленном требовании не может.

Вердикт триажа: подтверждена. Зацепка: критерий — запуск из README
воспроизводит демо на стенде.

### F4 — P2 — подтверждена

**Окно свежести и время не определены.** Заметили: proj-coverage (Н3),
proj-authority (P2-5), proj-terms (5 частично, 6).

Сверка: «недельный» (заголовок) против «последние 7 дней» (Контекст);
граница окна не задана; формат даты в имени не назван; даты заметок
стенда не оговорены — правило окна не имеет опровергающего доказательства
(все три заметки могут быть свежими).

Вердикт триажа: подтверждена. Зацепка: одна строка «дата в имени —
YYYY-MM-DD, свежая = дата в [сегодня−6, сегодня]»; стенд с заметкой
старше окна.

### F5 — P2 — подтверждена

**Статистика неопределима, демо показывает половину.** Заметили:
proj-authority (P2-4), proj-terms (10), proj-coverage (Н4).

Сверка: «счётчик записей» — единица счёта не названа (все файлы или
свежие); «самые частые слова» — источник, длина списка, стоп-слова,
регистр не названы; демо п. 2 печатает только счётчик, список слов вне
демо-пути.

Вердикт триажа: подтверждена, приоритет P2 (разнобой P2/P3 у срезов):
без ожидаемого результата тест статистики не может упасть иначе как на
захардкоженной реализации. Зацепка: зафиксировать единицу счёта и
параметры списка, вывести список в демо.

### F6 — P3 — подтверждена (приоритет снижен с P2)

**Терминологический дрейф: «заметка» / «запись» / «markdown-файл».**
Заметили: proj-terms (5).

Сверка: «счётчик записей» (Готово 2) против «заметка» (Контекст) —
синонимы без определения; «формат» в двух ролях питает F1, «недельный
против 7 дней» уже в F4.

Вердикт триажа: подтверждена в части заметка/запись. Приоритет снижен
с P2 до P3: сущности не расходятся в действиях, правка — одно слово
(«счётчик заметок»); остальное покрыто F1 и F4.

### F7 — P3 — подтверждена

**Предпосылки окружения не проверяемы.** Заметили: proj-terms (9),
proj-authority (P2-3 частично).

Сверка: стенд из трёх заметок не создаётся ни одним пунктом «Готово»;
форма вызова (`digest` против `digest.py`, аргумент каталога) не названа;
temp-проект не определён.

Вердикт триажа: подтверждена. Зацепка: блок «Предпосылки» в Контексте,
форма вызова в п. 1.

### F8 — P3 — подтверждена

**Границы данных не определены.** Заметили: proj-terms (11).

Сверка: поведение на файлах без даты / с нераспарсиваемой датой, пустом
каталоге, не-markdown файлах не названо.

Вердикт триажа: подтверждена. Зацепка: одна строка правил пропуска в
Контексте.

### F9 — P3 — отвергнута

**Версия Python не названа.** Заметили: proj-terms (12).

Вердикт триажа: отвергнута — оверинжиниринг. Утилита использует базовый
stdlib (пути, даты, строки), доступный во всех поддерживаемых версиях;
версия Python — факт окружения исполняющего проекта, не требование
спеки. Пин версии добавляет требование, не выводимое из цели.
