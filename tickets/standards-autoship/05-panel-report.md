с ролью пака на игрушечном диффе в temp-проекте с установленным
эталонным паком. Проба проведена 2026-11-11 в `/tmp/sa05-executor`
(не в этом репозитории — «Ограничения» спеки).

Один прогон, пять ролей: четыре роли ядра и роль пака. Маршруты и
уровни — из реестра temp-проекта, сверены с живым каталогом до запуска.
Модель сессии — `qwen4-max-preview` (`qwen-token-plan-max`); все роли
панели — `qwen-token-plan/qwen3.8-flash` с `xhigh`: независимость по
умолчанию соблюдена, фолбэков нет.

Факт окружения: лимит активных детей хоста — 4. Четыре роли ядра
стартовали в одном сообщении; роль пака стартовала после завершения

## Механические гейты (артефакт критерия 3)

Эталонный гейт `reference-gate` — константа `print('reference gate:
ok')`; его способность падать доказана пробной мутацией данных
установленной копии пака (прецедент: мутации эталона тикета 01
доказывали отказ валидатора). Мутация объявлена в игрушечном тикете.

Выводы исполнителя гейтов `run_gates.py` (прочитаны исполнителем):

1. Эталонный гейт как есть, на игрушечном диффе:

   ```text
   ✓ гейт reference-pack/reference-gate: exit 0
       reference gate: ok
   ✓ гейты паков: 1 пройдено
   exit=0
   ```

2. Пробный гейт на игрушечном диффе ДО правки:

   ```text
   ✓ гейт reference-pack/reference-gate: exit 0
       reference gate: ok
   ✗ гейт reference-pack/toy-style-gate: ожидался exit 0, получен 1
   гейты паков: 1 из 2 красные
   exit=1
   ```

3. Финальный гейт стиля (camelCase-паттерн) на сломанном диффе
   (`/tmp/sa05-broken/toy.py` с `applyDiscount`): `exit=1` — гейт
   умеет падать; на базе (snake_case) — зелёный по построению
   инварианта.

4. После правки (`apply_discount`, коммит `4501bf6`):

   ```text
   ✓ гейт reference-pack/reference-gate: exit 0
       reference gate: ok
   ✓ гейт reference-pack/toy-style-gate: exit 0
   ✓ гейты паков: 2 пройдено
   exit=0
   ```

Тесты-пробы после правки: `python3 -m pytest tests/ -q` — `2 passed`.

## Пробелы и факты пробы

- На базе роль пака в панели не запускается: базовый скилл ship не
  несёт сборки из ролей паков (контрактные тесты сборки красны на базе
  `d5b4268` — 20 падений test_skill_ship).
- Лимит активных детей хоста — 4: старт роли пака рассрочен (выше).
- Роль спеки в игрушечном юните несёт сам тикет (отдельной спеки нет)
  — названо во входе reviewer-spec.
- Живой 1С-пак — названный пробел юнита (решение 18); эталонный пак
  доказывает контракт.
- Пробная мутация данных пака — объявленный приём пробы, не норма
  метода: пак в проекте — данные команды, мутация доказывает
  способность гейта падать.
